# 并行工作分析规则

**最后更新**: 2026-06-04

---

> **升级**: 多模型分发(派给 Composer 2.5 / GPT-5.5·Codex / Opus 的"分发卡")见 [`multi-model-dispatch.md`](./multi-model-dispatch.md)。本规则只回答"能不能并行"; 那条规则在此之上回答"每块并行工作派给哪个模型 + 怎么隔离 + 怎么交接"。出计划时**默认**产分发卡(总览表 + 每任务 brief 卡), 取代下方"并行工作建议"的简版输出格式。

制定计划时，在末尾添加「并行工作建议」：

## Subagent 并行（单Chat内）

| 适合 | 不适合 |
|------|--------|
| 独立模块修改 | 严格依赖顺序 |
| 探索不同代码区域 | 需前一步结果 |
| 同时测试和审查 | 需人工确认 |

## 多Chat窗口并行

| 适合 | 不适合 |
|------|--------|
| 前后端独立开发 | 修改相同文件 |
| 不同模块互不影响 | 有git冲突风险 |
| 文档+代码 | 需共享上下文 |

## 输出格式

> ⚠️ **已被 [`multi-model-dispatch.md`](./multi-model-dispatch.md) 的「分发卡」取代。** 出计划末尾**统一**产「分发总览表 + 每任务 brief 卡」(含模型路由 + worktree 隔离命令), 不再单独产下面这个简版, 避免两套输出格式打架。下方仅作 **fallback**: 当任务确实单 chat 单人、无任何可派出的并行工作时, 至少给一句并行可行性判断。

```markdown
## 并行工作建议 (fallback —— 无可分发时)
### Subagent: ✅/❌ [说明]
### 多Chat: ✅/❌ [说明] [冲突风险]
```
