# F006 生产全链路测试 SOP（2026-07-29）

> 适用范围：食品工厂的建档、BOM、Workflow、期初库存、采购、生产计划、调拨、报工、结单、成本、销售交付与盘点。本文是操作咨询口径，不代替页面权限、审批规则或正式业务单据。
>
> 在线逐项核对版：`https://aiassist.cretaceousfuture.com/lsmsop/`

## 1. 回答与执行边界

- AI Assist 只解释功能、字段、路径、业务逻辑、测试步骤与排错方法，不代替用户创建、审批、报工、调库存或结单。
- 不确定当前页面是否支持某入口时，明确写“请以当前页面为准并记录为待验证”，不能编造按钮、状态或成功结果。
- 回答操作问题时优先给出：适用路线、菜单路径、填写内容、操作步骤、预期结果、阻塞条件。
- 销售订单生产与存货生产共用 SKU、BOM、Workflow、报工、成本和仓储能力，但生产计划来源、结单与销售交付不同。

## 2. 三种测试深度

### MVP：非阻塞最小闭环

只走正常数据：主数据建档 → 一条可用 Workflow → 期初库存 → 一条生产路线 → 正式报工 → 必要审批 → 仓库确认入库 → 成本与盘点。先证明链路能闭环，不故意制造异常。

### 中度：关键业务闭环

包含全部 MVP，再加入 1→1、多→1、1→多、多→多基础拓扑、缺料采购、报工审批、完整调拨、部分发货、开票收款和关键成本分摊。

### 全量：全数据闭环

包含全部中度，再加入 Workflow 覆盖冲突、采购异常、质检、不良、退料报损、撤回冲销、BOM/ECN 版本治理、跨单合并和分析核对。

## 3. MVP 前置条件

1. 确认当前账号、工厂和角色正确；至少有一个生产仓及一个主仓或外仓。
2. 确认生产操作员、生产主管、仓管能进入各自页面。
3. 中度以上再准备采购、销售、财务与审批角色；全量再准备质检、BOM/ECN、损耗与冲销角色。
4. 系统管理 → 系统设置 → 成本设置：核对全局工时单价。工序主档不重复填写本轮工时和时薪；实际工时在工序报工时记录。

## 3A. RN App 12 个关键角色与最小账号集

以下 12 个账号覆盖 F006 手机 RN App 的关键管理权限和一线闭环。账号只用于识别岗位，不在手册或 AI 回答中提供密码。登录后必须回读 `factoryId=F006`、角色和当前页面；角色名称正确但页面入口、审批节点或工厂不一致时立即停止，不能借用老板账号替角色“代做通过”。

权限口径：`rw` 表示该业务域可读写，但仍受单据状态、数据范围和 OA 审批约束；`r` 表示只读；`-` 表示不应操作。页面上能看见入口不等于有权提交，拥有模块写权限也不等于可以审批自己发起的单据。

### 老板 / 工厂超级管理员：`f006_admin`

- 角色码：`factory_super_admin`。使命是看全厂经营、配置基础规则、处理跨部门异常并确认最终责任人。
- 实际能力：工厂模块均为 `rw`；RN 进入工厂管理员首页，可查看 AI、报表、SmartBI、管理和个人中心，并维护系统级配置、主数据及角色权限允许的业务对象。
- 边界：老板账号不是万能代办账号。采购、收货、质检、付款、报工仍应由真实岗位发起和执行；涉及 OA 时不能用超级管理员绕过节点或替发起人自批。
- 交接：接收各岗位无法自行解决的权限、配置和跨部门异常；处理后交回原岗位继续业务，不直接制造后续业务事实。

### HR：`f006_hr_admin`

- 角色码：`hr_admin`。使命是维护组织、人员、考勤和用工信息，为排产与工时成本提供可信人员基础。
- 实际能力：`hr=rw`、`dashboard=r`；RN 可管理员工、部门、白名单、考勤统计与异常、排班、人工成本、绩效和批次人员分配。
- 边界：不能创建采购、销售、财务、仓储、质检或生产业务单据；人员建档不等于给自己增加其它业务角色。
- 交接：向调度和车间主管提供可排班人员、班次与考勤事实；异常薪资或付款交财务，生产执行异常交生产经理。

### 财务经理：`f006_finance_mgr`

- 角色码：`finance_manager`。使命是审核业务金额、管理应收应付、发票、成本和财务 OA。
- 实际能力：`finance=rw`，采购、销售、生产、研发和报表为只读；RN 进入财务首页、待办和个人中心，可处理自己有权处理的财务审批并回读采购、销售与生产依据。
- 边界：财务经理 RN 不显示出纳专属“付款”页，不能代替出纳执行实际付款；也不能修改采购订单、销售订单、仓储库存或生产报工。审批必须遵守发起人与审批人分离。
- 交接：采购提供订单/收货/发票依据，销售提供订单/发货/开票依据；审核通过后交出纳付款或继续应收核销，差异退回原业务岗位修正。

### 出纳：`f006_cashier`

- 角色码：`cashier`。使命是依据已批准的付款任务执行付款并留下可核对凭证。
- 实际能力：`finance=rw`、采购和销售只读；RN 与财务经理共用财务导航，但额外显示出纳专属“付款”页，可查看付款任务并按当前状态执行允许的付款动作。
- 边界：不能修改采购、销售或收货事实，不能把未审批、超余额或凭证不完整的申请当作可付款；不能审批自己执行的付款。
- 交接：只接收财务经理或 OA 已批准的付款任务；付款后把流水、时间、金额和凭证交财务经理核销，失败或退票保持原单据可追溯并退回处理。

### 销售经理：`f006_sales_mgr`

- 角色码：`sales_manager`。使命是维护客户、销售订单、价格与交付承诺，并把有效需求交给生产和仓储。
- 实际能力：`sales=rw`、`rd=rw`，分析、财务、生产、报表和仓储只读；RN 可管理客户、销售订单、销售退货、价格表及应收应付概览。
- 边界：不能替生产创建实际报工，不能替仓库发货或扣库存，不能替财务确认收款；订单未通过当前审批/财审门禁时不能承诺已可排产。
- 交接：订单审核后交调度/生产经理排产；缺料交采购；可发货任务交仓储；发货与开票依据交财务。

### 采购经理：`f006_procurement_mgr`

- 角色码：`procurement_manager`。使命是维护供应商和采购订单、跟踪交付、处理采购异常并向仓储交付可收货任务。
- 实际能力：`procurement=rw`，财务、库存、生产、报表和仓储只读；RN 可管理采购订单、采购退货、价格表、供应商、供应商送货、到货确认和采购异常，并查看应付概览。
- 边界：采购确认供应商交付不等于库存入账；不能替仓管确认入库、替 QC 下质检结论或替财务付款。页面若提供跨模块入口，仍以目标模块权限和单据状态为准。
- 交接：经审批的采购和到货信息交仓储；品质问题交 QC；发票、收货和应付依据交财务；短收、超收、退货决定回写采购跟踪。

### 调度员：`f006_dispatcher`

- 角色码：`dispatcher`。使命是把已审核需求转成可执行计划，安排路线、人员和时间并跟踪异常。
- 实际能力：生产、销售、排程、工作报工、分析和看板为 `rw`，其余相关模块多为只读；RN 可查看车间状态、计划与路线，分配任务和人员，处理插单、重排、预警、生产线和工序运行概览。
- 边界：不能替仓库收发货、替 QC 判定、替财务审批或替操作员填写现场实际投入产出；计划只能引用已满足门禁的 SKU、BOM、Workflow 和订单事实。
- 交接：从销售/生产经理接收需求，从 HR 读取可用人员，从仓储读取库存；计划下发给车间主管，执行偏差回收后再重排。

### QC / 质量检验员：`f006_quality_insp`

- 角色码：`quality_inspector`。使命是独立完成来料、过程、成品或标签质量检查并留下证据。
- 实际能力：`quality=rw`、生产和工作报工只读；RN 可处理待检列表、批次选择、扫码、表单、语音、拍照、标签审核、结果、记录、趋势和质量报告。
- 边界：不能修改采购、库存、生产计划或财务单据；AI 初筛不能替代人工结论，所有标签照片都要完成人工审核；QC 结论不能由采购、仓储或生产岗位代填。
- 交接：来料结论交仓储决定是否可入库并同步采购处理异常；过程/成品结论交车间主管和生产经理；不合格处置保留责任人、证据与复检结果。

### 仓储主管：`f006_warehouse_mgr`

- 角色码：`warehouse_manager`。使命是对实物收发、批次、库位、调拨和盘点负责，确保库存只由仓储动作改变。
- 实际能力：`warehouse=rw`、`inventory=rw`、`dashboard=rw`，采购、生产、销售、排程和报表只读；RN 进入仓储首页、入库、出库、库存和个人中心。
- 边界：不能创建采购/销售订单、替 QC 下质量结论、替操作员报工或替财务确认金额；采购“到货”不是入库，生产“报工完成”也不是主仓已入库，必须由仓储在对应任务确认。
- 交接：从采购接收到货任务和 QC 结论后确认入库；按生产需求领料/调拨；接收完工入库任务；按销售发货任务出库并把库存流水交销售、生产和财务回读。

### 生产经理：`f006_production_mgr`

- 角色码：`production_manager`。使命是统筹产能、计划、生产主数据和跨部门生产结果。
- 实际能力：生产、销售、排程、工作报工、分析和看板为 `rw`，设备、财务、HR、库存、采购、质量、报表、系统和仓储多为只读；当前 RN 走通用管理导航，可按权限进入生产、物流、管理、OA 和报表入口。
- 边界：生产经理的宽权限不能替代车间主管确认班组执行，也不能替操作员填写现场投入产出；对仓储、质量和财务只有读取或协同权时，不得直接制造对应业务事实。
- 交接：接收销售需求和调度方案，确认生产优先级与主数据准备；把执行交车间主管和操作员，把缺料交采购/仓储，把质量异常交 QC，把完工交仓储。

### 车间主管：`f006_workshop`

- 角色码：`workshop_supervisor`。使命是把计划落实到班组、工序和现场节奏，并核对报工质量。
- 实际能力：生产、质量和工作报工为 `rw`，设备、HR、研发、报表、排程、仓储等为只读；RN 可查看车间首页、批次、人员和个人中心，并进入 AI 对话。
- 边界：不能替销售、采购、财务或仓储创建业务事实；不能凭估计替操作员填写实际投入、产出和工时；质量写权限仍须遵守独立 QC 和当前质检流程。
- 交接：从调度接收计划并安排人员/批次，向操作员下达工序；收集缺料、设备、质量和工时异常，分别交仓储/采购、设备岗位、QC、HR 或生产经理。

### 操作员：`f006_worker1`

- 角色码：`operator`。使命是执行本人被分配的工序，如实提交现场投入、产出、时间、人数和异常。
- 实际能力：`production=rw`、`work_report=rw`、`dashboard=r`；RN 默认进入“分配给我的工序”，可逐步报工、填写产量/出成、查看缺料预警并维护个人信息。
- 边界：只能操作分配给本人且状态允许的任务；不能修改计划、BOM、Workflow、主数据、库存、质检结论或财务数据。保存草稿不扣库存，只有正式报工并通过适用门禁才形成正式事实。
- 交接：缺料或批次不可用报车间主管并联动仓储；质量异常报 QC；设备异常报车间主管；正式报工后由车间主管/生产经理跟踪，完工入库交仓储确认。

### 12 角色关键交接链

1. 销售经理确认客户需求 → 财务经理完成必要财审 → 调度员/生产经理形成计划。
2. 采购经理解决缺料并确认供应商交付 → QC 给出独立质量结论 → 仓储主管确认入库。
3. 调度员下发计划 → 车间主管安排班组 → 操作员正式报工 → QC 完成过程/成品检查。
4. 生产完工 → 仓储主管确认成品入库和发货出库 → 销售经理回读交付 → 财务经理核对开票、应收应付。
5. 财务经理批准可付款事项 → 出纳执行付款并回传凭证；跨部门配置或权限阻塞才升级老板处理。

AI 回答“谁来做”时应先给主责角色，再给前置角色和下一交接角色；回答“某角色能不能做”时同时说明模块权限、单据状态、OA/数据范围门禁和禁止代做项。不能只因为老板可见全部菜单就建议用 `f006_admin` 代替真实岗位。

## 3B. AI 表单入口的能力边界

- 当前 AI 表单入口按明确的表单类型解析字段，覆盖产品、生产计划、采购单、销售单、盘点、仓库入库和工序任务等已注册实体。
- 使用者必须先登录，并具备目标页面与目标动作的权限；AI 入口不能绕过页面权限、单据状态、审批或租户范围。
- 自然语言解析只回填当前表单草稿。用户必须核对实体、日期、数量、单位和关联对象后手动提交；助手不会自动审批、报工、调库存或生成正式入库事实。
- 未注册的表单类型、缺少实体类型或解析失败时应明确报错，不得用通用 Prompt 猜字段，也不得返回假成功。

## 4. 创建投入物料档案

菜单路径：系统管理 → 原料类型字典。

- 原料、辅料、包材都在原料类型字典创建，不在 SKU 管理中创建。
- 建议测试数据统一加前缀。例：原料 A/B/C/D，黄油调味料、香辛料，成品盒、封膜、外箱。
- 原料 A/B/C/D 入库计量单位使用 kg；按页面选择 L1 大类、L2 中类、L3 小类。
- 保存后应能按名称搜索，且同名对象只出现一次；辅料和包材应能在 BOM 对应页签中被筛选。

### 原料多包装与基本单位库存

- `RawMaterialType.unit` 是唯一库存基本单位；原料的箱、袋等采购包装换算在原料类型字典中、紧邻基本单位维护，不在成品 SKU 管理中配置。
- 每条有效规格必须直接表达“采购包装单位 → 库存基本单位”，例如 `1箱=10kg`、`1袋=2.5kg`。多规格时必须显式选择，只有一个可证明规格时才允许自动带入。
- 采购、收货和跨仓调拨可以按箱/袋录入并实时展示折合基本量；交易保存包装身份、包装数量、换算系数与折合基本量快照，之后修改主档不重解释历史单据。
- 库存批次、库存余额、移动平均价、BOM 可用量和生产领料统一使用 kg 等基本单位。超收上限按折合基本量比较，不能把不同单位的裸数量相加。
- 抄码/称重原料不套固定包装换算，收货继续按现场实际称重的基本单位落账。

## 5. 创建半成品与成品 SKU

菜单路径：生产管理 → 生产配置 → 产品管理。

### 半成品 SKU

- 产品大类选择半成品，基本单位选择 kg。
- 半成品只定义库存与报工单位，不在 SKU 主档预设投入多少必然产出多少。

### 成品 SKU

- 产品大类选择成品，基本单位选择盒。
- 标准单位换算填写 `1盒=800克`；需要外箱时再增加 `1箱=8盒`。
- 规格文本由系统根据单位关系生成，不再手写另一套口径。
- 盒、克、箱各司其职：不能显示成 `1kg=1盒`、`1袋=1盒` 或把外箱右侧单位改成 kg。
- SKU 单位改变后，Workflow 应提示重新核对并发布；已创建生产计划继续使用创建时快照，不回写历史。

## 6. 创建工序主数据

菜单路径：生产管理 → 生产配置 → 工序管理 → 新增工序。

- 原料处理：填写工序名称、工序类别，默认产出类型选择半成品。
- 定量包装：默认产出类型选择成品。
- 工序主档不维护 kg、盒或 1:1 数量换算；投入单位和产出单位由 SKU 与 Workflow 的连接关系决定。
- 预估工时、标准时薪和出成率上下限属于高级设置，本轮不是必填；实际工时在报工中记录。

## 7. 创建、按工序配置并激活 BOM / 配方

菜单路径：生产管理 → 生产配置 → BOM / 配方维护。

当前强制门禁是：先保存结构完整的 Workflow 草稿；创建 BOM 草稿时，系统根据目标 SKU 自动固定唯一兼容的 Workflow 修订并生成 DAG 配置骨架；配置并激活 BOM 后，再回 Workflow 发布启用。ACTIVE BOM 是 Workflow 发布启用的前置条件；BOM 激活不会自动发布 Workflow。

### BOM 与 Workflow 的自动关联顺序

BOM 激活与 Workflow 发布不能互相替代。当前正确顺序是：

问答与验收的兼容摘要必须保留：“Workflow 完整草稿 → BOM 绑定工序辅料并激活 → Workflow 刷新、发布并启用”。当前自动关联页面把“BOM 绑定工序辅料并激活”展开为下面第 2 至第 4 步，不代表需要手工选择 Workflow 版本。

1. 到 Workflow 建立完整 Cell / 工序链并保存草稿；此时不要发布。
2. 返回 BOM 选择目标 SKU 并创建草稿。系统自动固定唯一、完整且兼容的 Workflow 修订；普通用户不选择 Workflow 版本。
3. 核对只读“工艺来源”卡片。系统按目标成品从终端节点反向回溯 DAG，锁定工序名称、顺序和投入/产出接口。
4. 至少配置一项主原料；替代料、包材和工序辅料按实际业务需要补充，完成校验并激活 BOM。Workflow 和 BOM 都不预设某一次报工的产出角色或静态成本比例。
5. 再回 Workflow 刷新并复核 Cell、SKU、终端产出、单位和 ACTIVE BOM，然后发布并启用。

“工艺来源”应显示 Workflow 名称、修订/版本和当前状态，不显示可任意切换版本的下拉框。若存在新兼容修订，页面显示“升级到最新工艺”；升级只迁移稳定节点/接口可证明兼容的数据，遇到删除、歧义或单位不兼容时列出冲突并停止，旧 BOM、旧计划和历史报工不漂移。

ACTIVE BOM 是 Workflow 发布启用的前置门禁，但 BOM 激活本身不会自动发布 Workflow。BOM 激活后回到 Workflow 刷新并点击“自动同步并发布”；系统按最后一次保存后的草稿与当前 ACTIVE BOM 做实时预检。READY 可直接继续；AUTO_MIGRATABLE 会创建或复用 BOM 同步草稿并迁移可证明兼容的物料绑定；USER_INPUT_REQUIRED / CONFLICT 必须列出缺失、歧义或单位冲突并停止，不能绕过或猜测映射。

确认后，BOM 同步、Workflow 发布和启用作为一个原子动作完成。若确认期间 Workflow 或 BOM 版本发生竞争变化，页面刷新最新状态并停止自动重试；用户修正后再次发起时复用同一幂等请求，不能重复发布。验收时 Workflow 显示“已发布并启用”及当前版本，BOM 与 Workflow 均为 ACTIVE；既有生产计划继续使用创建时快照，新计划才采用新状态。

1. 选择目标成品 SKU，先核对基本单位和标准克重由 SKU 只读带入。SKU 缺标准克重时先回产品管理补录。
2. 原料页签：逐行添加主原料，单位由物料主档带入；普通原料不在这里硬写固定出成率。
3. 包材页签为可选项；真实需要盒、膜或外箱时，填写每一个成品基本单位所需包材量。例如 1 盒用 1 个盒；8 盒共用 1 箱时，每盒外箱用量为 0.125。没有包材的产品留空，不应阻止 BOM 激活。
4. 至少有一行主原料后创建配方头草稿；同一事务自动固定工艺来源，配方头的盒和 800g/盒为只读，不另写换算。
5. 辅料 → 工序编排为可选项；真实存在调料或添加剂时，打开当前 BOM 草稿，按 DAG 锁定的工序顺序添加工序调料。投入基准使用对应 Workflow 产出 SKU 的原始单位，`kg` 显示每 `1 kg`，`g` 可兼容每 `1000 g`，`只`、`袋`、`bag` 或其它非空自定义单位可直接作为同单位基准；只有跨单位换算时才要求明确换算关系。
6. 只有真实存在首锅/续锅差异的辅料才开启按锅序计算；第一锅 100%，后续锅填写相对第一锅比例。
7. 在辅料汇总中核对辅料使用工序、g/kg、锅序、自动单价和计成本标记，避免重复计成本。
8. 激活版本。同一 SKU 只能有一个 ACTIVE；页面应明确显示“正在编辑草稿”“当前生效，内容已锁定”或“历史版本，仅供查看”。修改生效版本时使用“克隆为新版本修改”，已有草稿时进入该草稿；新草稿继承原 BOM 的精确 Workflow 修订和快照，不要求新建 Workflow 草稿。旧计划继续引用原快照。

常见阻塞：找不到或同时找到多个兼容 Workflow 草稿、终端成品不唯一、DAG 有环/断边/单位不完整、SKU 无标准克重、没有主原料、同一物料重复、单位量纲不兼容、已填写的辅料未绑定精确工序、历史版本达到上限、试图直接编辑生效版本。没有辅料或包材本身不是阻塞。

## 8. 绘制、校验并发布 Workflow

菜单路径：生产管理 → 生产配置 → 产品-工序配置 → 选择归属 SKU。

发布前必须确认对应 BOM 已完成配置并处于 ACTIVE；若未激活，Workflow 必须阻止发布。兼容验收摘要是“Workflow 完整草稿 → BOM 绑定工序辅料并激活 → Workflow 刷新、发布并启用”；当前页面在创建 BOM 时自动固定工艺修订，再由用户完成原料、包材和工序辅料配置并激活。

1. 成品归属主路线：顶部归属选择目标成品；最终成品 Cell 必须与顶部归属一致。
2. 原料归属分流或联产路线：顶部归属选择真实原料，画布可包含多个终端成品；不能伪造产品 SKU 作为归属。
3. 建立链路：原料 Cell A/B/C/D → 原料处理工序 → 处理后半成品 Cell → 定量包装工序 → 成品 Cell。
4. 同一张 Workflow 里同一原料只能选择一次；已选原料应从后续选择器中消失。
5. Workflow 只维护工序拓扑和“可能投入、可能产出”的稳定接口，不维护某一批实际选择。主料、替代料、辅料、包材、用量和成本来自计划固定的 BOM。
6. 多个来源连接到同一工序后，正式报工候选取 Workflow 当前接口、pinned BOM 授权主料/替代料和当前仓可用批次的交集；至少选择一项真实投入，不再在 Cell 中配置替代组、全部必投、主投入或追加投入。
7. 原料和处理后半成品均为 kg，最终成品为盒。Workflow 只声明每项投入和产出的报工单位，不预设 kg 必然产多少盒，也不预设本次多产出的成本比例。
8. 自动布局后检查无悬空线、无重复原料、Cell 均绑定 SKU；按上一节自动关联顺序确认对应 BOM 已激活，再刷新并发布启用 Workflow。

## 9. 生产计划选品与 Workflow 匹配

Workflow 冲突在创建生产计划并选择成品时出现，不是在绘制 Workflow 时出现。系统以“用户所选成品集合”和“Workflow 终端成品集合”匹配；Workflow 名称不参与优先级。

### 四种基础拓扑

- 1→1：选择唯一成品，唯一完全匹配路线自动固定。
- 多→1：多个原料汇入同一成品。计划选该成品时固定路线；报工至少选择一个来源，可选择一个、多个或全部。
- 1→多：一个来源联产多个成品。选择全部终端时完全匹配；只选其中一部分时，唯一最小超集可被选中，但必须提示会同时产出其他成品并要求确认。
- 多→多：多个来源联产多个成品。选择完整终端集合时完全匹配；只选子集时按最小超集处理并明确额外产出。

### 多产出实际报工与成本分摊合同

- Workflow 只列出本工序所有可能产出；工序 Cell、Workflow 和 BOM 都不配置主产出、联产品、副产品或某一次报工的静态成本分摊比例。
- 正式报工至少提交一项数量大于 0 的实际产出。只发生一个产出时只提交该行，本道共享投入成本 100% 归该产出；未发生的候选保持空白，不提交伪造的零数量业务行。
- 同次发生多个产出且单位可以统一时，系统按统一后的实际数量自动计算本次成本分配；单位量纲不能统一时，只在本次报工表单要求填写各实际产出的分摊比例，合计必须为 100%。
- 计划固定的 Workflow revision、输出集合和对应 BOM revision 仍保留；新语义只用于新草稿/新 revision，已发布 Workflow、历史计划、报工和成本快照不回写。

### 覆盖冲突处理

1. 优先完全匹配：终端集合与用户选择完全相等。
2. 没有完全匹配时，选择包含用户所选成品的最小超集。
3. 同一层级仍有多个候选时弹出 Workflow 选择弹窗，禁止按名称、创建时间或归属类型静默猜测。
4. 每个候选应提供工序链预览，展示原料、半成品、工序和成品 Cell 的连接关系；用户离开预览按钮后气泡关闭。
5. 找不到覆盖全部所选成品的单条路线时明确阻止，不自动拼接多张 Workflow。

## 10. 期初库存、采购与生产前调拨

### 期初库存

菜单路径：仓储管理 → 入库管理或原料批次。

- 按物料、仓库、批次、数量、单位、生产/到期日期、单价录入期初库存。
- 原料、辅料、包材分别入库；入库单位必须与主档兼容。
- 保存后在分仓库存查询中回读批次、可用量和金额。

### 缺料采购

菜单路径：采购管理 → 采购订单。

- 创建采购订单 → 提交 → 审批 → 到货登记 → 质检或收货 → 仓库确认入库。
- 未审批订单、未确认到货或质检不合格不能增加可用库存。
- 有包装规格的原料在采购行选择具体规格和包装数量，页面同时展示折合基本量；收货默认继承采购规格，实际到货包装不同时只能改选该原料的有效规格。
- 采购、收货和调拨均保存包装快照；收货确认后的新批次只按库存基本单位落账。多规格缺少选择时必须失败，不能猜测。

### 主仓/外仓到生产仓

- 创建领料或仓间调拨，源仓选择主仓/外仓，目标仓选择生产仓。
- 提交、审批、发运、签收、确认后，源仓减少、生产仓增加；同厂总库存保持守恒。
- 库存不足、批次状态不允许、源目标仓相同或单位不兼容时必须阻止。
- 默认职责分离仍是“发起人不能审批自己的调拨单”。唯一例外是：当前 OA 节点明确只授权 `factory_super_admin`，且发起人本人是本厂启用状态的 `factory_super_admin`；此时允许自审批以解除单一总监工厂的死锁并记录审计日志。节点授权仓管或其他角色时，超级管理员不得借此越权。

## 11. 创建生产计划

### 存货生产

菜单路径：生产管理 → 生产计划 → 新建。

- 来源选择存货生产，选择一个或多个目标成品、计划数量、日期和仓库。
- 系统按成品集合匹配 Workflow；唯一候选自动固定，冲突候选必须人工选择并查看工序预览。
- 计划启动前固定 SKU、BOM 与 Workflow 版本快照。
- 点击创建后按钮进入处理中并禁止重复点击；网络重试或重复提交同一创建请求只能返回同一张计划，不能生成重复计划号。
- 取消只允许尚未正式执行的状态，并必须保存取消原因、操作人和时间；已开工或已有正式事实时应走停产/结算路径。

### 销售订单生产

菜单路径：销售管理 → 销售订单 → 新建，随后确认并按当前规则完成财务审核或审批。

- 订单包含客户、成品 SKU、数量、单价和交付日期。
- 审核通过后从订单生成或关联生产计划；生产计划必须回溯订单号和订单行。
- 缺料时形成采购或补货动作，不允许绕过库存与审批直接开工。
- 同一销售订单行的重复点击或网络重试不得重复建计划；页面应回显已存在计划并提供查看入口。

## 12. 逐道报工

菜单路径：生产管理 → 报工或移动端工序操作。

每道工序按现场填写顺序核对：①投入物料/批次与投入数量 → ②工序执行的开始时间、结束时间、人数和总工时 → ③产出明细与数量 → ④确认提交。生产计划、工序、SKU、单位和工序顺序来自计划固定快照。

- 多来源工序：至少选择一个投入来源；允许选一个、多个或全部，未选来源不能被扣库存。
- 单一确定来源或产出：系统自动选中并锁定，不展示没有意义的多选控件；多个候选必须人工选择。必填标记和阻塞原因在对应行内显示。
- 投入候选：只能来自 Workflow 当前工序接口、计划固定 BOM 授权主料/替代料和当前仓可用批次的交集，前端不能扩展候选。
- 报工单位：页面按 Workflow/物料配置单位显示并提交。kg/g 等质量单位只在同量纲内科学换算；盒、袋、只等计数或包装单位按字面量匹配（忽略大小写），不能偷偷折成重量。手工批次与库存批次遵守同一合同，单位不兼容时必须指出具体物料、报工单位和库存单位并阻止提交。
- 多产出工序：选择并填写本次真实产出的一个或多个成品；未发生项留空且不提交，不能凭 Workflow 候选自动入库。
- 本次成本分配：只报一个产出时共享投入成本 100% 归该产出；多个产出单位可统一时按统一后的实际数量自动分配；量纲不可统一时保留已填数量，并只在本次报工展开比例输入，合计 100%。
- 成品率：投入与产出同量纲时按统一单位计算；跨量纲时不能直接相除，页面应说明需补充“每单位成品重量”。操作员在产出行填写每盒/每袋/每只多少克后才重算重量口径成品率；未补充时明确显示不可比，不得伪造成百分比。
- 时间和人数属于“工序执行”，不混在产出数量区；产出数量与只读单位紧邻展示。
- 副产物：在具体报工记录的副产字段填写，不要求为了副产物单独建 Workflow。副产物数量与回收价值分别记录。
- 锅序：只有 BOM 对本道工序的辅料开启锅序时显示锅数或锅序计算；普通辅料不显示。
- 人工成本：按本道实际工时 × 全局工时单价计算，不读取工序主档中的测试时薪。
- “保存草稿”是次操作，“正式报工”是唯一主操作。草稿不占用或扣减生产仓库存，也不形成正式成本。
- 正式报工按固定 BOM 和工序快照，从生产仓 FEFO 分配原料、调料和包装包材批次；成功后回显物料、批次、数量、实际单价和成本。库存不足或单位不兼容时失败关闭，不能部分扣库；缺价时成本保持未知并提示补价，不能伪造 0 元完整成本。
- 双出成率总览表的表头与数据列线对线；可排序列支持点击和键盘 Enter/Space 切换升降序，工序/状态筛选继续使用表头漏斗。
- 报工提交、审批、正式落账分开。待审、驳回状态不能提前改变最终库存与成本。

### 包装标签拍检与人工审核

- 包装标签拍检是独立质检流程，不等同于本道报工人工工时，也不能用普通批次质检或副产字段替代。
- 管理员先按真实手机号邀请“质量检验员”，员工本人在手机端设置密码；角色和工厂来自邀请，员工不能自行改成管理员。
- 质检员填写 SKU、批次号、生产日期并拍摄 1–6 张照片。AI 初筛后，无论找到 0 处还是多处疑似区域，所有照片都必须进入人工审核。
- 复核台逐图显示盒子、白标和彩标三层参考框及图例。人工用“选择”工具确认/拒绝已有候选；发现漏检时切换白标画笔或彩标画笔拖拽补框，画错可撤销、删除后重画。
- 每张照片都要给出合格、缺白标、缺彩标或无法判断等结论，全部完成后只提交一次人工审核，结果成为服务端人工真值。三层参考框只辅助定位，不自动改变人工结论。
- Web 管理端后续可备份、归档，并由有权限的技术管理员批准或拒绝训练。批准只允许导出训练数据，不会自动启动训练或发布模型。

常见报错：库存不足、没有可用批次、批次过期或被锁定、投入未至少选择一项、投入数量超过可用量、产出单位不匹配、Workflow/BOM 快照缺失、重复提交、无报工权限。

## 13. 小结、结单与仓库确认入库

### 存货生产

- 每轮报工后可做增量小结：只扣本轮投入、只增加本轮产出，计划继续开放。
- 第二次小结只处理第二轮增量，不能重复扣减第一轮。
- 小结成功后，本轮消耗必须标记已结算，本轮半成品/成品入库状态与库存流水一致；重复小结只能返回既有结果。
- 所有轮次完成后停产，计划关闭且不能继续小结。停产只允许可结算的运行状态，并保存操作人、时间和原因。

### 销售订单生产

- 打开核对结单，核对实际产量、领用、工时、成品单位和销售订单关联。
- 提交结单只表示生产方完成交接，不等于仓库已经收货。

### 仓库确认完工入库

#### 多产出完工入库逐行合同

- 仓管核对计划号、目标生产仓，以及计划固定终端产出集合中的每一行成品 SKU、批次、生产日期、正式报工数量、实收数量和单位。
- 混合单位保持各自单位，不能把 kg、盒、只等数量相加成一个总数，也不能伪造合计单位。
- 每一产出行实收数量必须大于 0，并且与该行正式报工数量完全一致；少收、多收、漏行或计划外 SKU 都阻止本次确认，交生产修正报工事实。
- 全部产出行一次校验、一次入库。任一行失败时整组保持待收，不能部分 SKU 已入库、其余 SKU 待收。
- 只有整组仓库确认成功后，所有正式成品批次和生产仓可用库存才一起生效；重复确认或网络重试复用既有幂等结果，不能重复入库。

## 14. 生产后仓储交接

- 先在生产仓确认正式成品批次，再创建生产仓 → 主仓/外仓的仓间调拨。
- 调拨依次完成申请、审批、发运、签收和入库；确认后源仓减少、目标仓增加、同厂总库存不变。
- 少收时记录调拨差异，未处理前不能静默平账；发出量 = 实收量 + 在途量 + 已审批损耗量。
- 余料退回必须沿用原领料批次与成本；损耗须填原因、责任环节与凭证并按规则审批。

## 15. 成本归集与出厂核算

- 成本汇总与盘点是两条不同链路。
- 逐工序核对投入、产出、人数、实际工时、人工成本、材料成本和小计。
- 原料、调料和包材都应能从正式报工分配明细追溯到生产仓批次、实际数量和实际单价；草稿不得进入成本。
- 多产出成本分配以本次正式报工为准：单产出为 100%；多产出同量纲按统一后的实际数量自动分配；量纲不可统一时使用本次录入且合计 100% 的比例。各产出分摊成本之和必须等于本道应分成本。
- 副产回收 = 副产数量 × 回收单价；净成本 = 总成本 − 副产回收。副产无单价时数量仍显示，回收额为 0。
- 成品出厂成本应能解释原料、工序辅料、包材、人工、设备、其他和副产回收；单盒成本按真实入库盒数计算。
- 物料价格缺失显示“—”或待补价格，不能伪装为 0 元。

## 16. 销售交付与财务闭环

1. 销售从已入主仓/外仓的成品创建发货任务，填写计划日期、地址与数量；创建任务时不立即扣库存。
2. 仓管分配实际来源仓与 FEFO 批次，批次分配合计必须等于实发量；仓库确认后才扣库存并生成送货记录。
3. 支持部分发货；累计实发不能超过订单量，重复确认不能重复扣库。
4. 销售发起开票申请，财务审核；登记收款后核对应收余额。
5. 销售退货草稿不直接改变库存或资金；审批后再处理退货入库、退款和应收变化。

## 17. 盘点闭环

菜单路径：仓储管理 → 盘点管理。

1. 盘点前记录原料、半成品、成品按仓库与批次的系统数量和单位。
2. 发起盘点任务，选择仓库、月份或页面允许的专项盘点方式。
3. 录入实盘数量并保存暂存；暂存时库存不变。
4. 提交审批并由有权限人员审核；审批完成后库存仍未调整。
5. 点击应用差异后库存才等于实盘数量；同一差异只能应用一次。

## 18. 撤回、冲销与审计

- 草稿或待审报工可取消；正式落账必须走撤回或冲销单据，禁止删记录或直接改库存。
- 冲销审批后，原料补回、半成品/成品产出失效，成本重算；原报工与冲销单互相可追溯。
- 半成品已被下游消耗或成品已调拨/发货时，系统应指出具体下游占用并阻止上游冲销。
- 旧生产计划保留创建时的 BOM 与 Workflow 快照；新版本只影响之后创建的计划。

## 19. 回答常见问题的口径

### 为什么 Workflow 不填写 1kg 产 1盒

Workflow 的单位关系只声明投入用 kg 报工、产出用盒报工，不预设实际出成率。`1盒=800克` 已由成品 SKU 定义，真实投入、产出与出成率在报工和成本分析中形成。

### 多个原料是否必须全部投入

不是。实际投入候选来自 Workflow 当前接口、计划固定 BOM 授权主料/替代料和当前仓可用批次的交集；正式报工至少选一项数量大于 0 的真实投入，可以选择一个、多个或全部。未发生项不提交，也不再在 Workflow Cell 中区分主投入和追加投入。

### Workflow 和 BOM 不预设本次投入、产出后怎么报工

Workflow 维护工序拓扑与可能投入/产出，BOM 维护主料、替代料、辅料、包材、用量和成本，计划创建时固定两者的精确版本。正式报工只提交本次实际发生且数量大于 0 的投入和产出：至少一项投入、至少一项产出；未发生项留空，不伪造零数量行。单产出成本 100% 归该产出，多产出同量纲按统一后的实际数量自动分配，量纲不可统一时只在本次报工填写合计 100% 的比例。

### 副产物要不要单独建 Workflow

不需要。副产物在具体报工中记录；只有真实存在独立后续工艺或库存主数据需求时，才另行评估建档。

### 为什么选择成品时弹出多个 Workflow

因为多个已启用 Workflow 在完全匹配或同级最小超集层级上重叠。用户必须通过工序链预览选择正确路线；系统不能靠 Workflow 名称自动猜测。

### 报工完成为什么成品还没进主仓

报工、生产结单、仓库确认完工入库、生产仓到主仓/外仓调拨是四个不同动作。只有仓库确认后生产仓库存生效，再完成仓间调拨后主仓/外仓才增加。

### 多产出完工后仓库怎么确认入库

按计划固定的终端产出集合逐行核对 SKU、批次、正式报工数量和单位；混合单位不合计。每行实收必须大于 0 且完全等于该行报工数量，任一行不符则整组保持待收并退回生产修正，不能部分入库。

### 原料按箱采购、按 kg 入库时去哪里换算

去原料类型字典，在库存基本单位旁维护 `1箱=多少kg` 等有效包装规格；采购、收货、调拨可以选箱并查看折合 kg，但库存批次、BOM 可用量和生产领料只保留 kg。成品 `1箱=8盒` 才属于成品 SKU 包装，不能混用。

### 标签 AI 没框出问题能否直接判合格

不能。标签拍检要求所有照片进入人工审核；AI 为 0 候选时仍要逐图检查。复核台显示盒子、白标、彩标三层参考框，漏检由人工选择对应画笔补框并给出每张照片结论。人工提交后才形成真值，训练批准也不会自动训练或发布模型。

### 报工单位不同，成品率为什么不能直接算

kg 与 g 等同量纲单位可先科学换算再计算；盒、袋、只等计数或包装单位必须按配置字面量提交，不能暗中折重。投入是 kg、产出是盒等跨量纲场景，先在产出行补充每盒多少克等“每单位重量”，再计算重量口径成品率；未补充时页面必须显示不可比，不能给伪造百分比。
