# 设计卡：全景读数要不要自带「那一条问句期间 LLM 抖了没」

**日期** 2026-08-18 · **裁定人** 本轮执行者（授权全权决策）· **状态** 已执行

## 背景（全部是实测，⛔ 无一条来自读代码）

同一命令、同一天、生产形态（共用 `session_key`）跑了三次全景：

| | 答上 | 日志里 LLM 故障 |
|---|---|---|
| pan1 | 39/48 | 8 |
| pan2 | 40/48 | 9 |
| pan3 | **38/48** | **16** |

pan3 轮1 里出现**连续四条**拒答（第 6–9 条），其中两条拿到**逐字相同**的 10 字反问，
而**同一次跑的轮2**里同样的问句答上了 1227/1353 字。

为查它，逐个假设做了 A/B，**三个全被自己的读数否掉**：

| 假设 | 读数 |
|---|---|
| 自评判「没答到」→ 逐出计划缓存 → 退化 | 逐出**确实发生**（日志两条都在），答案**没退化**：单问句 2 组 × 2 轮全 answer |
| 前置的对比类问句留下会话状态 | A（先问两条对比句）与 B（直接问）**逐字相同**：`['answer','answer','clarification']` |
| LLM 供应商抖动 | 逐条对应后：**答上侧 50% 有故障，拒答侧只有 25%** —— 拒答侧反而更低 |

⇒ 那个现象**6 轮里只出现 1 次**，三个探针都复现不了。
按形态 A¹⁴′ 它是**结构问题**（每次复现尝试都换了被测对象），⛔ 不是样本量问题。

## 要决定的事

排查它花了三轮探针，全部成本都在**事后**把日志和读数手工对起来。
下一次它再出现时，要不要让读数**自带**这个信息。

## 三个选项

| | 做法 | 代价 |
|---|---|---|
| **(a)** | 把 flap 钩子加进 `restaurant_panorama_probe`，每条问句记故障数，汇总报总数 | 探针多一个 logging handler；每条读数多一列 |
| (b) | 单独一个探针（本轮临时写的那个） | **第二份问句表**（形态 D）—— 两份一定会漂，而漂的方向是「两个探针的基线不可比」 |
| (c) | 不做，靠事后 grep 日志关联 | **已经实测过成本**：三轮探针才排除三个假设，且期间我写过一次「未达基线」的错误归因 |

## 裁定：(a)

理由三条：

1. **问句表只此一份** —— (b) 立刻造出形态 D，而本轮已经被同名常量漂移闸抓过一次。
2. **每条读数带来源标记** —— 这是本仓的纪律，而「那一条问句期间 LLM 抖了没」
   正是判断读数可不可比时要看的东西。
3. (c) 的代价**已经付过一次**，且它让「38 vs 40」这种差值**默认可疑而无从查证** ——
   报数字必须带口径，而 LLM 故障数就是这个口径的一部分。

## ⛔ 明确不做

- **不**用它去过滤读数（「有故障就不计入」）—— 那会把「没量到」偷偷折叠进「没问题」，
  而三态的价值全在第三态。它只**报**，不改判定。
- **不**据此改产品行为。逐条对应已经证明抖动与拒答无关；
  ▎按一个被证伪的因果去改产品，就是在建幻觉。

## 一个能让判据红的对照

⛔ 判据不能只是「跑起来不报错」——那种闸永远绿。

**变异**：把收集器的匹配条件改成永不命中（`_FLAP_MARKS = ()`）。
**必须红的断言**：`test_flap_collector_catches_a_real_router_warning`
（喂一条真实格式的 `[llm_router] … timeout (cb_fails=0/2)`，计数必须 > 0）。

**阴性对照**：喂一条 `[llm_router]` 的普通日志（不含故障词）和一条非 router 的告警，
计数必须为 0 —— 否则它会把任何 warning 都算成抖动，读数虚高。

## 解冻条件（那个连续四条的现象）

出现**一次带 per-question 故障记录的全景**，其中有连续 ≥3 条拒答，
且那几条的 `flap` 计数、`tier`、`missing_slot` 都记了下来。
⛔ 在那之前不再投入排查 —— 已经花了三轮，三个假设全错。
