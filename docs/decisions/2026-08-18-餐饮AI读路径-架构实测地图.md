### 📏 零 token 回放的真实行为（同一句连问三遍，⛔ 不清缓存）

```
第1遍  回放未命中 → T3 LLM 1 次   authority='llm_contract_repair'
第2遍  回放命中   → T3 LLM 0 次   authority='validated_plan_cache_contract_repair'
第3遍  回放命中   → T3 LLM 0 次   同上
```

🔑 **它复用的是 LLM 自己编译过的计划，⛔ 不是句子库匹配。**

### 📏 完整句子飞轮的真实状态

```
句子库 merge_samples()  = 62 条，覆盖 10 个意图
其中 load_promoted_samples() = 0 条        ← 晋升进来的一条都没有
_approved_exact_route 命中 = 0 次
   （阳性对照：拿【句子库里本来就有的】「哪道菜毛利最高」进去，
     仍然 authority='llm'，飞轮入口一次都没被调用）
```

▎**结论不是「关键词和向量还没退役」，而是：**
▎**关键词和向量已经不在生产路径上了，但句子飞轮没接上来 —— 现在是纯 LLM 单腿跑。**

```
   │              （router:1342，已被 router 内 3 处消费），只是没接到 dish 槽位
   │
   ├─ 计划编译 `_plan_requested_intents`（确定性分支链）
   │    📏 12 问句实测：改写 LLM 的 intent 3 次、dims 3 次、dish 0 次
   │       逐条读：4/5 次改对了（其中 1 次是 product→dish 同义词归一）
   │
   ├─ 契约修复（三处手写补丁 + 今晚新增两条通用规则）
```

### ③ 晋升飞轮：**输入端在转，输出端从来没被按过**

```
load_promoted_samples()  =   0 条     ← 一条都没晋升过
load_rejected_queries()  =   0 条
aggregate_candidates()   = 176 条     ← 真实问句正在排队等晋升

   我要不要关掉最差的那家店 / 按门店看领料趋势 / 损耗都是哪些类型造成的 …
```

⇒ **飞轮不是坏的，是从来没有人转过它。**

▎所以「只留 LLM + 完整句子飞轮」这个目标的真实缺口是：
