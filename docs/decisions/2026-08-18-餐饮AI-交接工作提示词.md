你接手 Cretas 餐饮 AI 读路径的一次完整重构。**全权决策，⛔ 不中途停、不等裁定。**

## 〇 · 北极星

**让一个餐饮老板打开它，能自己做出一个决定。**

取舍顺序：**能不能决定 > 数字准不准 > 覆盖得全不全**

五条交付定义：① 答得上 ② 说一件他没想到的事 ③ 追问接得住 ④ 该给表格就给表格 ⑤ 答不了时说清缺什么·怎么拿到·他自己要干什么。

反目标：**一条误发的提示，烧掉的是「这东西说的话能信」。** ⛔ 不为只有种子数据支持的形状建检测器。

## 二 · 架构一句话

> **只让 LLM 判断「他想要什么」。代码只做三件不需要懂中文的事：核对、算日期、执行。**
> **问过并审过的直接回放，越用越便宜、越快、越不抖。**

**三个角色，职责不重叠 —— 判据是「猜 vs 查 vs 算」：**
```
LLM     所有语义判断（意图/维度/指代/实体提名/时间概念）        ← 猜
数据库   所有存在性（是不是一道菜、一家店、有没有这个能力）      ← 查
代码     核对、日期算术、执行、格式                            ← 算
```

**八步：**
```
① 短路      已审句子 / 会话缓存 / 向量召回（召回=提名，LLM 拍板）
② 加载事实  19意图 + 门店 + 菜单 + 能力表 + 20轮对话 + 会话摘要
            ⚠️ 开集或大的（门店/菜单/能力表）走【检索召回几条】, ⛔ 不全量塞 prompt
③ LLM 判断  一次。⛔ 信息不足必须输出 clarify + 候选维度, 不许硬挑一个
④ 核对      判据是「在不在【这次召回给它的候选集】里」, ⛔ 不是「在不在全量目录里」
            只覆盖四类: 归一 / 继承槽位没验过 / 跨租户污染 / 跑不跑得动
            前三类只修正值或记账(老板无感); 只有第四类会拦, 拦住也是带原因丢回 ③ 重试一次
            ⛔ 不是一个冲突就丢回 —— 全部校完, 收集所有冲突, 一次性丢回, 只重试一次,
               回来后不再校对已确认部分
⑤ 概念→日期 纯算术（只有代码知道今天几号）
⑥ 执行      dimensions 必须传进执行器
⑦ 答案契约  11 项。要认「因权限而缺」一态
⑧ 记账+飞轮 记「LLM 说 X, 我们用了 Y, 因为 Z」→ 审 Top-50 → 晋升 → 回 ①
```

## 五 · 措辞规范（老板可读，⛔ 不许出现技术词）

```
没有数据      「当前系统里还没有库存数据，接上之后我才能回答缺货情况。」
没有维度      「当前库存只能【按食材】看。要不要先按食材看一下？」
              ⛔ 不说「该能力尚未支持，请联系工作人员」—— 给出路, 不认错
没有判定标准  先用默认算法算出来, 再声明「本次按默认判断标准计算，您门店的标准建议重新设置」
              ⛔ 没标准 ≠ 不能算
窗口内 0 行   「这家店最后一条记录是 8/12，之后没有数据上来。麻烦排查一下 POS。」
              ⛔ 不猜「有没有开张」
不支持的指标  「翻台率我算不了 —— 缺【台位数】和【每桌就餐时长】，补上来我就能算。
               眼下最接近的是每小时订单数和时段分布，要不要先看这个？」
部分能做      能做的先给, 再说为什么另一半不能, 再说老板要做什么
```

## 七 · 测量纪律（这些是本仓反复踩出来的，⛔ 不是提醒是执行项）

```
1  会读出「全无」的仪器必须配【阳性对照】—— 否则分不清「真没有」和「钩子没挂上」
2  monkeypatch 要钩【所有副本】: from-import 进来的那份 + 原模块全局
   （实测踩过: 只钩 restaurant_intent 的副本, 够不着 restaurant_ops_router 自己的）
3  钩函数要 functools.wraps 保签名 —— resolve_by_code 按签名过滤 kwargs,
   通配签名会让答案从 1249 字塌成 35 字
4  跨样本批量读数前清缓存, 并贴出清了哪几个:
   clear_semantic_plan_cache / clear_route_cache / clear_tenant_gate_cache
5  ⛔ 不从注释/文档推行为 —— 跑一次让它自己说(成本几乎为零)
6  ⛔ 不用 grep 数结构, 用 AST。⛔ 不用行号推控制流, 用调用计数
7  改动前后各数一次同一个数, 两个数必须相等（改共享结构时）
8  每条读数带【来源标记】(是 llm 还是 plan_cache), 否则分不清「相等」是真相等还是同一个东西
9  变异对照: 每条断言都要证明【它能红】, 且红在它守的那一条上
10 报数字时同时报口径 —— 两个「9 条」可能是两个完全不同的集合
```

## 八 · 本轮踩过的坑（⛔ 别再踩一遍）

```
🔴 三个信号列全是空的   user_feedback / query_embedding / history 各 0/9731 有值
                        ⇒ 任何被设计依赖的信号, 必须先证明它非空
🔴 我以为的顺序是错的   确定性抽取在 LLM【之后】, 不是之前 —— 病根是「同一件事推导了两次」
🔴 96.4% 重复率是假的   那是探针流量(「今天天气怎么样」152 次, 集中在 8-09~8-13), ⛔ 不能外推
🔴 关键词路由已经死了   五处调用点 × 四场景 = 0(阳性对照已过), 且它对「哪家店卖得最好」返回 None
                        ⇒ ⛔ 不要复活它, 复活等于给飞轮加一个会漂的竞争者
🔴 prompt 示例污染      示例里的 2026-06-03 被模型抄成了答案
🔴 42/48 说多了 1       抖动那句不该算进改动的功劳 —— 真值 41/48
🔴 「接住 10/12」是假的 量的是「返回了 answer」不是「答的是追问那件事」
🔴 一整个模块没接线     entity_resolution/agents/* 存在, 餐饮读路径一次都没 import
```
