# 设计卡：答案契约认「因权限而缺」一态

**日期**: 2026-08-18
**范围**: `backend/python/smartbi/gold/restaurant/answer_contract.py`
**来源**: 餐饮 AI 缺口清单第 20 项 / 架构定稿第十节例 16
> ⚠️ 答案契约要认「因权限而缺」一态，⛔ 不当成「算不出来」

---

## 一、缺口的实测长相（不是读注释推的）

跑 `answer_contract.validate` 喂**真实上游逐字产出**的文本与 meta，
今天的读数：

| 场景 | meta | `missing` | 老板看到 |
|---|---|---|---|
| A 因权限而缺（`resolve_dish_margin` 遮蔽，router:4588-4599） | `{"rbac_masked": True}` | `['profitability_verdict']` | 是否赚钱的判断 |
| A2 因权限而缺（中央金额闸 `_money_masked_answer`，router:10152） | `{"rbac_masked": True, "masked_reason": "price_view_permission"}` | `['profitability_verdict']` | 是否赚钱的判断 |
| **C 真·算不出来**（有价格权限，全店 0 张成本卡） | `{"price_view": True, ...}` | `['profitability_verdict']` | 是否赚钱的判断 |

▎**A 与 C 的读数逐字相同。** 两态在契约的输出里**结构上不可分辨** ——
这不是措辞问题，是契约根本没有表达「因权限」的位置。

下游 `restaurant_intent_service.py:2415` 把它拼成：

```
这次没算出是否赚钱的判断，所以我<拒答标记>，我不会拿别的数据凑。说清楚具体范围我再试一次。
```

两处都是假的：
1. **「没算出」是假话** —— 算得出，是不给他看。
2. **「说清楚具体范围我再试一次」是假建议** —— 他把范围说一百遍也拿不到，
   因为拦他的是角色不是范围。⇒ 正中反目标最重那条：
   **一条误发的提示，烧掉的是「这东西说的话能信」。**

### 还有第二种长相（B）—— 更隐蔽

`resolve_sales_summary` 在 `can_see_money=False` 时**就地脱敏**（不短路）：

- `_money()` 返回 `"***"`（router:8133-8137）
- `if spec.wants_margin:` 里整块挂在 `if can_see_money:` 下，**没有 else**
  （router:8256 起）⇒ 毛利这件事正文里**一个字都不说**
- meta 里只有 `"price_view": False`（router:8532）

实测读数：`missing = ['profitability_verdict', 'margin_value']`，
老板看到「这次没算出**是否赚钱的判断、毛利数据**」——
同一句假话 + 同一条假建议，而且**正文里连「你没权限」都没提**。

## 二、三个选项

### 选项 1：抑制 —— 无价格权限时把金额元素从 `required_elements` 里剔掉

**代价**：
- `required_elements(spec)` 是**纯 spec 函数**，塞 meta 进去要改签名；
  它有 3 个外部消费者（`restaurant_intent_service` 共用 `MARGIN_CAPABLE_INTENTS`、
  `test_planner_invented_metrics`、`test_spec_aliases_point_somewhere`）⇒ 形态 D 风险。
- 元素消失 ⇒ 飞轮日志 `contract_missing` 里再也看不到这一类，
  **规模变得不可量**。
- 把一个**错误的解释**换成**没有解释**：`passed=True` 之后下游一个字不加，
  A 场景侥幸还有 resolver 自己那段话，B 场景就是一屏 `***` 加沉默。

### 选项 2：换措辞 —— `_ELEMENT_LABELS_CN` 给权限态换一套标签

**代价**：
- ⛔ 架构定稿要的是**认一态**，措辞换皮不是认态：`passed` 仍是 `False`，
  下游仍走「这次没算出…」那条分支，**内核一个字没变**。
- `describe_missing` 只收 token 列表，要换标签就得把 meta 传进渲染函数 ——
  把结构信息塞进呈现层，正是形态 D 的起点。

### 选项 3（裁定采用）：`ContractResult` 长出第二个维度

`missing` 回答「缺什么」，新增的 `permission_blocked` 回答「**为什么缺**」。
两者是**同一批 token 上的两个正交读数**，不是换名字：

```
A  missing=[]                                    permission_blocked=['profitability_verdict']   passed=True
B  missing=['profitability_verdict','margin_value'] permission_blocked=[同上两项]                passed=False
C  missing=['profitability_verdict']             permission_blocked=[]                          passed=False
```

⇒ `permission_blocked` 空不空，把 A/B 与 C **结构性**地分开了；
`missing` 空不空，把 A（正文已说清）与 B（正文没说清）分开。

**代价**（诚实登记）：
- `passed` 与 `missing` 的关系变成「`missing` 是移除权限项之后的余量」，
  读代码的人要多理解一层 ⇒ 用 docstring + `__repr__` 带上新字段来兜。
- A 场景 `passed` 由 `False` 翻成 `True` ⇒ **通用执行器兜底那条路不再触发**。
  这是**有意的**：实测 `generic_answer.py` 里 `role` 出现 **0 次**，
  它不知道调用者有没有价格权限。「因权限被遮蔽 → 契约判失败 → 兜底接手」
  今天是一条**绕开金额闸**的路径。本改动顺带堵上它。
  ⚠️ 兜底是否真会吐出金额**未实测**（要真库），只登记，⛔ 不据此下结论。

## 三、裁定

**采用选项 3，且只认「正文已经把话说清」的那一半（A/A2），B 保持今天逐字不变。**

### 为什么 B 不动 —— 这是克制，不是遗漏

owner 交付定义第 5 条：答不了的时候要说清三件事 ——
**缺什么、怎么拿到、他自己要干什么**。「只说拿不到」不算数。

A/A2 的正文（resolver 自己写的，逐字实测）三件事齐全：

> 菜品毛利、成本和营收金额属于成本/价格权限，当前角色不能查看金额。（缺什么）
> 可以先看销量视角：问「哪个菜卖得好」看菜品销量排行；（他自己要干什么）
> 如需毛利数据请联系管理员开通价格查看权限。（怎么拿到）

⇒ A 认成一态之后，老板拿到的**就是这段话**，不需要我再造一句。

B 的正文里这三件事**一件都没有**，而拒答句式
`"这次没算出{X}，所以我…说清楚具体范围我再试一次。"` 的前后缀
**不在 `answer_contract.py` 手上**（在 `restaurant_intent_service.py`，
本轮红线禁止触碰）。在契约里无论把 `{X}` 换成什么，都拼不出三件事齐全的话。

▎**在 B 上强行放行 = 把「假建议」换成「沉默」，两条都不满足第 5 条。**
▎按取舍顺序「能不能决定 > 数字准不准 > 覆盖得全不全」，
▎覆盖第二种长相是最后一位的，⛔ 不为了覆盖而发一句经不起查的话。

⇒ B 只在结果里**标注**（`permission_blocked` 填上、`missing` 不动、
`passed` 不变），行为零变化，规模可量。修 B 的正确位置在 router，见「五」。

### 判据的三个组成（都是代理判据，明写出来）

1. **`_permission_signal(meta)`** — 上游说「这一屏的金额被角色剥掉了」
   - `meta["rbac_masked"] is True`（真实产出点：router 4597 / 6050 / 10166；
     多意图合并时由 service:1622 提升到顶层）
   - `meta["price_view"] is False`（真实产出点：router 8532 / 8960）
   - `meta["sub_results"][*]` 里任一子结果满足上述两条
     （多意图合并只提升 `rbac_masked`，`price_view` 会留在 `sub_results` 里）
   - ⛔ **必须 `is False` / `is True`，不能用真值判断**：`price_view` 缺省是
     `None`，那表示「这个 resolver 不报告」，⛔ 不能推断成「没权限」——
     否则 18 个不报告的 resolver 全被误分类。**不确定就当不是权限问题**
     （fail-safe 方向 = 保持今天的行为）。

2. **`_MONEY_DEPENDENT_ELEMENTS`** — 哪些契约元素**按定义只能由金额产出**
   `profitability_verdict` / `margin_value` / `margin_integrity`

   ⛔ **故意不收**（硬约束 8 的登记纪律，「漏了」和「有意跳过」要分得开）：
   | 元素 | 为什么不收 |
   |---|---|
   | `request_coverage` | 混合了非金额要求（`asks_priority` / `asks_export` / 顾客评价 / 出餐速度）。整个归到权限态会**掩盖真实缺口** —— 那正是形态 A「量错了对象」 |
   | `window_label` / `store_name` / `dish_name` / `comparison` | 与金额无关，无权限也该有 |
   | `execution_consistency` / `analysis_action` / `non_empty_answer` | 同上 |

3. **`_permission_explained(text)`** — 正文有没有把三件事说清
   三类词各命中至少一个：权限词 / 拿到途径词 / 替代动作词。
   ⚠️ 这是**代理判据**（词表），它判的是「三类词都出现了」，
   ⛔ 不假装等于「真的说清楚了」。要收敛得把这句话收到一处产出再扫那一处 ——
   与 `_explicit_analysis_gap` 的 docstring 同一条纪律。

## 四、一个能让判据红的对照

⛔ 不用 MOCK_REST 那种「干净样本」验收 —— 一道在验收环境里不可能红的闸
等于恒真式。本条判据的**变异对照**（逐条实测，见 PR 描述里的表）：

| 变异 | 打在哪 | 应该红的断言 |
|---|---|---|
| M1 `_permission_signal` 恒 `False` | 信号识别 | A 场景重新落回 `missing`（认不出这一态） |
| M2 `price_view` 判据写成 `not meta.get("price_view")` | 缺省态误判 | 「不报告 `price_view` 的 resolver 不许被当成无权限」 |
| M3 `_MONEY_DEPENDENT_ELEMENTS` 加进 `request_coverage` | 收得太宽 | 「非金额缺口不许被权限态吞掉」 |
| M4 `_permission_explained` 恒 `True` | 说清与否的区分 | B 场景被误放行（正文没说清也 `passed`） |
| M5 `permission_blocked` 里的元素**不**从 `missing` 移除 | 移除动作 | A 场景 `passed` 仍是 `False`（等于没修） |

**最硬的一条对照是 C**：有价格权限、真的算不出来（0 张成本卡）——
它的 `permission_blocked` 必须是**空**。这一条红了，说明判据把
「算不出来」也吞进了权限态，那比不修更糟（老板会去找管理员开一个他已经有的权限，
**去查会一无所获**）。
