# 疑问词退役：确定性层不再靠词表识别疑问词

**日期**: 2026-08-17
**裁定人**: Steve（owner）
**执行**: Claude
**PR**: #2761

---

## 触发

prod 实测，老板问：

```
哪几家店在拖后腿
→ 没有找到名为「哪几家店」的门店
```

`extract_store_mentions` 里有一份疑问词黑名单，列着
`哪家 / 哪个 / 哪些 / 有没有`，**唯独没有「哪几家」**。
于是这个疑问片段被当成店名，去目录里查，查不到，拒答。

## owner 的裁定（原话）

> 「不对啊 这些问题比如说疑问词这个问题不应该让 llm 直接处理的吗，
> 不是去通过词语识别的啊？」
> 「疑问词这种东西不能彻底解决的，这个东西以 llm 为主我觉得」
> 「然后疑问词直接退役」
> 「store slots 那个逻辑也是 llm 之后去正则配对的，
> 不是放在理解句子含义的这一个层面的」

最后那句是这张卡的**定位依据**：`extract_store_mentions` 属于
**LLM 之后的正则配对层** —— 它的活是「把模型判出来的范围配到真门店上」，
⛔ 不是「理解这句话里有没有店名」。理解归 LLM。

## 选项与取舍

| | 做法 | 取舍 |
|---|---|---|
| A | 往黑名单补「哪几家」 | 10 秒改完，**下一个变体照样漏**（哪间/哪位/哪一家/哪两家…）。这要求穷举「所有不是店名的词」= 无界集合。本仓在同一个文件的注释里已经吃过这个亏 |
| B | 整个抽取器退役，门店只认 LLM 的 `store_slots` | 方向对，但**今天做会弄坏能用的那条**：`scope='single'` 时门店的实际来源常常就是这个正则（上一轮实测，改动被 revert，见 `ac29927314`） |
| **C ✅** | **判据换成封闭集合 `_INTERROGATIVE_MARKERS`** | 「哪」一个字盖住全部变体。集合封闭 ⇒ 不需要穷举。是 B 的**第一步**，不弄坏 B 依赖的那条路 |

**建议 = C，已执行。**

### 为什么 C 不是「又一份黑名单」

黑名单要穷举「不是店名的词」——**无界**。
封闭集合列的是**疑问词本身**——汉语疑问词是有限的，且
**带疑问词的片段永远不可能是专名**。这是结构判据，不是词表。

⚠️ 与「名字不存在」是两回事：「红烧肉卖了多少」而菜单上没有红烧肉，
仍然应该答「查无此菜」—— 那是用户**真的当名字用了**。
这里拒的是用户**根本没当名字用**的词。

| RES_3101_009 | 38 | 0 | 0 |
| DEMO_REST | 27 | 0 | 0 |
| R_XMX_CHAIN | 1 | 0 | 0 |
| R_GML_DEMO | 132 | 0 | 0 |

**198 个真店名零误伤。**

🔴 第一版探针**读数作废**：`dim_store.relrowsecurity = t`，
没 set_config 就全 0 —— 而「阳性对照也是 0」是唯一分得清
「仪器坏」和「真的没有」的东西。⛔ 差一步就把那个 0 读成「安全」。

## 只动疑问词

同一处还剩两类，**本轮不动**（去黑话只动黑话）：

| 剩下的词 | 属于哪一类 | 该怎么做 |
|---|---|---|
| 最高/最低/最好/最差/排名/排行 | 排名·极值词 | 另一个封闭集合 |
| 客单价/营收 | **指标名** | 由 `METRICS` 登记表推导，⛔ 不手写 |

已在代码注释里登记。

## 范围之外（登记，不做）

- **B（抽取器整体退役）** 仍然是终局，但要先让 `store_slots` 撑得起
  `scope='single'`。上一轮实测证明现在撑不起。
- 菜名抽取器里还有 4 类同形排除（指标限定词/后厨域名词/日期区间/整体是时间表达），
  同一把刀能不能切要**逐类量**，⛔ 不假定同形就同解。
