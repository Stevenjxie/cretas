# 接地闸误报，把整份答案换成了兜底 —— 设计卡

**日期** 2026-08-18 · **状态** 已执行
**触发** 查「我要不要关掉最差的那家店」为什么被 `verdict()` 判 B 时撞见

---

## 📏 实测（MOCK_REST，prod 活代码，**3/3 稳定复现**）

绕过 `narrative_cache` 重新生成三次，`n=1811` **逐次完全相同**，每次都：

```
synthesis rejected by narrative grounding gate: factory=MOCK_REST violations=[
  '缺失维度被当作事实（review）：评价：评价数据还没接入',
  '缺失维度被当作事实（review）：没法判断模拟·打浦桥日月光店口碑好不好',
  '缺失维度被当作事实（review）：3. 补评价数据：把大众点评/美团评价导出传上来',
  '缺失维度被当作事实（review）：看模拟·打浦桥日月光店差评是不是集中在服务或菜品']
```

⇒ 整份答案被丢弃，换成 `_deterministic_fallback_response`，
老板看到的**第一句**是：

> **刚才生成的说明和系统数据对不上。** 我先把系统当前能查到的真实经营数据整理给你。

⚠️ 这条现在被 `narrative_cache` 里一条 8-18 00:04 写入的旧条目挡着
（老板暂时看到的是另一份 948 字的答案）。**那条明天 00:04 过期。**

---

## 🔴 两个缺陷，成因不同

### ① 豁免判据太窄 ⇒ **诚实声明缺数据的句子被判成「把缺失维度当作事实」**

那 4 条里至少 3 条是误报，逐条读根因：

| 违规句 | 豁免正则要的 | 实际写的 |
|---|---|---|
| `评价：评价数据还没接入` | `没有(?:接入)` | 「**还没**接入」 |
| `没法判断…口碑好不好` | `不能判断` / `无法` | 「**没法**判断」 |
| `3. 补评价数据：把…导出传上来` | `待补` / `需补` / `需要补充` | 「**补**评价数据」 |

▎闸抓的是「把缺失维度当作事实」，而这三句恰恰是**反面** —— 它们在说「这一维没有数据」。

⚠️ 第 4 条（「看…差评是不是集中在服务或菜品」）是**补齐之后能看什么**的条件句，
它确实没有豁免词 —— 这一条**不改**，登记为「窄而可信的代价」。

### ② 兜底文案把**内部诊断串**给了老板

```python
sections = [
    "### 核心结论",
    f"{reason}。我先把系统当前能查到的真实经营数据整理给你。",
]
```

`reason` 有 4 种取值（硬约束 8，改之前数过）：

```
叙述模型预算已用完 / 叙述未通过数据因果门禁 ×2 / 叙述模型暂时不可用
```

**四种全是内部故障名。** 老板不关心我们的门禁叫什么，
他关心的是「这一轮到底能不能拿来做决定」。

## 三个选项

| | 做法 | 代价 |
|---|---|---|
| **A** | **补豁免词（治本）＋ 兜底文案不提内部原因（治标）** | 补词是「加启发式逼近」，形态 E 警告过它会越加越复杂；但这三个词都是**实测撞出来的具体说法**，不是我猜的 |
| B | 把这道闸从「拦」降成「只报」 | 它守的是真东西（把缺失维度当作事实 = 编数据），降成只报等于放开最重的那一类假话 |
| C | 只改兜底文案，不动闸 | 闸继续误报 ⇒ 每次都走兜底 ⇒ 老板永远拿不到那份 1811 字的分析。**治标不治本** |

**裁定：A。**

理由：这道闸的代价是**最重的那种** —— 误报一次，整份答案被丢弃。
形态 E 说「宁可让闸窄而可信」，而**「窄」在这里指的是判据窄，不是豁免窄**：
一条正当的缺数据声明被拦，闸就不是窄，是**歪**。

⛔ 不选 B：闸守的东西（编造缺失维度的数）是反目标里最重的一类。
⛔ 不选 C：老板拿不到分析，等于这道闸把产品变成了一张数据表。

⚠️ **补的三个词全部来自实测的具体句子**，⛔ 不是我想象中「可能还有哪些说法」。
形态 E 禁止的是「不断加启发式去逼近『面向用户』」那种无底洞；
这里补的是**三个被实测证明会误伤的具体词**，且每个都配一条会红的断言。

## 能让判据红的对照

| 变异 | 应该打红 |
|---|---|
| 豁免词表去掉「还没」 | 「评价数据还没接入」重新被判违规 |
| 豁免词表去掉「没法」 | 「没法判断口碑」重新被判违规 |
| 豁免词表去掉「补X」 | 「补评价数据」重新被判违规 |
| 兜底文案把 reason 拼回去 | 老板可见文案里出现内部门禁名 |
| **豁免词表放太宽**（例如豁免掉「评价分 4.5」） | 🔴 阴性对照：真违规必须还能被抓到 |

🔴 最后一条是关键：**补豁免词最容易滑成把闸关掉**。
必须有一条断言钉住「真的把缺失维度当作事实」仍然被拦。

## 登记：没做的

| 项 | 为什么 | 什么条件下再做 |
|---|---|---|
| 兜底答案**不回答老板问的那件事**（只列数据） | 那是兜底路径的结构性设计，改它是另一个工程 | 闸修好后重新量：如果还有别的原因频繁走到兜底，就动它 |
| 第 4 条违规（「看…差评是不是集中在服务或菜品」） | 它确实没有豁免词，属于「窄而可信的代价」 | 如果它单独导致拒答（本轮不是），再看 |
| `reason` 的另外三种取值（预算用完 / 模型不可用） | 本轮只实测撞到了「门禁」这一种 | 一并改文案（同一处代码），但**没有它们的实测读数** |
