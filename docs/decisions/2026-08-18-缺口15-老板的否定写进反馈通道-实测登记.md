## 第 3 步：真实入口往返（因为第 1 步判定"通道是通的，只是没人用过"）

用与生产 `auth_middleware._verify_token` 完全一致的算法（HS256，JWT_SECRET 取自
`.env.prod`，密钥 96 字节 > 32 字节不触发补零分支）现场签发一枚 5 分钟有效期的
JWT，`factoryId=DEMO_REST`（明确的演示租户，非任何真实客户），直接 POST
`http://127.0.0.1:8083/api/smartbi/restaurant/feedback`（跳过 nginx，但命中的
是同一个运行中的 FastAPI app，走的是真实的 JWTAuthMiddleware + router，不是
mock）。

**请求**：
```json
{"query": "GAP15_PROBE_2026-08-18_owner_negative_feedback_roundtrip_do_not_treat_as_real_feedback",
 "value": -1,
 "comment": "[GAP15 自动化只读探针的写路径验证, 非真实用户反馈, 可忽略/清理]"}
```

**响应**：`HTTP 200 {"success":true,"id":28146}`

**落库核对**（怎么认出这一行）：
```
id=28146, factory_id='DEMO_REST',
query='GAP15_PROBE_2026-08-18_owner_negative_feedback_roundtrip_do_not_treat_as_real_feedback',
user_feedback=-1,
feedback_comment='[GAP15 自动化只读探针的写路径验证, 非真实用户反馈, 可忽略/清理]',
template_code='RESTAURANT_FEEDBACK', source='template',
agg_meta={"source": "user_feedback_orphan"},
created_at=2026-08-18 09:34:28 UTC
```
字段与代码逻辑完全对应：查询文本此前没有捕获行 → 走 orphan-INSERT 分支
（`template_code='RESTAURANT_FEEDBACK'` + `agg_meta.source=user_feedback_orphan`，
与 `restaurant_feedback.py:77-91` 注释描述一致）。验证后
`user_feedback IS NOT NULL` 总数从 0 → 1，就是这一行。

**这一行是我写的测试数据，通过 query 前缀 `GAP15_PROBE_` 和 `id=28146` 可以随时
定位/清理**；未做清理（prod 数据只多一行、内容自证是探针写的，未混入任何真实
统计口径的过滤条件——`template_code='RESTAURANT_FEEDBACK'` 走 orphan 分支的行
本来就只在这个功能自己的核对语境里出现）。如果下一棒需要一个干净的 0，删这一
行即可：`DELETE FROM smart_bi_llm_fallback_log WHERE id = 28146`。

## 断在哪一层：结论

**哪一层都没断。** 注册、部署、前端调用点、鉴权、落库全部核实通过，且用真实
HTTP 请求（非 mock）跑通一次完整往返。

prod 「user_feedback 非空 = 0」这件事的真实成因：**这张捕获表目前唯一有数据的
租户是 MOCK_REST，而这个租户 38 小时内 312 次问答、0 次反馈点击**。这是一个
使用率问题，不是接线问题——没有代码可以"修"出反馈来，除非有人（无论是真实老板
还是内部验收人员）真的去点那两个按钮。

**本轮没有改动 `smartbi/api/restaurant_feedback.py`**，因为读完代码 + 跑通真实
往返之后，没有发现任何缺陷：关联逻辑（按 `factory_id + trim(query)` 取最近一条，
找不到就 orphan insert）符合文档描述的设计意图，鉴权、错误处理（400/401/500）
单测覆盖齐全且当前全部通过。

## 我没做什么，以及为什么

- **没有改 `restaurant_feedback.py`**：没找到缺陷，改了就是硬做没人需要的接线。
- **没有碰前端**（`RestaurantChatPanel.vue` / `mobile-rest-ai/src/App.vue`）：
  按钮已存在、已部署、已路由可达。前端可用性（比如按钮是否够显眼、是否需要
  引导用户去点）是另一个问题，不在本轮文件白名单内，也不是"接线断了"这个诊断
  能回答的问题。
- **没有碰 `llm_fallback_logger.py` / `restaurant_intent.py` 等**：按任务要求
  这些文件另有并行线在改，本轮只读不写。「MOCK_REST 是这张表唯一的租户」这个
  观察值得登记给那条线（如果他们在查"为什么真实租户的问答不落这张表"，这条
  读数是直接证据），但修它不是本任务范围。
