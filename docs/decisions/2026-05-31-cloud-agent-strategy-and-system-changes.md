# Cloud Agent 时代 · Cretas 战略 + 系统改动决策

## 0. 一句话结论

Cloud Agent 把"逻辑可被自然语言描述 + 数据 agent 可达"的一切商品化(纯分析、厚工具、写入底座都会被绕过/脱媒)。Cretas 唯一能长期守住的是三样 agent 拿不到的东西——**客户不外放的原始数据、agent 担不了的法律责任、扎进车间门店的物理流程**——加上一层**中立的交易撮合**。路对; 但卖点要从"更便宜"换成"数据主权/中立", 商业模式要"轻资产不持货", 系统重心要往**工厂端**倾。

## 1. 局势

- 阿里云 Cloud Agents = 全托管 Agent 运行平台, 1 天上线, 原生 MCP/Skills, 独立沙箱 + 全链路追踪。AI 从"买产品"变"调能力", agent 基础设施像云服务器一样被商品化。
- BAT 全面入局; 美团 2025/10 发袋鼠参谋/智能掌柜/袋鼠管家, AI 投入百亿(研发 260 亿), **CEO 王莆中亲口承认"Token 确实很贵"**, 但策略是**自己补贴、免费给商家**(智能掌柜免费开放)。

## 2. 护城河再判断(修正了此前"垂直工作流+数据+溯源+防呆"的叙事)

**判据**: 一个功能抗不抗 agent, 测两条 —— (1) 逻辑能否被自然语言描述? (2) 数据 agent 能否够到? 两个都"是" → 必被商品化/绕过。**不看工具厚薄。**

**3 个真壁垒(agent 拿不到):**
1. **数据主权 / 隔离** — 客户因隐私/合规/网络隔离不外放原始车间/POS 数据给公有 agent。是数据"不可达"(n=1 即成立), 不是数据"多"。
2. **法律责任主体** — 食安事故谁签字担责, agent 担不了。
3. **线下物理嵌入** — 报工终端/电子秤/摄像头人效/嵌入 SOP 的切换成本, agent 进不去物理现场。

**被降级:** 数据飞轮(prod 仅 2 工厂有 ≥30 POS 天, 未激活); 防呆(只"现场执行界面"是 moat, "写校验"会被 agent 从 spec 复制); 溯源合规(进场理由非留场理由, 会被国标/平台标准化); **system-of-action/"写入底座"=假命题**(文档化 API = self-commoditizing); 省 token(工程卫生, 非 moat, 会被成本年降 + 美团免费侵蚀)。

**最大新威胁 = 脱媒:** 中小客户老板自己用通义/DeepSeek/钉钉 agent 直接问自己的 Excel/DB, 绕过 Cretas。纯数字/纯分析层必然被脱媒, 主动让出。

## 3. 酷虎讨论纪要 + 核实

**酷虎是谁:** 20+ 年餐饮/食品供应链老炮 + 渠道商。资产: 餐饮供应链/仓配(月流水 100 多万)、**客如云上海核心代理商**、两支 20 年采购执行团队(在做广州案子)、深谙行业潜规则。正与 Cretas 合作 AI 垂直食品方案, 把 Cretas 系统当"数据抓手"。

**他独立讲出的、与我们一致的判断:** 套壳"落不了地"(token 太贵)、自建垂直小模型/省 token、POS 2-3 年向美团/客如云集中、线下物理(摄像头/电子秤/仓配)、责任分清、不自建 POS(接 API)、**美团已在做 6-7 成雷同的餐饮方案**。

**核实结论(web research):**
| 论点 | 核实 |
|---|---|
| 客如云=阿里全资 | 真(2020 ~8 亿全资)。**但客户数 ~60 万非"200 万"(纠正我上条引用)**; 2022 有"阿里降持股、客如云或再独立"报道, 深绑前须确认现状 |
| 美团做餐饮 AI + token 贵 | 真(王莆中承认"token 确实很贵")。**关键反转: 美团补贴免费, 不向商家收 8000/天 → "我们更便宜"卖点站不住, 便宜不过免费** |
| POS 只剩 2 家 | 方向真(向美团/阿里集中; 哗啦啦资金链断裂今年靠亿阳信通 2.5 亿续命), "只剩 2 家"夸张(哗啦啦/二维火/奥琦玮/科脉等仍在) |
| 自建小模型省 token | 技术可行(垂直小模型+RAG+精简 Prompt 省 30-60%), **但非 moat = 工程卫生, 会被成本年降+美团免费侵蚀; Cretas 8 级管线已在做** |
| 供应链变现 | 市场真实(万亿, 农贸市场仍 80% 未数字化), **但经济残酷(中小价格敏感/无忠诚度/毛利低, 美菜快驴撤仓)+ 对中大型才成立** |

来源: 华尔街见闻(客如云收购/供应链 C 位)、36氪/新浪(美团 AI)、腾讯新闻(餐饮 SaaS/食材 B2B)、移动支付网(阿里降持股)。

## 4. 商业模式修正:"数据抓手→供应链变现"要拆开 + 轻资产不持货

**硬伤①经济残酷:** 别让 Cretas 自己重资本下场持货(低毛利/撤仓/烧钱)。
**硬伤②(最关键)中立性冲突:** Cretas 核心卖点是"数据主权+数据可信+中立"。一旦自己**反向供货**, 商家会怀疑"你又看我成本又卖我货, 建议是不是为了让我多进你的货" → **侵蚀最硬的护城河**。

**修正后的模型:**
- **降本咨询/分成**(顾问帮省钱, 不持货): 中立冲突小, 可做, 但是服务/关系活(酷虎的活), 难规模化。
- **反向供货**: **Cretas 自己不下场卖货, 保持数据中立**; 持货/仓配由酷虎/第三方做; Cretas 只出"数据抓手 + 中立撮合/比价"轻资产层, 从撮合分成。保中立 + 分到交易价值 + 不背重资本。

## 5. 工厂优先打法(战略重心)

美团/客如云/阿里全是餐饮/POS/外卖生态玩家, **不碰食品加工厂(制造)**。
- **工厂端 = 无人争的主场(安全)**: 录音里工厂痛点(贴标错/杂质品控/防偷对账/人效/排产)正是巨头触不到的。重心放这。
- **餐饮端 = 美团免费的主场(危险)**: 不和美团免费 AI 分析硬拼; 餐饮走"供应链 + 客如云渠道 + 中立撮合/对账"(美团照不到), 不投资源做通用经营分析。

## 6. 系统层面要改什么(回答"我们的系统目前有什么需要改")

> 按优先级。P0 是必须先处理的"矛盾"。

### P0 — 数据主权矛盾(最重要, 必须先解)
**问题**: 卖点/护城河是"数据不喂公有 AI", 但系统现在**把客户业务数据发给 DashScope(通义, 阿里公有)** 做 LLM 意图兜底(~8-16% query) + **SmartBI insight 叙述**(qwen/glm/deepseek)。**卖点与系统行为直接矛盾。**
**要改(三选一或组合):**
- (a) **脱敏后再调公有 LLM**: 调外部模型前去掉客户名/门店名/可识别字段, 只发结构/数字/占位; 原始标识不出境。
- (b) **私有/本地模型模式**(给敏感/合规客户): LLM 层也能跑本地小模型(embedding-service 已本地; 加一个本地 LLM 选项/可配置 provider, 数据不出客户/我方隔离环境)。
- (c) **数据出境审计日志 + 透明告知**: 记录"哪些字段发给了哪个外部服务", 可导出可演示——让"数据主权"可审计、可证明, 而不只是口号。
**为什么 P0**: 这是把官网刚锐化的"数据主权"卖点变成真功能 + 消除"说一套做一套"的硬伤。也是反脱媒最直接的功能化。

### P1 — 责任锚点做成一等公民
现在批次追溯/防呆有责任人, 但"签字担责/不可篡改审计/出事倒查到人/审计导出"不够强。
- 关键写操作 + 审批 = 责任人签字 + 时间戳 + 防篡改留痕(tamper-evident)。
- 食安事故倒查链(批次→责任人)+ 一键审计导出(合规/出事用)。
- 这是 agent 永远给不了的, 做成产品一等公民(独立"责任/审计"视图)。

### P1 — 线下物理边深投(agent 杀不掉, 且工厂客户明确要)
- **视觉品控**(异物检测: 头发/钢丝球/石头)——Cretas 有 efficiency_recognition(VL), 扩展到品控异物/贴标校验。替代客户现在的 5 人 5 道品控。
- **摄像头人效**(已有 VL 人效)——深化, 出每人/每环节效率 + 报工。
- **电子秤对账**(已有 scale tools)——深化: 毛菜净菜出成、防偷(收重自动上传 + 责任分清)。
- **报工终端 OTA**——之前没闭环(客户还在用旧 App, 报工转圈未解), 修。

### P1 — 中立撮合层(不持货)
- 原材料价格库 + 三价比价(部分已有)+ 供应商库 + "这个料贵了, 市场价 X, 推荐源头"——**中立推荐, 不持货**。
- 自动叫货(餐饮: 按销量/天气/节假日/供应商频率)、安全库存预警(销量下滑→自动调减生产计划; 客户超期没交货→提醒跟进)——录音里反复要。
- 明确系统边界: Cretas 不持库存、不卖货(保中立); 撮合分成。

### P1 — 工厂端深做(把已有的做透)
- 智能排班/排货/交货时间预测(订单→排产→原料→交货)。
- 防偷对账(米/油盗、毛菜出成、责任分清 + 智能称重上传)。
- 出成率/浪费定位(加工浪费 vs 原料出成率低)。
- 老板"问一句出结果"(今天营业/毛利/库存/哪个菜品毛利低)——SmartBI 已有, 接工厂数据。

### 不做 / 收手(省力气)
- 不再堆几百个薄工具(盘点/扩工具不是重点; 真正难的是数据+集成+物理边)。
- 省 token 层够用即可(工程卫生, 不投战略资源)。
- **不完全开放/标准化 API 给第三方 agent**(= self-commoditizing; 保留 Cretas 自有编排独占的完整调用路径)。
- 餐饮端不投资源做"通用经营分析"和美团免费 AI 硬拼。
- 不自建基础模型。

**做:** 单客户深度交付(卤味厂 F006 + 川式连锁本季度真付费的东西); P0 数据主权矛盾先解; 责任锚点 + 物理边深投; 工厂端做透; 中立撮合(不持货); 把酷虎定位为渠道+供应链+持货合伙人(书面分工分成)。

## 8. 最大风险 + 不确定性(诚实标注)
- 美团免费补贴 → "更便宜"无效, 餐饮端被碾压风险; 工厂端是更安全的退守。
- 3 壁垒能否支撑溢价**未验证**; "客户不把数据给 agent"是**未验证的行为假设**(很多人已把 Excel 贴公有大模型)。
- 客如云"产品全开放"= 把 IP 给阿里系的风险; 客如云阿里全资状态须确认。
- 供应链变现经济残酷 + 中立冲突, 必须轻资产不持货。
- 单一 partner(酷虎)押死风险 + 他方向发散("有钱赚的活都干")。
- 现有 2 客户能否撑到壁垒变现 = 现金流根本不确定性(青花椒欠款已是信号)。
