# 驳回一条报工，库存不会跟着退 —— 「实时入库 + 事后核对」目前缺后半截

**日期**: 2026-08-17
**来源**: web-admin 生产 E2E（F006 批次 10759）
**状态**: 已定性，**未实现**（缺的是功能，不是缺陷修补）

---

## 实测

| 动作 | 读数 |
|---|---|
| App/接口提交第②道产出 2.5kg | 半成品 `336` 建行 `produced 2.50 / available 2.50 / AVAILABLE`；任务 1786 → `COMPLETED 2.5000` |
| 文员在「报工审批」页点**驳回**（理由「不同意」） | 报工 `23814 → REJECTED`、`rejected_reason=不同意` |
| **驳回之后** | 半成品 `336` 仍是 `2.50 / AVAILABLE`；任务 1786 仍是 `COMPLETED 2.5000` |

**下一道照样能领走文员刚判为无效的那 2.5 kg。**

## 为什么这条要紧

Steve 定的模型是：

> 不用审批，反正这个是实时报工，最后一天结束下来的时候也是需要去核对一遍，
> 当然库存还是要实时的，只是说**如果在核对的时候有问题的时候，可以直接更改，然后库存也更改**。

**实时入库之所以可以接受，前提就是核对能纠正它。** 核对纠正不了库存，实时入库就变成不可追溯 ——
错的数进了库，系统里没有任何动作能把它退出来。

## 现状（代码层面，已核实）

- `ProcessWorkReportingServiceImpl.rejectReport` 只写 `approvalStatus / rejectedReason / approvedBy / approvedAt`，
  **一处都没碰库存**（grep 计数 = 0）。
- `ProcessWorkReportingController` 只有 `approve / reject / batch-approve / by-task`，
  **没有冲销端点**。
- `ProductionReport.reversalOfId` 这个字段**只被读进 DTO，全仓没有任何地方写它** ——
  冲销的位置留好了，实现没写。

⚠️ 所以「撤回审批」菜单不解决这件事：那是 OA 审批流的撤回，与报工库存无关。

## 建议（未实施，需 Steve 拍板口径）

冲销要走**反向流水**而不是改原始行 —— 原始报工是工人做过的事实，不该被抹掉：

1. 驳回 / 修改时，生成一条 `reversalOfId = 原报工` 的冲销报工；
2. 让 `WipInventoryService` 对冲销报工过一次**反向**账（产出减回去、领用还回去），
   与正向过账同一个事务、同一套幂等标记；
3. 任务的 `status / actual_quantity` 按剩余有效报工重算，⛔ 不是直接置回 PENDING。

⚠️ 第 2 步要先回答一个问题：**上一道的产出已经被下一道领走了怎么办**
（本轮实测里 336 被领空过一次）。至少有两种口径 —— 拒绝冲销并提示「下游已领用」，
或允许冲销并把下游一起标记待复核。**这是业务口径，不该由我替 Steve 选。**

## 同一页上的第二条（内容缺口，不是接线缺陷）

驳回弹窗的「常用语」是**必选**的，而可选项是一份通用审批话术：

```
同意 / 不同意 / 请补充材料后重新提交 / 已核实 / 金额过高，需总监审 / 其他(自定义输入)
```

驳回一条报工却要从「**同意**」「**已核实**」「**金额过高，需总监审**」里挑一个。
没有一条说得清报工哪里错了（数量填错 / 投入与实际不符 / 工序选错 / 照片不清）。

机制是**接上的**：`GET /opinion-templates/available?decisionType=…` 已按 `decisionType` 过滤，
只是 5 条系统种子（Flyway `V20260605_01`）**全归在 `CUSTOM`** 下，
且表里没有「场景」维度区分报工与采购。

⇒ 这是**内容缺口**，与「42/186 工序没配半成品产出编号」同一类：
机制在，内容要业务侧来写。⛔ 我没有替他们编报工驳回话术 —— 那是他们的车间用语。
