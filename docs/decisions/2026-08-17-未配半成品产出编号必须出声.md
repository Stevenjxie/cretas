# 未配「半成品产出编号」的工序，报工时必须出声

**日期**: 2026-08-17
**决策人**: 本 chat（Steve 授权范围内自裁）
**触发**: F006 生产端到端走查

---

## 事实（实测，不是推断）

| 读数 | 值 |
|---|---|
| F006 配了 `semi_finished_output_code` 的工序 | **42 / 186（23%）** |
| LIUSHANMEN | 13 / 22 |
| 客户在用的批次 `10759` 三道工序 | **一道都没配** |

后果链：

```
工序没配 semiCode
  → output-options 返回 {"items":[]}
  → RN 报工屏【根本不显示】半成品产出栏
  → 工人报完工, 返回 200, 一切看起来正常
  → postSemiOutputLedger 静默跳过 (DEBUG 级日志)
  → 下一道工序【领不到料】
  → 没有任何人被告知哪里不对
```

⇒ **这就是客户说的「上工序报工，下工序就没有库存」的直接成因之一。**
它不是代码 bug，是**配置缺口 + 静默失败**的组合。

## 决策

**当一道工序后面还有未完成的下一道、而本道没有配半成品产出编号时，
报工响应必须带一条非阻塞警告，并给出下一步。**

```
本道未配「半成品产出编号」，产出没有进入半成品库，第③道领不到料。
请在 工序管理 → 卤制 里配置后重新报工。
```

### 为什么是「警告」不是「拒绝」

- **拒绝**（422）会把只报工时/只报人数的合法场景一起挡死，而且存量 144 道未配工序会瞬间全部报不了工 —— 那是一道当天被关掉的闸。
- **静默**（现状）是最坏的：用户以为成功了。
- ⇒ 取中间：**做完，但明说做了一半，并指出下一步**。与既有的 `balanceWarning`（物料平衡偏差）同一档。

### 为什么判据是「后面还有未完成的下一道」

- 末道工序产出的是**成品**，本来就不该进半成品库 —— 对它报警是误报。
- 一道天天误报的提示，最终结局是被无视，那时它的覆盖率归零。
- ⇒ 判据必须**窄而可信**：只在「产出确实需要被下一道领用」时才出声。

## 被否掉的方案

| 方案 | 否掉的理由 |
|---|---|
| 自动生成 semiCode | 编号是业务标识，系统编一个出来，用户在别处对不上账。⛔ 不替用户编数据 |
| 建厂时强制全配 | 144 道存量改不动；且不是每道都产半成品 |
| 只在 UI 上提示、后端不管 | web-admin 和 RN 两处都要写 → 形态 D。判据应该在**产出这一侧**算一次 |

## 判据

- 有下一道未完成 + 本道未配 semiCode + 本次有产出 → 响应带 warning
- **末道**（后面没有工序）→ ⛔ 必须安静（阴性对照）
- **已配 semiCode** → ⛔ 必须安静（阴性对照）
- 变异：把「有没有下一道」这个条件去掉 → 末道那条阴性对照必须红
