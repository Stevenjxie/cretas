# 契约的 `analysis_action` 要认「诚实说明算不出来」—— 设计卡

**日期** 2026-08-17 · **决策人** 本 chat（全权）· **状态** 已裁定，按推荐项做

---

## 一 · 实测事实

拒答归因图（8/8 有效样本）显示 **契约 `analysis_action` 是最直接的拦截方（4/8）**，
而接地闸**从不单独拦人**（0/8，它总是经契约拒的）。

看契约怎么判（`answer_contract.py:278`）：

```python
def _analysis_action_present(spec, answer_text) -> bool:
    if spec.analysis_action == "diagnose":
        return _contains_any(answer_text, ("原因拆解","计算构成","驱动因素",
            "不能证明因果","前提成立","前提不成立",…))
    if spec.analysis_action == "optimize":
        return _contains_any(answer_text, ("优化目标","优化建议","优化动作","验证指标"))
    return True
```

**纯魔法词白名单。** 两个问题叠在一起：

1. **写了实质分析但没沾白名单词 ⇒ 不算数。**
   LLM 自然会写「主要来自客单价下降」「建议先试点在三家店…」，一个白名单词都不沾。
2. **诚实说明「算不出来」也不算数。**
   而契约在别处**自己就有**这条哲学 —— `_EXPLICIT_GAP_TOKENS` 的注释原话：

   > an explicit, honest "we could not compute this" disclosure
   > **satisfies the contract just as well as a real number would**
   > (per spec section 4: 「缺不了就明说」is itself compliant, not a failure)

   **唯独 `analysis_action` 没接上这条哲学。**

▎问题 2 直接违背 goal 的**定义五**：答不了时说清缺什么/怎么拿到/自己要干什么，
▎**那本身就是一个合格的回答**。而现在它会被判不合规、整份拒掉。

## 二 · 一条不能忘的前车之鉴

契约里白纸黑字记着（`restaurant_intent_service.py` 兜底那段）：

> 2026-08-10 的事故：用户问「本月营收比上月低是什么原因」，契约正确判定
> 「没覆盖原因分析」准备拒答，兜底接住后回了一句「本月全部门店营收合计
> ¥6,490,180.61。」—— **用一个数字回答了「为什么」**。

⇒ **放宽 `analysis_action` 最大的风险就是重演这件事。**
⛔ 逃生口**不能**是「文本里随便出现一个 `缺少`/`无法` 就放行」——
那正好会让「营收合计 ¥X（某处提到缺成本卡）」蒙混过关。

## 三 · 三个选项

| | 做法 | 利 | 弊 |
|---|---|---|---|
| **A** | 扩白名单（把「建议」「主因」等常见写法加进去） | 一行改动 | ⛔ **还是白名单**，下个月又漏；且「建议」太松，一句无关建议就放行 |
| **B** | `analysis_action` 认**显式的分析缺口说明**：同一句里同时出现「做不到」标记**和**分析域词（原因/归因/为什么/优化/动作） | 接上契约自己的哲学；诚实回答成为合格答案（定义五）；**双条件同句**挡住「用数字回答为什么」 | 仍是模式匹配，只是判据更窄更准 |
| **C** | 干脆不要求 `analysis_action` | 立刻不拦 | ⛔ **违反禁止降级**：那就等于允许用一个数字回答「为什么」，正是 8-10 事故 |

## 四 · 裁定：**做 B**

**推荐 B，⛔ 不做 C。**

理由：
1. **C 是把闸关掉** —— 8-10 事故的复现路径，⛔ 不走。
2. **A 治标**：白名单的问题不是词不够多，是**判据形态错了**；再加词还会漏。
3. **B 接的是契约自己已有的哲学**（`_EXPLICIT_GAP_TOKENS` 那条注释），
   ⛔ 不是新发明一套标准。
4. **B 的双条件同句**是关键：光有「缺少」不行，必须**在讲分析这件事**的那一句里说。
   这正好挡住 8-10 那种「正文全是数字、别处顺带提一句缺成本卡」。

## 五 · 验收判据

- **正向**：一句「这次算不出下降的原因，因为缺 X」应当**通过** `analysis_action`。
- **🔴 阴性对照（最重要）**：8-10 事故那种文本 ——
  「本月全部门店营收合计 ¥6,490,180.61。（另：部分菜品缺成本卡）」
  **必须仍然判不通过**。少了这条，B 会滑成 C。
- **阴性对照二**：完全不提分析的纯数字答案，必须仍然不通过。
- 变异：把双条件改成单条件（任一即可）⇒ 阴性对照必须红。

## 六 · 登记的盲区

- 「分析域词」和「做不到标记」两个集合仍是**人写的**。⚠️ 它是**代理判据**，
  ⛔ 不假装它等于「真的说清楚了」。要收敛得靠把面向用户的分析结论收到一处产出。
- 本卡只动 `analysis_action`。`diagnose` 与 `optimize` 两支的白名单本身没动 ——
  **问题 1（写了实质分析但没沾白名单词）本卡不解决**，登记，留给下一轮。
