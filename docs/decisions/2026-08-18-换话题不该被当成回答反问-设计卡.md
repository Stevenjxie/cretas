# 设计卡：老板换了话题，不该被当成在回答上一句反问

**日期** 2026-08-18 · **裁定** 本轮执行者（授权全权决策）· **状态** 🔵 **已实现并回退 · 挂账**

> ⚠️ 这张卡记的是一次**做出来又撤回**的改动。撤回不是因为没做完，
> 是因为**实现之后的读数推翻了裁定**。四条判据、13→2 的收敛过程、
> 以及「代价打在多数身上」这个结论，都是下一轮直接能用的东西。

## 缺陷（📏 三条件对照，阳性对照：三条件下对照问句全 `answer`）

```
A 独立 key，直接问「我要不要关掉最差的那家店」  → answer 948
B 共用 key，直接问                            → answer 948
C 共用 key，前面先问过「哪家店缺货最严重」      → clarification 14
                                                dims=['store']
                                                「你想针对哪家门店做优化决策？」
```

▎**他问「最差的那家」，系统反问「哪家」。**

而这一问正是北极星本身：老板要做一个决定（要不要关店）。

### 机制

前一句「哪家店缺货最严重」撞维度闸 ⇒ `_maybe_register_pending` 注册 pending
⇒ 下一句进来时 `_pending_pop` 命中，**无条件**走 `_parse_continuation`，
且 `combined_query = 前一句 + 新问句` ⇒ `store` 维度来自**前半句**。

⚠️ 这条正是 `_maybe_register_pending` 的 docstring 里**已经登记**的「未做」：
> ⛔ 未做，显式登记：真反问之后换话题仍会拼接 …… 归架构点 25。

现在它有了一个**可复现**的实例，且命中北极星。

## 三个选项

| | 做法 | 代价 |
|---|---|---|
| **(a)** | 走续接前**先独立编译一次**新问句；它自己就是完整问句（有 `intent` 且 `not clarification_needed`）⇒ 当新话题，丢掉 pending | 有 pending 时多一次编译（~1–3s）。📏 实测 24 条里 4 条拒答 ⇒ 约 17% 的轮次会触发 |
| (b) | 扩大「不注册 pending」的范围（把维度闸拒答也排除） | ⛔ `_maybe_register_pending` 的 docstring 明写：「缺时间 / 缺门店 / 说不清要看什么**照旧注册**，否则等于把整个澄清续接关掉（有阴性对照钉着）」 |
| (c) | 架构点 25：上下文存 spec 栈，⛔ 不存对话文字 | 正解，但是**跨模块重构**；本轮做不完，做一半比不做更危险（续接是核心路径） |

## 裁定：⛔ **不做 (a)** —— 判据可行，但代价的形状不对

⚠️ 这张卡的裁定**在实现之后被自己的读数推翻了**，两段都留着：
先是「(a) 可行」，然后是「(a) 的代价打错了地方」。

### 第一步：判据本身**已验证可分**（📏 各独立编译一次）

```
槽位回答  上个月 / 最近30天 / 陆家嘴店 / 全部门店 / 全部门店 最近30天 / 晚市 / 按食材
          → 独立成句 = False   **0/7 误判**
新话题    我要不要关掉最差的那家店 / 最近生意怎么样 / 哪家店卖得最好 /
          最近损耗怎么样 / 折扣力度多大 / 哪道菜毛利最高
          → 独立成句 = True    **6/6**
```

⚠️ 判据要**四个**条件，后三条**都是被既有断言逼出来的**（⛔ 不是设计时想到的）：

| 条件 | 被谁逼出来 |
|---|---|
| `intent` 非空 且 `not clarification_needed` | 「晚市」有 intent 但仍在回答反问 |
| `planner_authority == "llm"` | 📏 13 条既有断言：`trusted_context` / `explicit_*` / `promoted_exact` / `llm_unavailable` 全是**零 token** 路径，契约是 `assert llm.await_count == 0`（「T3 挂了也能续接」）。▎T3 都挂了，就没有资格再问一次 T3 |
| `source_tier == "llm"` | 📏 三轮链用例：独立编译「本月」**命中计划缓存**，返回完整 `GROSS_MARGIN` spec ⇒ 多轮链断掉。▎判据要的是「T3 现在看这句话认为它完整」，⛔ 不是「这句话以前出现过」 |
| `intent != 续接的 intent` | 同上。语义上这才是真正的那一条：**换话题 = 问的是另一件事** |

加满四条之后，13 条红降到 **2 条**。

### 第二步：那 2 条（后来是 3 条）红得**不一样** —— 它们钉的是**代价**

```
assert llm.await_count == 1      →  实际 2
assert planner.await_count == 2  →  实际 3
```

**主张全都还成立**（三轮链仍保留原指标、判据在那条链上实测返回 False、链路没被改道）。
红的只是**多了一次 T3 调用**。

我一度接受这个代价并改了那两条断言，然后**第三条同类用例也红了** ——
全是核心的澄清续接场景。

▎**代价打在多数身上，收益只在少数身上。**
我原以为触发条件很窄（续接后仍需澄清 + `authority == llm`），
实测它覆盖的是**几乎每一个澄清续接轮次**，而真正「换话题」的是少数。

⇒ ⛔ 回退。**判据没错，形状错了。**

### 正确的方向（下一轮）

让**同一次续接调用**回答这个问题 —— 续接本来就要调一次 T3，
在那次调用里让它同时判「这句话是在回答我，还是换了话题」。
⛔ 不额外调一次。那是 prompt 层的改动，需要独立一轮 + 自己的对照。

## ⛔ 明确不做

- **不**据此跳过澄清 —— 判成新话题时走的是正常新问句流程，该反问照样反问。
- **不**用关键词判断「像不像新话题」—— 已裁定不重开关键词路由。
- **不**为了让那几条断言变绿而把 `await_count` 一路往上改 ——
  ▎那是**把代价藏进断言里**，而那几条断言存在的理由正是钉住这个代价。

## 挂账 · 解冻条件

出现下面任一条即解冻：

1. 续接的 T3 调用被改成能**同时**输出「这是回答 / 这是新话题」（prompt 层），
   ⇒ 那时判据零额外成本，本卡第一段验证过的四条件可以直接复用；
2. 或者实测证明「续接后仍需澄清」的轮次占比 **< 10%**
   （那时多一次调用的代价才落在少数身上）。⛔ 目前没有这个读数。
