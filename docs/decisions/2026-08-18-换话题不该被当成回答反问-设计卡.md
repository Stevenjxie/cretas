# 设计卡：老板换了话题，不该被当成在回答上一句反问

**日期** 2026-08-18 · **裁定** 本轮执行者（授权全权决策）· **状态** ✅ **已执行**（中途回退过一次，回退理由被读数否掉，见下）

> ⚠️ 这张卡的裁定**改过一次**：先做、后回退、再重做。
> 回退的理由（「代价打在多数身上」）**没有读数支撑**，补量之后被否掉。
> 两段都留着 —— 错误的评估本身是这张卡最有用的部分。

## 缺陷（📏 三条件对照，阳性对照：三条件下对照问句全 `answer`）

```
A 独立 key，直接问「我要不要关掉最差的那家店」  → answer 948
B 共用 key，直接问                            → answer 948
C 共用 key，前面先问过「哪家店缺货最严重」      → clarification 14
                                                dims=['store']
                                                「你想针对哪家门店做优化决策？」
```

▎**他问「最差的那家」，系统反问「哪家」。**

而这一问正是北极星本身：老板要做一个决定（要不要关店）。

### 机制

前一句「哪家店缺货最严重」撞维度闸 ⇒ `_maybe_register_pending` 注册 pending
⇒ 下一句进来时 `_pending_pop` 命中，**无条件**走 `_parse_continuation`，
且 `combined_query = 前一句 + 新问句` ⇒ `store` 维度来自**前半句**。

⚠️ 这条正是 `_maybe_register_pending` 的 docstring 里**已经登记**的「未做」：
> ⛔ 未做，显式登记：真反问之后换话题仍会拼接 …… 归架构点 25。

现在它有了一个**可复现**的实例，且命中北极星。

## 三个选项

| | 做法 | 代价 |
|---|---|---|
| **(a)** | 走续接前**先独立编译一次**新问句；它自己就是完整问句（有 `intent` 且 `not clarification_needed`）⇒ 当新话题，丢掉 pending | 有 pending 时多一次编译（~1–3s）。📏 实测 24 条里 4 条拒答 ⇒ 约 17% 的轮次会触发 |
| (b) | 扩大「不注册 pending」的范围（把维度闸拒答也排除） | ⛔ `_maybe_register_pending` 的 docstring 明写：「缺时间 / 缺门店 / 说不清要看什么**照旧注册**，否则等于把整个澄清续接关掉（有阴性对照钉着）」 |
| (c) | 架构点 25：上下文存 spec 栈，⛔ 不存对话文字 | 正解，但是**跨模块重构**；本轮做不完，做一半比不做更危险（续接是核心路径） |

## 裁定：**做 (a)**（⚠️ 中途回退过一次，回退的理由是错的）

### 判据已验证可分（📏 各独立编译一次）

```
槽位回答  上个月 / 最近30天 / 陆家嘴店 / 全部门店 / 全部门店 最近30天 / 晚市 / 按食材
          → 独立成句 = False   **0/7 误判**
新话题    我要不要关掉最差的那家店 / 最近生意怎么样 / 哪家店卖得最好 /
          最近损耗怎么样 / 折扣力度多大 / 哪道菜毛利最高
          → 独立成句 = True    **6/6**
```

判据要**四个**条件，后三条**都是被既有断言逼出来的**（⛔ 不是设计时想到的）：

| 条件 | 被谁逼出来 |
|---|---|
| `intent` 非空 且 `not clarification_needed` | 「晚市」有 intent 但仍在回答反问 |
| `planner_authority == "llm"` | 📏 13 条既有断言：`trusted_context` / `explicit_*` / `promoted_exact` / `llm_unavailable` 全是**零 token** 路径，契约是 `assert llm.await_count == 0`。▎T3 都挂了，就没有资格再问一次 T3 |
| `source_tier == "llm"` | 📏 三轮链：独立编译「本月」**命中计划缓存** ⇒ 多轮链断掉。▎判据要的是「T3 现在看这句话认为它完整」，⛔ 不是「这句话以前出现过」 |
| `intent != 续接的 intent` | 语义上真正的那一条：**换话题 = 问的是另一件事** |

**位置**也是被逼出来的：必须在 `_parse_continuation` **之后**。
第一版放在 `_pending_pop` 之后 ⇒ 13 条断言当场红。
▎判据红了不许加豁免，要看它逼出什么 ——
▎它逼出的是「**只有在确定性续接已经失败时，才有资格多花一次编译**」。

### 🔴 我回退过一次，回退的理由是错的

回退时我写的是「代价打在多数身上，收益只在少数身上」。
**那个评估没有读数支撑。**

📏 补量之后：触发条件是「上一轮拒答了」，而全景 24×2（生产形态）
**拒答 8/48 = 17%** ⇒ 只有这 17% 的下一轮可能付这一次编译，
**而收益正落在同一批轮次里**。
我说的那个「多数」是**澄清链内部**的多数，而澄清链本身只占 17%。

⇒ 按取舍顺序（**能不能决定 > 数字准不准 > 覆盖得全不全**），
延迟不在这三条里，而「答非所问」直接伤第一条。⇒ 接受代价。

### 三条计数断言怎么处理

`assert llm.await_count == 1 → 2`、`assert planner.await_count == 2 → 3`。
⛔ **不是**为了让它变绿 —— 每一处都在断言旁写明：**主张一个字没变**
（那几条守的东西原样保留），变的是**代价**，并附上 17% 那个读数和设计卡链接。

⚠️ 中途我把注释挂错了测试（同一段注释在两处匹配），已挪到真正改了的那一条上。
▎描述过期比没有描述更糟。

## ⛔ 明确不做

- **不**据此跳过澄清 —— 判成新话题时走正常新问句流程，该反问照样反问。
- **不**用关键词判断「像不像新话题」—— 已裁定不重开关键词路由。
- **不**靠「不注册 pending」来修：📏 四组对照证明元凶是「米饭卖得怎么样」
  注册的**合法槽位反问**，它真的在问槽位。
