## 一、第 1 步读数：`synthesis_engine.py` 里有没有两段式

**方法**：AST 数结构（`ast.walk` 取 `ClassDef` / `FunctionDef` / `Call`），
⛔ 不用文本 grep。阳性对照：五个已知存在的结构
（`_grounding_findings` / `_narrative_grounding_violations` /
`_keep_what_is_grounded` / `strip_ungrounded_lines` /
`ComprehensiveSynthesisEngine`）必须全部被数到 —— **通过**。

### 读数（实测）

`synthesize` 是**一趟**流程，⛔ 没有「先执行排行 → 拿到实体 → 二次核对 → 二次执行」
的两段式：

```
1 精确缓存 → 2 预算 → 3 plan_dimensions(规则, 无 LLM) → 3b 语义缓存
→ 4 _build_factbook(按 plan 并行拉 gold) → 5 _analyze
→ 5b 薄复述(纯归因问句) → 6 LLM 叙述 → 7 接地闸 → 8 图表/告警 → 9 缓存
```

`SynthesisResponse` 有 5 个构造点（缓存命中 / 语义缓存 / 薄复述 / 兜底 / LLM），
每个都是**这一趟**的出口，没有一条路会回到第 4 步再跑一次。

## 二、#19「计算式指代」：不是没做，是换了个形状做的

例 15 要的四步，仓里的对应物（**实测**，⛔ 不是读注释推的）：

| 例 15 | 仓里是什么 | 证据 |
|---|---|---|
| ① 识别「这是计算式指代，且说了是【店】」 | `plan_dimensions` 的 `_wants_store` × `_wants_lag` 规则（⛔ 不用 LLM） | `plan_dimensions("最差的那家店是哪家")["attribution"] is True`；`("哪家店拖后腿")` 同 |
| ② 先执行一次计算 → 得到具体店名 | `factbook.compute_store_attribution`：`laggard = min(stores, key=delta_revenue)`，在有效门店集合上算 | prod 实测 laggard=`模拟·打浦桥日月光店` Δ=¥-35,623 |
| ③ 那个店名才进核对 | `FactReconciler.reconcile` + `_thin_store_names` + 接地闸；实体名编不出来 | 三处都在 `synthesize` 第 7 步之前 |
| ④ 再执行决策分析 | LLM 拿 FactBook（含 laggard + 效应分解）写叙述 | prod 正文引用了 353.7 / 359.4 / 5845 |

⇒ **判据「维度确定了没有」由规则词表承担，计算由确定性函数承担，核对由 reconciler
承担。** 三件事都在，只是没有排成两次执行。

**实测反证也在**：例 15 里那句「那最差的呢」（维度没确定，必须反问）——
`plan_dimensions("那最差的呢")` 的 `attribution` 是 `False`，也不会点亮归因，
即它不会拿一个没确定维度的指代去算。这条判据的方向是对的。

⛔ **所以本轮不做两段式。** 为一个不复现的缺陷做大工程，正是反目标里那条。

### 唯一一处窄缺口：登记，不做

`_wants_store` 的词表**不含「那家店 / 这家店」**（有「哪家 / 哪个店 / 各店」）。
所以「我要不要关掉最差的那家店」在**无 history** 时 `_wants_store=False`。

⛔ 不补这个词。理由是实测的：补了之后 plan 只剩 `attribution=True`，
`_is_thin_restate_eligible` 变成 True ⇒ 走 500-token 的**薄复述**，
对「要不要关店」这种决策问句**比现在更薄**。
⇒ 真正该修的是「这是个决策问句」，不是「这里有个门店词」——见第三节。

**解冻条件**：如果日后薄复述路径也带上决策要素（前置条件 / 验收 / 时间窗口），
再回来补词表。

## 三、#18 归因七步链：哪几步有、哪几步没有

| 步 | 例 14 说的 | 现状（实测） |

| ② | 拆成量 × 价 | ⚠️ **函数有，决策问句够不着** ← 本轮修的就是这个 |
| ③ | 客流再拆（同比/环比；外部客流） | 🔶 同比/环比有；`physical_traffic` 无数据源，登记在 `missing_dimensions` |

**排序依据**：「哪一步补上之后老板更能做决定」。
② 是「关店还是修客单价」的分水岭 —— 它是整条链的地基，且**代码里已经有**。
⇒ 本轮只做 ②。

### ② 的病是「机制在，没接上」（形态 B）

📏 prod 实测（MOCK_REST，真实入口 `tiered_answer`，绕过 `narrative_cache`）:

```
问「我要不要关掉最差的那家店」
  synthesize 收到 '我要不要关掉最差的那家店 最近30天'
  mode=lookup / auto_expand=False / attribution=False
  factbook.attribution = None          ⇒ 量价分解那一步根本没跑
```

成因：`decision_cues` 十四个词**全是「怎么做」型**
（怎么改善 / 怎么办 / 给建议 / 优化方案 …），**一个「要不要 / 该不该」型都没有**。
而是非题恰恰是老板最直接的决定。

### 改法

```python
_yes_no_decision_cues = ("要不要", "该不该", "值不值得", "划不划算",
                         "有没有必要", "是不是该", "是否应该", "是否值得")
_is_yes_no_decision = (any(k in ql for k in _yes_no_decision_cues)
                       and (_wants_store or _wants_lag))
```

- 复用**已有的** `_wants_store` / `_wants_lag`，⛔ 不新造第二张门店词表（形态 D）。
- ⛔ 不写第二份量价分解 —— 分解仍然只有 `compute_store_attribution` 一份。
- ⚠️「能不能」故意不收：「能不能给我看看营收」是取数请求，不是决定。
- ⛔ **故意没把「关店 / 关掉」加进 `_HIGH_IMPACT_ACTION_RE`**：prod 基线里
  「关掉它省不了多少成本，反而少一块收入」是**后果陈述**不是建议，而那道闸是
  分句级的、这个分句里没有安全措辞 ⇒ 加词会把这句有用的话**整行删掉**。
  有一条断言钉着这个「故意不做」，日后有人加词它会红。

### A/B（prod，MOCK_REST，各 3 轮，绕过叙述缓存）

⚠️ 两侧是**同一棵 prod 源码树的副本**，只有 `synthesis_engine.py` 一个文件不同；

## 四、第 ⑤ 步「反问现实事件」：三个选项、裁定、以及为什么不上线

> 「这两家店最近是不是有商场活动、施工、周边变化？」

它的价值是**产品承认自己看不到线下**，把那部分交给老板。
它的风险是**每次都问就是废话** —— 反目标里最重的那条。

### 判据（设计完成，由数据算出，⛔ 不是无条件追加）

三条同时成立才追加，任何一条不成立就闭嘴：

1. `laggard.delta_revenue < 0` 且 `|Δ| / bench_revenue >= 阈值`
   —— 差距要有实质规模。**MOCK_REST 实测 1.5%，落在这条下面 ⇒ 不问。**
2. `primary_cause == "客流"` —— 差在**人少了**。
   客单价差是内部可解释的（折扣 / 菜品结构 / 渠道），⛔ 不该拿商场活动去搪塞。
3. 能解释「为什么人少了」的外部维度全在 `missing_dimensions` 里
   （`physical_traffic` / `mall_activity` / `nearby_event` / `competitor`）
   —— 有数据就用数据答，⛔ 不反问。

第 ⑦ 步跟着它一起收口：「这四条你都想不起来有变化 ⇒ 才更可能是门店自己的运营问题」。

### 三个选项

| | 做法 | 代价 |
|---|---|---|
| **A** | 按上面三条判据，在接地闸**之后**确定性追加一段（同 `_append_dimension_guidance` 的形状，2~3 个接线点） | 判据在今天的数据上**一次都不会触发** ⇒ 无法验收「命中的那个店经不经得起老板去查」 |
| **B** | 写进 prompt，让 LLM 自己决定问不问 | 不确定、不可测，且可能被接地闸整行删掉；等于把「会不会变成废话」交给模型 |
| **C** | 不上线，把判据写进设计卡，等有能让它触发的租户再做 | 这一步继续缺着；老板暂时拿不到「线下变化」这条线索 |

### 裁定：**C**

📏 决定性读数（prod，`smartbi_prod_db`，逐租户设 RLS 会话变量并贴出
`current_setting` 确认生效）：

```

DEMO_REST      0 行 / 0 店        RES_3101_009  0 行 / 0 店

R_XMX_CHAIN    0 行 / 0 店        REST_DEMO     0 行 / 0 店     T001  0 行 / 0 店

而唯一那个租户的形状是：**10 家店咬在 2.7% 以内，最差店只比门店平均低 1.5%，
主因还是客单价不是客流** —— 上面三条判据**一条都不成立**。

⇒ 我**无法回答**反目标要求的那句：「排在最前面的那个命中，他去查会不会一无所获？」
因为**没有命中样本**。
⛔ 而「不知道会不会误发」就上一条会主动向老板提问的提示，赌的是

## 六、正文里那个**算错的派生数**：不复现，但裁定要留下

> 交接件报的原话：「最差和最好只差约 **59 万元**，占比不到 3%」
> 而真值是 206.7 万 vs 212.7 万 ≈ **6 万**。⚠️ 单个数就错了，而且量级差 10 倍。

### 6.1 读数：⛔ 不复现（9 轮 0 次）

📏 prod（MOCK_REST，真实入口 `tiered_answer`，绕过 `narrative_cache`，
每轮清 4 个缓存 helper）。⛔ clarification 轮**不折叠**进「没复现」——
它们是「没量到」，单独计数：

| 批次 | 尝试 | 真的重新生成 | 出现「59 万」 |
|---|---|---|---|
| 探针 A（3 轮） | 3 | 1 | 0 |
| 探针 A（6 轮） | 6 | 2 | 0 |
| 探针 B（MAIN 组） | 3 | 3 | 0 |
| 探针 B（NOATTR 组） | 4 | 3 | 0 |
| **合计** | **16** | **9** | **0** |

🔑 阳性对照：每轮记 `_build_prompt` 调用次数 + **喂给模型的门店行数**。
9 轮全是 `1 次 / 20 行`。⛔ 是 0 就说明答案根本没重新生成，读数无意义。

### 6.2 成因在哪一层：**LLM 自己算的，FactBook 根本没喂这个数**

📏 确定性真值（同一份 FactBook 现算）：

```
最高 模拟·徐汇美罗城店   ¥2,126,568.95
最低 模拟·打浦桥日月光店 ¥2,067,338.32
差额 ¥59,230.63  = 5.92 万元 = 占最高 2.79%
```

▎`59,230.63` 与交接件里那个 **59** 逐位吻合 ——
▎**减法它做对了，错的是量纲**：把 `59,230 元` 说成了 `59 万元`。

📏 `prompt 里含 59xxx 的串: 无` ⇒ 这个数**不在 prompt 里**。
它是 LLM 拿门店名单里两行自己相减得到的。
⇒ ⛔ 不是 FactBook 喂错，是 FactBook **没喂**。

同一批读数里还抓到它算对的那一次（MAIN 组第 2 轮）：

```
「模拟·打浦桥日月光店虽然营收垫底，但和第一名只差约6万（59,230元），差距不到3%」
```

▎**同一个派生数，9 轮里出现过 3 种说法**：`约6万（59,230元）` ✅ /
▎只说比例不说绝对值 ✅ / 交接件那次的 `约59万元` ❌。
▎⇒ 「不复现」说的是那个错读数，**不是那个机制**。

### 6.3 变异对照：**FactBook 不算，LLM 就会自己算**

同一棵树、同一个问句，唯一变量 = `_render_attribution` 开/关
（关掉之后 prompt 里没有任何确定性差额；变异到达已核对：
MAIN 侧 3/3 有那句「较门店平均少 ¥x」，NOATTR 侧 3/3 没有）：

| | LLM 自己去减门店名单 |
|---|---|
| **MAIN**（prompt 里有 `较门店平均少 ¥35,623.31`） | **1/3** |
| **NOATTR**（prompt 里没有任何差额） | **3/3** |

NOATTR 三轮的原话都是自己算的：「最高约212.7万，最低约206.7万」/
「只比第一名少6万左右」/「仅差2.8%」。

### 6.4 裁定：这一类**不能靠加闸守住**

逐条核对现有的三道防线（读代码 + 数值代入）：

| 闸 | 守什么 | 为什么守不到 `59 万` |
|---|---|---|
| `FactReconciler._reconcile_one_fact` | **已知事实名 + 紧跟的数字** | `59,230` **没有名字** —— 它不是 `to_facts_index()` 里的任何一项，结构上够不着 |
| `detect_numeric_hallucination` | `亿 / 千万` 且 > max_agg × 2 | 双重够不着：`万` **不在模式里**（`_HALLUC_PATTERN = (亿|千万)`），而且 590,000 < 2,126,568×2 —— **量级也在合法范围内** |
| `_grounding_findings`（接地闸） | 语义诚实（无保留因果 / 缺失维度当事实 / 未标注的预算 / 高影响动作） | 它**不看算术** |

⇒ **一个派生数要被守住，唯一的办法是给它一个名字** ——
   即由确定性函数算好、进 FactBook、进 `to_facts_index()`。
   **问题不是「谁来守」，是「谁来算」。**

⛔ **不写正则去抓「59万」**：形态 E 明令禁止「靠不断加启发式逼近语义」，
   而且上表第二行说明——任何**量级**闸都抓不到它，因为它落在合法区间内。
   要抓它必须先知道真值，而知道真值 = 已经把它算出来了 ⇒ 那就直接喂给模型。

### 6.5 ⚠️ 顺带发现：这个数**仓里已经有一份确定性实现**，只是在另一条路上

`restaurant_ops_router._store_revenue_spread`（PR #2807）算的就是
「最高与最低相差多少 / 百分之几」，还配着一道 AST 闸
（`tests/test_store_spread_is_computed_on_all_stores.py::TestOnlyOnePlaceComputesIt`）
钉着「只许一处在算」。

**而 synthesis 这条路的 FactBook 从来没渲染过它** ——
⇒ **形态 D 的一个新实例：同一个数，一条路上是确定性事实，另一条路上是 LLM 心算。**

⚠️ 同时登记一个**闸的覆盖面缺口**（本轮发现，⛔ 没修）：
那道「只许一处在算」的 AST 闸 `inspect.getsource(rr)` **只扫 `restaurant_ops_router`**。
有人在 `factbook.py` 里再写一份 `(hi-lo)/hi`，它一个字都不会说。

## 七、第 ⑥ 步（给排查方向）+ 第 ⑦ 步（都排查不掉才轮到运营）—— 本轮上线

### 7.1 为什么是确定性追加，⛔ 不是改 prompt

上一棒登记的是「改它要动 prompt」。**本轮改了这个判断**，依据是实测：

📏 MAIN 组 3 轮里，LLM **自己**说出 ⑥ 那类话的只有 1 轮：

```
「评价、时段、周边竞品等数据都没接入，现在缺数据判断这家店是"地段问题"还是"经营问题"」
```

▎它既不稳定（1/3），内容也没人核对。
▎**能确定性算出来的东西交给模型说，等于把「说不说」和「说得对不对」一起交出去。**
▎改 prompt 只能提高频率，改不了这一点。

⇒ 落成 `_append_investigation_directions`，与既有的
`_append_dimension_guidance` 同一个形状（接地闸**之后**的确定性追加）。

### 7.2 判据：只说**这份 FactBook 里真的有数**的那几维

数据源取 `factbook.available_dimensions` / `missing_dimensions` ——
与接地闸里那条**镜像规则**（有数据的维度不许说成「你没提供」）**同一个数据源**，
⛔ 不新造第二套判定（形态 D）。label 一律来自 `dimension_catalog`。

这是反目标那句话的直接落地：
▎**排在最前面的那个命中，他去查会不会一无所获？**
列进「能查」的每一维，它的数就在**这同一份答案的数据段里**。

⚠️ `status == "partial"` 也算「有数」，但**当场标出来它不全**
（例：优惠有结构、缺对照基线）——不标就是把「看得见结构」说成了「算得出结论」。

**⛔ 四道门，任何一道不过就一个字都不说**（每次都说就是废话，反目标里最重的一条）：

1. 这一轮没有跑归因（`attribution` 为空 / `no_data`）
2. 归因没给出拖后腿门店
3. `primary_cause` 不在登记表里
4. 能查的和查不了的**都是空**

📏 实测第 4 道门真的会关上：**薄复述路径**（`_is_thin_restate_eligible`）只请求
`attribution`，`desired` 里只有 `store_comparison`，于是四个候选维度既不在
available 也不在 missing ⇒ 那条路上它**必然闭嘴**（读代码 + 用例覆盖）。
⚠️ 接线仍然接了两处（硬约束 8：同一个结构的所有位置），⛔ 不因为「现在用不到」就少接一处。

### 7.3 主因 → 排查方向的登记表（⛔ 不是第二张维度表）

```
客单价 → 优惠与营销活动 / 菜品销售结构 / 堂食·外卖·自提 / 午晚市与时段
