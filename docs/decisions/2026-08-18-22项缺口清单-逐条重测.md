## 🔴 顺带发现：两个判据陷阱

### ① `resolve_by_code` 按签名过滤 kwargs —— 没声明的**静默丢弃**

这既是好事也是陷阱：

```
好: 「签名里有没有 dimensions」就是「它能不能拿到维度」的硬判据
坑: 有 **kwargs 的 resolver **照样收得到** —— 第一版探针漏了这一支,
    把 STORE_MARGIN / STORE_DIRECTORY 误报成缺口（假阳性）
```

⛔ 这条判据本身也是**跑一次证出来的**，不是读注释来的
（探针 `_dims_gap.py` 的 `_prove_silent_drop`：注册两个探针 resolver，
一个不声明 `dimensions` 一个声明，比较行为；阳性 + 阴性对照都过才出读数）。

⚠️ 第一版的对照挑了真 resolver（`STORE_DIRECTORY`），它在 `None` pool 上
先炸了 `AttributeError` 而不是 `TypeError` ⇒ **阳性对照没过，读数当场作废**。
▎会读出「全都没有」的仪器必须配对照 —— 这次对照救了一次错读。

### ② 「答案不同」有两种，要用来源标记分开

量「维度起没起作用」时，两句答案不同**可能只是两次不同的 LLM 编译**。
所以探针里：

```
阴性对照  同一句问两遍（每次清 4 个缓存）必须**相同** —— 否则有非确定性，比不了
阳性对照  WASTAGE_TOP（已收 dimensions）两句必须**不同** —— 否则仪器坏了
来源标记  每条读数带 tier（llm / plan_cache / llm_contract_repair）
```

📏 实测：阴性对照 `fp=51ca4999` 两遍相同 ✅ / 阳性对照不同 ✅ ⇒ 读数有效。
