# 团购营收被一个破折号抹掉 —— 设计卡

**日期**: 2026-08-18
**状态**: 已执行
**触发**: 逐条读交付定义② 的读数原文时撞见（⛔ 不是探针报出来的 —— 探针的判据看不见它）

---

## 📏 缺陷（prod 实测，MOCK_REST）

问「外卖和堂食各占多少」，产品给的表是：

```
| 渠道 | 营收          | 营收占比 | 单量    | 单量占比 |
| 堂食 | ¥13,373,190  | 63.6%   | 36,393 | 62.2%  |
| 外卖 | ¥5,652,559   | 26.9%   | 16,266 | 27.8%  |
| 团购 | —            | —       | 5,859  | 10.0%  |
```

**63.6% + 26.9% = 90.5%。** 老板一加就发现少了 9.5%，而表上那个「—」在说
**「没有这个数」**。

直接查库（`fact_pos_transaction`，同一窗口，RLS 上下文已断言）：

```
order_type        bills            revenue   net_amount为NULL
dine_in           37647       13821643.00          0
takeaway          16786        5833427.33          0
groupon            6085        2078299.07          0     ← 有，且一条空值都没有
```

**团购营收 ¥2,078,299.07（9.6%）完完整整在库里。** 是产出端把它抹掉的：

```python
for name, r in typed.items():
    if name not in ("堂食", "外卖"):
        ...
        channel_rows.append([name, "—", "—", f"{other_bills:,}", f"{other_pct:.1f}%"])
```

而 `total_rev`（营收占比的分母）**是含团购的** —— 所以那 9.5% 既进了分母、
又没显示出来。

⚠️ 那段代码的注释写着「堂食/外卖有金额, 其它渠道只有单量」——
**那句话本身就是被实测否掉的那一句**。⛔ 不从注释推断行为，跑一次让它自己说。

▎这与 8-18 修掉的「这两层的数不在同一张表上」是同一形状：
▎**产品在对老板说假话**，只不过这次是用一个破折号说的。

---

## 三个选项

| | 做法 | 代价 |
|---|---|---|
| A | **有金额就显示金额和占比**；真没金额时打「—」并加一句说明 | 表宽不变，多一个分支；需要区分「金额是 0」和「金额没落库」 |
| B | 把非堂食/外卖的渠道整行从表里删掉 | 占比自洽了（分母也要跟着改），但**老板看不到团购有 6,085 单** —— 用删数据换自洽，更糟 |
| C | 保留「—」，在表下加一句「团购的营收未展示」 | 最小改动，但那是**给假话加个脚注**：数就在库里，没有任何理由不显示 |

**裁定：A。**

理由：这不是「要不要多给一个数」的取舍，是**表里那个格子在说假话**。
反目标第一条说「一条误发的提示，烧掉的是『这东西说的话能信』」——
一个和分母对不上的百分比列，比一条误发的提示更伤，因为老板**自己就能验出来**。

B 的代价最大：它让读数自洽的手段是**减少老板知道的东西**。
C 等于承认这个数存在却不给 —— ⛔ 没有理由。

⚠️ 保留「真的没有金额」那一态：那时 `total_rev` 也不含它，
剩下几行的占比自洽，只需要一句说明。
⛔ **不把「不知道」翻译成 0**（形态 A¹⁰）。

## 顺带做的第二件事（交付定义②）

同一个答案里，「各门店渠道构成」表列了 10 家店的外卖占比 27.3%~28.5%，
产品**一个字都没说**。老板问的是「各占多少」，他没问「门店之间差多少」——
那就是「一件他没想到的事」。

⛔ **只陈述极差，不下阈值判断**（「差异很小 / 差异很大」要一个我拍脑袋的阈值，
而反目标说「宁可这一类先不提示」）。所以只说：

> 各门店的外卖占比：最高 X（a%）、最低 Y（b%），相差 c 个百分点。

1.2 个百分点还是 20 个百分点，老板自己看得出来 —— **判断留给他**。

## 能让判据红的对照

| 变异 | 应该打红 |
|---|---|
| 团购那一行改回无条件打「—」 | 自洽闸：**营收占比之和 ≈ 100%** |
| 「真没金额」那一态也强行显示 ¥0 | 阴性对照：0 元渠道必须打「—」 |
| 门店极差那句删掉 | ② 那条断言 |
| 极差那句写死成固定门店名 | 换一份桩数据后名字必须跟着变 |

🔴 **自洽闸能不能红要先证明**：团购行打「—」时，它的占比不进和 ⇒
和 = 90.5% ≠ 100% ⇒ 闸红。✅ 这道闸真的在守这件事，
⛔ 不是「左右两边由构造相等」的那种（形态 B⁴）。

## 登记：没做的

- **门店表的「营收」列是全渠道合计**，与上面那张表的「营收」（分渠道）口径不同。
  两处都叫「营收」。⚠️ 暂不改 —— 改列名要同时改 RBAC 那一支和无金额那一支，
  且没有读数说老板混淆过。**条件**：有一条真实反馈说这两个数对不上，就动。
