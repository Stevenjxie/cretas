# 问答稳定性报告 —— 「我昨天不是能答吗」

**日期**: 2026-08-15   **租户**: `MOCK_REST`   **角色**: `restaurant_manager`
**状态**: 只量不修。⛔ 本轮零产品代码改动。

> 每次跑前清 4 个缓存（硬约束 3）：
> `clear_semantic_plan_cache, clear_route_cache, clear_tenant_gate_cache, clear_promoted_routes_cache`
> 每条读数带 `[租户]` 与 `source_tier`（形态 A¹³）。⛔ 没有来源标记的读数不作数。

---

## 结论一句话

**三个「非确定性」里，只有一个是真的。**

| # | 原判 | 实测 |
|---|---|---|
| ① 闸在槽位相同时翻转 1/10 | 闸不稳定 | ❌ **闸是确定的**。抖的是喂给它的 `dimensions` 一个字段 |
| ② 空 spec 1/10 且照样给答案 | 有回退路径在答 | ❌ **不复现**。空 spec 真实存在（LLM 超时），但**全部 fail-closed 成反问** |
| ③ 上下文串 | 从没真正量过 | ✅ **真的**。有效分母 13，真串 **3/13 = 23%** |

⚠️ ① 和 ② 的原判**都建立在我自己仪器的缺陷上**：我先 `parse_restaurant_query()`
记 spec、再 `ask()` 记 kind，中间清了缓存 ⇒ **那是两次独立编译**。
把 spec 换成 `res["spec"]`（同一次调用返回的那份）之后，两个现象都消失。

## ① 闸翻转 —— 定位到 `dimensions`，闸本身确定

### 硬停止一：那道闸**不调 LLM** ⇒ 不触发

`restaurant_intent_service.py:1565` 的 `_execution_mismatch(...)` 是**纯函数**，
完整输入清单只有五项：

```
spec, plan,
dish_mention  = spec.dish_slot or extract_dish_candidate(resolver_query)
                              or extract_dish_candidate(query)
store_mention = （同文件上方计算）
store_dish    = store_dish_split_dish(query) or store_dish_split_dish(resolver_query)
```

⛔ 无 LLM 调用、无随机数、无时间、无 spec 之外的会话状态。
⚠️ 但注意：闸之前一行有 `spec = _drop_unanswerable_mislabeled_dimensions(spec, plan, query)`
—— **spec 在进闸前被重写过一次**。

### 读数（12 次，spec 与 kind 绑在同一次调用）

```
### [MOCK_REST] '全部门店最近30天报损情况严不严重'
  [ 1] kind='answer'         source_tier='llm' intent='RESTAURANT_OPS_WASTAGE_TOP' agg='None'    dims=()                 闸=no
  [ 3] kind='answer'         source_tier='llm' ...                                 agg='summary' dims=()                 闸=no
  [ 6] kind='clarification'  source_tier='llm' ...                                 agg='None'    dims=('wastage_type',)  闸=YES
  [ 7]..[12] answer, dims=()

  kind 分布: {'answer': 11, 'clarification': 1}    source_tier: {'llm': 12}
  spec 字段数 = 43   抖动字段 = ['aggregation', 'dimensions', 'plan_hash']
  🔑 **同一次调用内** spec 全字段相同却 kind 不同的组: 0

### [MOCK_REST] '员工排班情况'
  [ 1]..[ 9],[11],[12] kind='clarification'  dims=('staff',)  闸=YES
  [10]                 kind='answer'         dims=()          闸=no

  kind 分布: {'clarification': 11, 'answer': 1}    source_tier: {'llm': 12}
```

▎**每一次 `clarification` 都伴随 `dimensions` 非空，每一次 `answer` 都伴随 `dimensions` 为空。**
▎闸是确定的；**非确定性在上游一层 —— LLM 编译出的 `dimensions`。**

⚠️ 上一轮报的「三个槽位逐字段相同却翻转」是**我的仪器造的**（两次编译）。

## ② 空 spec —— 成因是 LLM 超时，且它**不会**给出答案

### 成因（原文）

```
[restaurant-intent] T3 LLM parse failed/timed out: [llm_router] All providers
exhausted for review: aistore/DeepSeek-V4-Flash-A: ReadTimeout; tencent/deepseek-v4-flash-20…
```

32 次调用里出现 **3 次**（`全店本月毛利多少` 不带 / `最近30天按日期看毛利` 带 /
`上个月呢` 不带）。

### 「intent 空却给出答案是哪条路径」—— **没有这条路径**

三次空 spec 对应的 `kind` **全部是 `clarification`**：

```
覆盖·全店毛利      '全店本月毛利多少'        kind 不带='clarification'
按钮·最近30天按日期 '最近30天按日期看毛利'    kind 带  ='clarification'
对照·换时间窗      '上个月呢'                kind 不带='clarification'
```

⇒ **它 fail-closed 了，没有回退路径在答。** 原判「照样给出了答案」同样来自
两次独立编译的错配。

## ③ 上下文串 —— 有效分母 13，真串 3/13 = 23%

### 有效率：**16/16 = 100%**（清缓存之前是 2/18 = 11%）

### 逐条（阳性对照即最后三条：它们**应当**继承）

```
[MOCK_REST] 自足·本月订单 '本月订单数多少'            两侧 llm ✅
    store_scope    'all' → 'single'                                    🔴 串
[MOCK_REST] 自足·最近30天损耗 '全部门店最近30天报损情况严不严重'  两侧 llm ✅
    dimensions     () → ('wastage_type',)                              🔴 串
[MOCK_REST] 覆盖·全部门店毛利 '全部门店的毛利是多少'    两侧 llm ✅
    date_range     ('2026-07-17','2026-08-15') → ('2026-08-01','2026-08-15')  🔴 串
    window_label   '最近30天' → '本月'                                  🔴 串
[MOCK_REST] 覆盖·全店毛利 '全店本月毛利多少'          ⛔ 不带那侧是空 spec(LLM 超时) → 不计
[MOCK_REST] 按钮·最近30天按日期 '最近30天按日期看毛利' ⛔ 带那侧是空 spec(LLM 超时) → 不计

—— 阳性对照（差异**能**在「问句省略了什么」里找到解释，⛔ 不算串）——
[MOCK_REST] 对照·换时间窗 '上个月呢'
    store_scope None→'single' / metrics ()→(...)  ✅ 槽位原本为空，继承是补全
[MOCK_REST] 对照·换指标 '那毛利呢'
    date_range / window_label 变化                ✅ 问句含指代（呢）
[MOCK_REST] 对照·指代菜 '罗氏虾呢'
    四个槽位变化                                   ✅ 同上
```

### 🔑 阳性对照二：那几个槽位**自己会不会抖**（不带 history 跑 8 次）

单次 A/B 判「串」默认了「不带 history 那侧是确定的」。⛔ 那个默认要验。

```
[MOCK_REST] '本月订单数多少'              store_scope: {'all': 8}                    抖动 0/8 ✅
[MOCK_REST] '全部门店最近30天报损情况严不严重' dimensions: {'()': 8}                    抖动 0/8 ✅
[MOCK_REST] '全部门店的毛利是多少'          date_range/window_label 各 {..: 6}         抖动 0/6 ✅（2/8 是空 spec）
[MOCK_REST] '全店本月毛利多少'             store_scope/dimensions/metrics 各 {..: 8}  抖动 0/8 ✅
[MOCK_REST] '最近30天按日期看毛利'          store_scope/dimensions/metrics 各 {..: 8}  抖动 0/8 ✅
```

⇒ 三条真串的槽位在无 history 时**稳定**，差异**可以**归因给 history。

⚠️ 唯一的保留：`报损` 的 `dimensions` 在 ① 的 12 次里抖过 **1 次**，
在这里 8 次全稳。合并 20 次 ⇒ 自发抖动 **1/20**。
所以那一条的归因**不是零风险的**，只是概率上更像 history。

### 分母与结论

```
样本 16 个不同问句  ×  各比一次
减去 空 spec(LLM 超时) 3 次 ⇒ 有效分母 13
真串 3  ⇒  3/13 = 23%
```

⛔ 硬停止三（有效样本里 ≥ 8/10）**不触发**。

## ④ 总发生率 —— 按方向分报，⛔ 不合成一个数

| 方向 | 含义 | 实测 |
|---|---|---|
| **危险侧** | 该反问却直答（照着做会出错） | `员工排班情况` **1/12 = 8.3%** |
| **保守侧** | 该答却反问（只是烦） | `全部门店最近30天报损情况严不严重` **1/12**（无 history）＋ **1/1**（带 history 时） |
| **上下文串** | 槽位被上一轮污染 | **3/13 = 23%** |

⛔ 硬停止二（危险侧 ≥ 3/10）**不触发**（1/12）。

⚠️ **我的自动方向分类第一版是错的**：它把 `上个月呢` / `罗氏虾呢` 标成危险侧
（不带 history 反问、带 history 直答）。那两条是**阳性对照**，那个变化正是
**正确行为**。上表已按人工判读修正。
