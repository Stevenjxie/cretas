# 不支持的指标要给「最接近的替代」——「接近」这件事从哪来

**日期**：2026-08-18　**缺口清单**：第 21 项　**架构定稿**：例 17
**PR**：见文末

---

## 一句话

「翻台率算不了」后面缺一句「眼下最接近的是订单数」。
难点不在补那句话，**在于「接近」这个判断的出处** ——
它一旦写错，产物就是一条发给老板的、他照着去问会一无所获的提示。

---

## 📏 改之前的原文（prod 实测，MOCK_REST，2026-08-18）

```
**翻台率（缺少桌台、开台/结账时间、就餐轮次和可用桌数）现在算不出来。**

缺的是：翻台率（缺少桌台、开台/结账时间、就餐轮次和可用桌数）

我这儿有的是：营收和折扣（比如营收）、成本和毛利（比如食材成本）、
              损耗（比如损耗成本）、客流和销量（比如销量）。

想看哪一样，直接说它的名字就行（例如「营收」）。
```

交付定义第 5 条的三件事都在（缺什么 / 我有什么 / 他要干什么），
**「最接近的替代」不在**。

---

## 三个选项

### 选项 A：手写一张「翻台率 → 每小时订单数」的映射表

**代价**：这正是本文件所在这条路上**刚被换掉的东西**。
`capability_answer.py` 顶部记着那次事故：硬编码的「现在能算的：X」
恰恰在 X 与问句无关时才出现。手写映射的坏法是**沉默的** ——
指标改名、下线、这个租户没数据，表都不会红，只会继续推荐。

⛔ 否决。owner 已明确「⛔ 不写手工映射表」。

### 选项 B：同一大类里挑一个（复用 `computable_categories`）

「翻台率」归到「客流和销量」，锚点是该类里本租户数据最全的那个（实测是「销量」）。

**代价**：**同类 ≠ 接近**。销量与退菜率同属「客流和销量」，
而销量跟退菜一个字都不沾。而且锚点是按**填充量**挑的 ——
填充量不预测「跟他问的那件事像不像」。
更根本的问题：`CATEGORIES` 只有 4 类且全在 POS/损耗域，
「顾客评价」「工序瓶颈」根本落不进任何一类，
硬塞就会给出一个解释不通的替代。

⛔ 否决。它的错法是**看起来总有答案**，而那正是误发提示的形状。

### 选项 C（选中）：声明「这个量在它自己的定义式里由哪几个已登记指标构成」

```
净利润 = 营收 − 食材成本 − 人工/房租/水电 − 税费…   已登记的那一段 = 毛利
翻台率 = 就餐轮次 ÷ 可用桌数                        已登记的那一侧 = 订单数
退菜率 = 退菜量 ÷ 销量                              已登记的那一侧 = 退菜量
顾客评价 / 制作时长 / 出餐时长 / 工序瓶颈           一项都没有 ⇒ 不给替代
```

**为什么它不是选项 A 换个名字**：

| | 手写联想表 | 构成关系声明 |
|---|---|---|
| 写错了会怎样 | 什么都不会发生 | 值必须是 `METRICS`/`DERIVED` 上真实存在的 key，改名当场红 |
| 漏一项会怎样 | 静默不提示 | 键集合与 `_UNSUPPORTED_REQUIREMENT_LABELS` 逐字相等，漏了当场红 |
| 它声称什么 | **「这个能算」** | **什么都不声称** —— 能不能算由查库回答 |

最后一行是承重的。**这张表不声称任何东西能算。**
「能不能给出去」全部由 `capability_answer.computable_metric_keys` 回答：
registry ∩ schema ∩ **本租户每一个所需列的非空值** —— 与「我这儿有的是」
同一次查库、同一份 counts，⛔ 不可能出现「一段说能算、另一段说不能」。

它与登记表里既有的两个构造同形：`Derived(left, right)`、
`Metric.derive_from=(左, 右, 运算)`。⚠️ 之所以住在 `restaurant_intent.py`
而不是 `metric_registry.py`，只是因为本轮不许碰后者（另一条线在改）；
**登记表才是它该去的地方**，见「没做完的」。

## 承重的那一条判据

▎排在最前面的那个替代，老板照着去问，**如果答不上来就是一条误发的提示**。

📏 所以去 prod 问了（MOCK_REST，LLM 槽 3/3 有 key，缓存四个全清）：

| 问句 | kind | 长度 | 结论 |
|---|---|---|---|
| 营收（阳性对照） | `answer` | 1291 | 尺子活着 |
| **订单数**（翻台率的替代） | `answer` | 1284 | 首行就是「共 58,518 单」✅ |
| **毛利**（净利润的替代） | `answer` | 1330 | 自带覆盖率 65.0% 与「不等于整店真实盈亏」✅ |
| 翻台率怎么样（阴性对照） | `clarification` | 155 | 两侧都动 ⇒ 不是恒返回同一个 kind |

⚠️ 如实登记一条**不完美**：问「订单数」拿到的是一份经营摘要
（抬头与问「营收」几乎逐字相同，都路由到 SALES_SUMMARY），
订单数在第一行有，但不是一份专讲订单数的读数。
**不是一无所获，也不是正中靶心。** 这一条不阻塞本轮 —— 提示没有撒谎。

## 限定语必须跟着替代一起出去

```
眼下最接近的是毛利（未扣人工、房租、水电）。想看的话，说「毛利」就行。
```

不带限定语地拿毛利顶净利润，就是系统承诺不做的「相邻指标顶替」，
只是换到了**建议**这一侧。限定语取自 `Derived.caveat_short`（登记表字段），
⛔ 不在叙述层手写 —— 手写的话新登记一个同类指标不会自动带上，而漏掉不报错。

## 一个能让判据红的对照

本设计卡的判据是「**替代必须是这个租户实测算得出来的**」。
让它红的做法是**去掉查库那一层**：

```
变异 M3：nearest_alternatives 不再过滤 computable，直接取声明的第一项
观测   ：nearest_alternatives(('table_turnover',), {'revenue','sales_qty'})
         由 ()  变成  (('订单数',''),)          ← 变异确实改变了行为
结果   ：6 条断言红，其中承重的两条是
         test_替代必须是本租户实测算得出来的
         test_同一条调用链上租户没有数据就不给替代
```

⚠️ 另有一条变异（M8 第一版）**没红** —— 复查发现是**变异没打在被守的行为上**
（只往 `available` 里多塞了一个与该声明无关的 key，观测值一个字没变）。
按 C″ 先证明变异生效，重做成「真的加一个同类兜底分支」（M8b）之后，
观测值从 `()` 变成 `(('订单数',''),)`，目标断言当场红。
**不是断言没用，是第一版变异打空了。**

## 「接上没有」怎么钉

调用点在 `restaurant_intent_service.py:1917-1920`，**本轮不许碰**（另一条线在改）。
如果只给 `render_capability_refusal` 加一个 `alternatives=` 参数，
没有任何生产调用点会传它 —— 单测全绿、线上一个字不变，就是形态 B。

做法：让**查库那一步**（`tenant_capability`）把替代一起算好，挂在它
**已经在传**的那个返回值上（`TenantCapability(tuple)`）。
钉住它的是 `test_两行调用点原样接得上` —— 它把调用点那两行原样跑一遍。
变异「让 `tenant_capability` 返回裸 tuple」→ 当场红。

## 没做完的

1. **这张声明该住进 `metric_registry.py`**，和 `Derived`/`derive_from` 放一起，
   由 `assert_registry_self_consistent` 兜住，而不是靠一个测试文件。
   **解冻条件**：改 `metric_registry.py` 的那条线合并之后。
2. **飞轮 B 的能力缺口栏**（例 17 的后半句「频次涨上去就是下一个该开发的」）
   本轮**没做** —— `refusal_queue.py` 已有分类，是否要按「有没有替代」再分一档，
   需要 owner 裁。
3. **「订单数」的答案是摘要不是聚焦读数**（见上表的登记）。
   要让替代落到一个专讲它的读数上，动的是路由不是本轮这一层。
4. **脏租户验收缺席**：📏 实测 `RES_3101_009` / `DEMO_REST` / `R_XMX_CHAIN` /
   `R_GML_DEMO` 在 `smartbi_prod_db` 上 POS 事实表**今天都是 0 行**
   （RLS 策略已核对 = `factory_id = current_setting('app.factory_id')`，
   所以 0 是真的不是被挡的）。
   ⇒ 记忆里那份「脏样本清单」（2026-08-13 写的）**已经过期**。
   本轮的跨租户对照只能是「MOCK_REST 有 / 另外 4 个全空」，
   拿不到「覆盖率 42%」那种中间态。
