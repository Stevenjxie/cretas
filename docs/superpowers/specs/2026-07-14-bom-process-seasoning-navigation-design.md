# BOM 工序调料导航与锅序报工设计

**日期：** 2026-07-14
**状态：** 用户已确认
**范围：** Web Admin BOM/调料配置、BOM seasoning API、逐工序报工；不部署

## 目标

把调料从自由文本维护改成 BOM 版本下的辅料主数据选择，并用“工序导航 + 当前工序调料编辑器”降低页面空白和重复表格。锅序由配置显式开启；报工只填投入总重量和锅数，系统按等重锅自动生成逐锅重量并沿用现有成本公式。

## 已确认业务规则

1. 调料必须从原辅料主数据选择，名称和移动平均价自动带入并保存为 BOM 版本快照。
2. 每条调料绑定该 SKU 的一道 `workProcessId`，用量口径为“每投入 1 kg 本工序半成品所需克数”。
3. 任意工序都可显式开启锅序，不再依赖工序名称或 `processCategory=熟制`。
4. 第一锅按 100%；第二锅及以后都按第一锅的固定百分比，不做逐锅复利递减。
5. 报工只填写投入总重量和锅数。各锅按等重处理：`每锅重量 = 总投入重量 / 锅数`。
6. 总调料量：`每kg用量 × 每锅重量 × [1 + (锅数 - 1) × 后续锅比例]`。
7. 不再展示或编辑“单价1/单价2”；旧字段仅作为兼容存储，成本价格取自动快照值。

## 数据设计

沿用现有 `bom_seasoning_items` 与 `bom_process_seasoning`，避免把动态工序调料重复写进普通 BOM item 并造成双计成本。

- `bom_seasoning_items` 新增 nullable `material_type_id`，关联 `raw_material_types.id`。
- 新写入行必须携带 `materialTypeId`；历史自由文本行允许继续读取，并在 UI 标记“历史数据，需重新选择物料”。
- 保存时后端按 `(factoryId, materialTypeId)` 校验物料，覆盖客户端名称，并将 `movingAvgPrice` 写入 `priceSource1`；`priceSource2` 置空。
- 移动平均价为空时拒绝保存，明确提示先维护采购价格，禁止静默按 0 元计成本。
- `bom_process_seasoning.subsequent_pot_ratio != null` 表示该工序启用锅序；null 表示关闭。比例范围 0～1。
- 克隆 BOM 版本时复制 `materialTypeId` 和价格快照，保证历史成本稳定。

## 配置端 UI

调料页仍挂在 BOM 统一模块中，但内容重构为双栏：

- 左栏：按 SKU 工序顺序展示工序名称、类别、调料条数、锅序状态；点击只切换当前编辑工序。
- 右栏：显示当前工序上下文、调料列表、添加调料按钮、锅序开关和后续锅百分比。
- 添加调料后，行内使用可搜索下拉，只展示物料主数据中的“辅料/调料”；选择后自动显示单位和移动平均价。
- 用量字段文案为“每 1 kg 本工序投入用量（g）”。
- 锅序开关开启后才显示“后续锅占第一锅”，按百分比录入；关闭时清空 ratio。
- 页面使用紧凑卡片、状态色和明确空状态，不再为每道工序渲染大面积空表格。

## 报工端

- `ProcessSheet` 加载当前产品 BOM seasoning 参数，按 `workProcessId` 给每道工序传入 `seasoningPotEnabled`。
- `ProcessDataTable` 的锅数显示判据改为显式配置；兼容旧 `shuzhi/熟制` 仅用于读取历史已保存行，不驱动新配置。
- 操作员填写锅数后不再逐锅录入重量。
- 保存前用最终 `inputQuantity` 等分生成 `potRawKgs`，继续满足后端现有请求契约与成本计算器。
- 卡片和表格都显示“系统按总投入等分，每锅约 X kg”的只读预览。

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

- 生产管理员：熟悉产品和工序，但不应判断内部价格字段或重复维护名称。
- 一线报工操作员：低技术门槛，只应填写现场知道的总投入重量和锅数。

### 用户旅程

管理员选择产品 → 左栏选择工序 → 从辅料档案添加调料 → 填每 kg 投入用量 → 可选开启锅序并填后续锅百分比 → 保存/激活 BOM → 操作员进入对应工序报工 → 填总投入和锅数 → 查看自动均分提示 → 保存。

### 摩擦点

- 每道工序一个大空表造成视觉稀疏，定位慢。
- 调料名称、两个价格字段均手填，容易拼写错误或成本口径不明。
- 锅序依赖“熟制”分类或名字，真实工序类别为“加工”时字段消失。
- 逐锅重量重复填写，现场负担大且总和容易不等于投入量。

### 设计响应

- 工序导航一次只编辑一道工序，并展示完成状态。
- 自由文本改为主数据下拉，价格由后端权威带入。
- 锅序由显式开关决定，配置与报工使用同一个 `workProcessId`。
- 报工自动等分锅重，提交前展示计算边界；输入不完整时按钮禁用并给出具体下一步。

## 错误与兼容

- 物料不存在、跨工厂、不活跃或缺移动均价：保存返回明确业务错误和处理提示。
- 历史无 `materialTypeId` 行不静默丢失；只读版本可查看，克隆后必须重新选物料才能保存。
- seasoning API 404（产品无 BOM）继续走现有创建 BOM 引导。
- 报工加载 seasoning 失败时不猜测锅序配置，显示可重试错误，避免漏算调料。

## 验收

1. 调料行只能从辅料/调料主数据选择，自动价格可回显，保存重载不丢失关联。
2. 左侧工序导航切换后，右侧只显示当前工序，状态计数正确。
3. 任意类别工序开启锅序后，报工出现锅数；关闭后不出现。
4. 300 kg、3 锅、10 g/kg、后续 50% 时生成 `[100,100,100]` kg，调料量为 2000 g。
5. 报工不再出现逐锅重量输入框。
6. 后端与前端针对性测试、Web Admin 类型检查/构建通过后合并并推送 `main`，不部署。
