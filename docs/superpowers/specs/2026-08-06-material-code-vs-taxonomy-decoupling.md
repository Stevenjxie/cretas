# 物料编码与分类树解耦（第三层，规划中，未实施）

**日期**: 2026-08-06
**状态**: 📋 规划 —— 不要照着这份实施，先看「触发条件」一节判断该不该做
**起因**: 六膳门 L3 分类建不出来（PR#2329/#2330/#2332），修完症状后回看根因

---

## 一句话

现在的 16 位物料编码是 **smart key**：编码本身编码了分类路径。分类树一变，编码就该变；
而编码被历史物料引用不能变 —— 这是个死结。客户每重组一次分类，就必然烧掉一批编码、
留下一批"指向已删分类"的物料。

---

## 现状（事实，2026-08-06 prod 实测）

```
物料编码 0010010115000001
         └──┬───┘└┬┘└──┬─┘
        L1+L2+L3  │   6 位流水
        (10 位)   └── L3 的后 4 位
```

- `material_code_segments`：L1(3) → L2(+3) → L3(+4)，cumulative
- `uk_mcs_factory_segment (factory_id, segment_code)` **不排除软删除**
  —— 也不能排除：`material_business_code_prefixes` 有外键指向该编码
- 所以**编码一旦发出就永久烧掉**，删除分类不回收编码

### 三个直接后果

1. **重组分类必然烧号**。六膳门 08-04 一次性软删 226 个 L3 + 2 个 L2，
   那 228 个编码永久占用；08-06 重建时撞码，且报错被翻译成「重名」。
2. **分类无法移动**。`validateHierarchy` 要求 `code.startsWith(parentCode)`，
   换父级就要换编码，而编码不能换 → 「把某个 L3 挪到另一个 L2」做不到。
3. **物料的分类归属建完就看不见了**。`material-types/list.vue` 的级联注释写着
   `cascade is create-only` —— 编辑物料时 L1/L2/L3 一律清空，列表也没有分类列。
   分类只在**建物料那一刻**用一次，之后只剩编码前缀。
   ⚠️ 这也是删分类**当场没有任何症状**的原因：没有反馈回路阻止这个动作。
   prod 实测：14 个带 16 位码的在用物料里，**11 个的 L3 分类已被软删**。

---

## 目标形态

把「编码」与「分类归属」拆成两件事：

| | 现在 | 解耦后 |
|---|---|---|
| 物料编码 | 含分类路径，分类变则语义漂移 | **稳定不变**（流水号或业务码），永不因分类调整而变 |
| 分类归属 | 隐含在编码前缀里，只读一次 | `raw_material_types.segment_id` 外键指向分类表主键，**可改** |
| 分段码展示 | 编码里切片得到 | 由分类**现算**（跟着分类树走，改分类立即反映） |
| 重组分类 | 烧号 + 断链 | 改外键即可，编码一个不动 |
| 移动分类 | 做不到 | 改 `parent_id`，子孙的展示码自动重算 |

关键点：**分类表用 surrogate id 做关系，`segment_code` 降级为展示属性**。

---

## 迁移路径（若实施）

1. `raw_material_types` 加 `segment_id`（可空），按现有 `substring(code,1,10)` 回填 —— 已删分类也能回填，
   因为行还在（这正是恢复入口存在的价值）
2. 新代码只写 `segment_id`；`code` 保持不变，继续作为对外编码
3. 分类展示改为按 `segment_id` join 现算，不再切 code
4. 待所有读路径迁完，`code` 的前 10 位退化为"历史巧合"，不再有语义
5. `material_business_code_prefixes` 的外键改指 `segment_id`

⚠️ 不需要、也不应该改写任何已发出的物料编码。客户单据、条码、外部系统都在用它。

---

## 触发条件（该不该做）

**做**，如果出现任一：
- 客户还会再重组分类（08-04 那种整层删除）一次以上
- 需要「把某个 L3 挪到另一个 L2」
- 要做跨工厂共享分类（现在 `segment_code` 是 per-factory 的）
- 分类归属需要成为可查询/可改的物料属性（比如按分类做成本归集、采购分析）

**不做**，如果：
- 分类这次重组完就定型
- 没人问过「为什么改不了某个物料的分类」

代价参考：改 `raw_material_types` 表结构 + 回填 + 所有读分类的路径（BOM 选料器、
采购下拉、16 位编码生成器、物料档案页）。不是小活。

## 已做的两层（不在本 spec 范围）

- **第一层**（PR 见 2026-08-06）：删除守卫（有在用物料/有下级 → 拒绝并指向「停用」）、
  「显示已删除 + 恢复」入口、一键停用
- **第二层**（同上）：改名说明「不动编码、不影响历史物料」；上级下拉在编辑态禁用并说明
  「分类建好后不能换上级」

这两层把「用删除做重组」这条路径掐掉了，第三层解决的是「为什么重组这么贵」。
