## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像
**仓管员 / 操作员**（warehouse_worker / yield_operator）— **年纪偏大、文化素质低**（客户张权原话：「做仓管的他年纪都比较大文化素质很低，你不能太依赖他们」）— 手机端领料、报工、收货入库；怕看错数字、怕多步骤、怕报错看不懂。

### 用户旅程

**Lane A — 领料（双领 + 扫码 + 厂号选）**
| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|------|---------|---------|---------|
| 1 | 任务卡「化冻 — 掌中宝(SO-…)」+「领料」大按钮 | 点领料 | 进领料 picker |
| 2 | 需领清单：原料 + 半成品**分区显示**，各带「品名/批次/厂号/可用量」 | 浏览 | 一眼看清要领什么 |
| 3 | 每行「扫码选批」按钮 或 手动选 | 扫码 | 扫码后**立即回显品名+批次+厂号+数量**，目视确认 |
| 4 | 同品多厂号时，**按厂号分组/筛选** | 选实际用的厂号 | 锁定正确批次（不同厂号=不同批次） |
| 5 | 填实领量（大字号数字键盘，带 max=可用量） | 输入 | 超量 disabled，防超领 |
| 6 | 「确定领料」唯一主按钮 | 点确定 | 反馈成功 + 回任务 |

**Lane B — 开工缺料预警**
| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|------|---------|---------|---------|
| 1 | 待生产任务列表，缺料任务**红/橙标 + ⚠缺料 badge** | 浏览 | 一眼看出哪个缺料 |
| 2 | 点任务 → 缺料明细（品名/需求量/库存量/缺口） | 查看 | 知道缺什么、缺多少 |
| 3 | **不阻断开工**（N1 无条件化），仅预警 | 可继续开工 | 缺料可见但不卡流程 |

**Lane C — 标签打印**
| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|------|---------|---------|---------|
| 1 | 入库/领料完成后「打印标签」按钮 | 点打印 | 蓝牙热敏打印批次标签（品名/批次/厂号/数量/二维码） |
| 2 | 打印中 ActivityIndicator | 等待 | 打印成功反馈；失败给重试 |

### 摩擦点清单
| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|-----------|---------|---------|
| F1 | 原料/半成品混在一个列表，仓管分不清要领哪类 | HIGH | 内联 UX·信息密度 |
| F2 | 同品多厂号时手动找批次易选错（不同厂号≠同物） | HIGH | fool-proof Rule 2 + 扫码/批次选择 |
| F3 | 扫码后不回显，操作员不确定扫对没 | HIGH | 内联 UX·扫码 |
| F4 | 实领量无 max，超领不报错（库存负数） | HIGH | fool-proof Rule 1 |
| F5 | 缺料看不见，开工后才发现料不够 | HIGH | fool-proof Rule 2 + Rule 5 |
| F6 | 标签靠 web 打，仓管手机现场打不了 | MED | 转录一物一码诉求 |
| F7 | 数字输入小字号，仓管看错 | MED | 内联 UX·信息密度 |
| F8 | 打印失败黑屏/无反馈 | MED | 内联 UX·错误恢复 |
| F9 | 触摸目标小、误触 | MED | 内联 UX·触摸目标 |
| F10 | 已报哨兵工序仍显示，操作员重复点困惑 | MED | fool-proof Rule 5（#837） |

### 每个摩擦点的设计回应
- **F1** → 领料 picker **原料区 / 半成品区分节渲染**（section header），各区独立列表（N2 双领）。
- **F2** → 同品多厂号**按厂号分组**，每卡带「品名 + 批次号 + 厂号 + 当前工序」（Rule 2）；选厂号后才出对应批次。
- **F3** → 扫码结果**立即回显** 品名+批次+厂号+可用量，操作员目视确认后才允许加入领料（内联 UX·扫码）；单批次自动选不多点。
- **F4** → 实领量 `TextInput keyboardType="numeric"` 带 `max=可用量`，超量「确定」disabled + 提示「最多可领 X」（Rule 1）。
- **F5** → 缺料任务列表红/橙 + ⚠缺料 badge；点进看缺口明细；**不阻断**开工（Rule 5：可见但不 dead-end）。
- **F6** → 入库/领料完成屏加「打印标签」`TouchableRipple` 大按钮，蓝牙热敏打印（品名/批次/厂号/数量/二维码）。
- **F7** → 数字输入 ≥24px 大字号。
- **F8** → 打印失败双句式错误「打印机没连上 + 请检查蓝牙后重试」+ 重试按钮，不黑屏（内联 UX·错误恢复）。
- **F9** → 所有可点元素用 Paper `TouchableRipple`/`Button` ≥44×44pt，间距≥8px，ripple 反馈。
- **F10** → #837：已报哨兵工序从任务列表**过滤隐藏**，不让操作员重复点。

## 实现要点（各 lane）

### Lane A — 领料 picker overhaul（`MaterialBatchPicker.tsx` + `YieldStepReportScreen.tsx`）
- 原料/半成品分节（N2 双领：一次领料同时领原料 + WIP，各填实际量）。
- 扫码选批：扫码→回显→确认→加入；复用现有 `materialLabelApiClient.scanMaterialBatchLabel`。
- 厂号筛选：同品多厂号分组/筛选，卡片带厂号（#901 已存 `factoryNumber` on batch）。
- max 防超领 + 大字号数字 + TouchableRipple。
- ⚠ RN hooks 铁律：所有 hook 在早返回前（避免 #618 类崩溃）；避免 TDZ（分支移到 const 后，#725 教训）。
- ⚠ Alert 用项目 `appAlert`（非 `Alert.alert`，#509 教训：RN web Alert 不可见）。

### Lane B — 缺料预警屏（新屏 + OperatorNavigator）
- 复用后端缺料/库存数据（N1 已有缺料判断）。
- 新屏注册进 OperatorNavigator；任务列表 badge。
- 不阻断开工（呼应 N1 无条件化）。

### Lane C — 标签打印（新 print 组件）
- 蓝牙热敏打印（调研现有 RN 蓝牙能力 / expo-print 或第三方）。
- 标签内容：品名/批次/厂号/数量/二维码（复用一物一码 label 数据）。
- 失败重试，不黑屏。

### fix #837 — 隐藏已报哨兵工序
- ProcessTask 列表过滤掉已报（reported）的哨兵工序，防重复点。

## 验收（各 lane）
- RN `tsc`/type-check 绿；**真机或 headed Expo Web 跑**（build✓≠跑通，#723/724/725 教训：极致案例真机验）。
- Lane A：双领分区渲染 + 扫码回显 + 厂号筛选 + max 防超领 截图。
- Lane B：缺料 badge + 缺口明细 + 不阻断开工。
- Lane C：打印按钮 + 失败重试。
- fool-proof 四位一体 + 触摸目标 + 大字号数字。
- OTA 推送后设备冷启 2 次拉取验证。
