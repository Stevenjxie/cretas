# 餐饮问答路由：A+B 混合漏斗的完整形状与空挡

**日期**: 2026-08-07
**前置**: `2026-07-07-restaurant-intent-tiered-routing-design.md`（分层路由原始设计）
**本篇增量**: 用当天 prod 实测数据把「确定性优先 vs LLM 优先」两种架构合成一条自演进
漏斗，并**逐条列出它处理不了的空挡与各自的兜底出口**。

---

## 0. 一句话

**A（LLM 先理解）负责覆盖面，B（确定性先试）负责成本，飞轮把 A 的产出沉淀成 B。**
两者不是二选一——它们是同一条链的不同位置，而且这条链会自己变便宜。

判据：**只有可证伪的证据才能授权执行。** 相似度不可证伪，所以向量永不授权。

---

## 1. 漏斗全景

```
用户问句
   │
   ├─[前置] 已知数据缺口判定 ──────────────► B 类诚实答案   0 token / 43ms
   │        (真查表; 有行/查不动则放行)
   │
   ├─ L0 整句精确匹配 ────────────────────► 授权执行       0 token / 32-360ms
   │     _APPROVED_EXACT_ROUTES(代码, 极小)
   │     ai_promoted_routes(表, 人审晋升, 可撤销)
   │     槽位: 时间(6 闭集) × 全部门店 × 任意顺序 ⇒ 一条 ≈ 50 种说法
   │
   ├─ L1 结构解析 ★待建 ──────────────────► 授权执行       0 token
   │     闭集: 指标(13) / 时间(6) / 动作(4)
   │     开集: 菜品·门店·食材·供应商 → **对着租户目录校验**
   │     ⛔ 歧义即拒, 不许挑一个
   │
   ├─ L2 向量检索 ────────────────────────► **不授权**, 只召回相似例子喂 L3
   │     用途二: `--misses` 覆盖率仪表(像但没命中 = 该加模板的信号)
   │
   └─ L3 LLM planner ────────────────────► 授权执行       ~3.2k token / 3-10s
         产出 RestaurantQuerySpec(意图+槽位, 不可变, 带 plan_hash)
                    │
                    ▼
         确定性执行: resolver → SQL → 模板成文
                    │
                    ▼
         答案契约校验 ── 不过 ──► fail-closed 反问(绝不改走相邻指标)
                    │
                    ▼
         捕获日志 → 飞轮候选 → **人审 --apply** → 回灌 L0
```

**关键闭环**：L3 每答对一次，就产生一条候选；人审晋升后它变成 L0，下次 0 token。
系统用得越多越便宜——这是 A+B 合体的全部意义。

## 2. 各层的证据类型（为什么只有某些层能授权）

| 层 | 证据 | 能否被反驳 | 授权 |
|---|---|---|---|
| 缺口前置 | 「该表 0 行」——查得到 | ✅ | ✅ |
| L0 | 「归一化后字符串相等」 | ✅ | ✅ |
| L1 | 「『罗氏虾』在 dim_product 里」 | ✅ | ✅ |
| L2 | 「余弦相似度 0.93」 | ❌ | **永不** |
| L3 | 模型判断 + 答案契约兜底 | 部分 | ✅ |

### 向量为什么在这个域特别危险

分析类问句的区分点常常只有一两个字，而向量对短差异不敏感：

| 一对问句 | 向量距离 | 实际含义 |
|---|---|---|
| 哪个店营业额**最高** / **最低** | 极近 | 完全相反 |
| 毛利**率** / 毛利**额** | 极近 | 比率 vs 金额 |
| 损耗最高的**食材** / **门店** | 极近 | 不同 resolver |

⇒ 「相似度 0.95」在这里不构成「是同一个问题」的证据。

## 3. 真实案例走位（全部取自 2026-08-07 prod 实测 / 飞轮候选表）

| # | 问句 | 走哪层 | 实测 |
|---|---|---|---|
| 1 | `最近损耗情况怎么样` | L0（今日晋升） | **32ms / 0 token** |
| 2 | `明天天气怎么样` | L0 → OUT_OF_DOMAIN | **22ms / 0 token** |
| 3 | `哪个供应商报价最贵` | 缺口前置 → B | **43ms / 0 token**，4 轮稳定 |
| 4 | `全部门店最近30天哪个菜卖得最好` | L0（槽位组合，未单独晋升） | 0 token |
| 5 | `加权毛利率是多少` | **L1 目录否决「加权」** → 全店毛利 | 现状靠黑名单；L1 建成后自动 |
| 6 | `本月鲜行者打浦桥日月光店的营业额呢？` | **L1**（门店目录+指标闭集+时间闭集） | 今天要 3.2k token；L1 建成后 0 |
| 7 | `这两个月生意咋样，挣着钱没` | L2 找例子 → L3 | ~3.2k token，之后进候选 |
| 8 | `把这个策划案预算改成5000` | **不进漏斗**（编辑类） | 见 §5 |

案例 6 是 L1 的主要价值来源：飞轮候选表里 196 条真实客户提问，**大量是同一形状换槽位**
（「最近7天全部门店招牌青花椒味(单人份)的单份成本是多少？」「上个月…」），
L0 需要**每道菜一条**，L1 只要**一个模板**。

## 4. 空挡清单（处理不了的，及各自兜底出口）

⚠️ **每个空挡都必须有明确落点。没有落点的空挡 = 系统会悄悄猜。**

| # | 空挡 | 为什么处理不了 | 兜底出口 | 状态 |
|---|---|---|---|---|
| G1 | **跨类槽位歧义**：「青花椒」既是菜名子串（招牌青花椒味）又是门店名子串（青花椒南方百联店） | L1 的证据同时支持两种解释 | **歧义即拒 → 落 L3**（`_exact_shape_matches` 已是此语义：ambiguous never authorizes） | ✅ 已有 |
| G2 | **指代 / 上轮延续**：「那家店呢」「换成上个月」（候选表真实存在） | 依赖上一轮状态，L0/L1 是无状态的 | 澄清延续（Postgres 单次消费）+ trusted context repair | ✅ 已有 |
| G3 | **复合多意图**：「昨天的营业额是高于前天还是低于前天？」 | SALES_SUMMARY 与 TREND_ANALYSIS 都合理 | 飞轮标 `冲突` **拒绝晋升** → 永远走 L3 | ✅ 已有 |
| G4 | **自由文本实体**：活动主题、备注、策划案正文 | 无目录可校验；用词表猜自由文本正是黑名单的来源 | **禁止进确定性层**，只走 L3 | ✅ 设计约束 |
| G5 | **数据本身口径矛盾**：折扣（`has_discount`=0 单 vs `discount_amount`=¥369 万） | 不是路由问题，是数据问题 | **第三态「判不了」**（`skippedRules`），两个数都说出来，不选边 | ❌ **未实施** |
| G6 | **新菜/新门店上线但目录未同步** | L1 会判「不是菜」→ 静默降级为全店口径 | fail-open **且必须披露**（「未在菜单中找到 X，已按全店口径回答」） | ❌ **未实施** |
| G7 | **晋升冻结了「选哪个 resolver」** | 晋升行不再问 planner；resolver 换了它不知道 | 退役 resolver 会被 `_VALID_CODES` 过滤（静默回落 L3）；但**换 resolver** 无防护 | ⚠️ 半有 |
| G8 | **晋升后无回归验证** | 没有任何东西回放晋升表检查答案仍正确 | 需要一条回放闸 | ❌ **未实施** |

### G7 的真实案例（今天就发生了）

`哪个时段生意最好` 在今天之前被路由到**排班** resolver（它正确地拒答历史问题）。
**如果当时晋升了，现在还会钉在错的 resolver 上**——因为晋升行永远不再问 LLM。

⇒ 判据：**算法变了会自动跟上（resolver 内部改口径没问题），该换 resolver 了它不知道。**
这是晋升的固有代价，只能靠 G8 的回归闸兜。

## 5. 查询 vs 编辑：两条路，别混

| | 查询 | 编辑（策划案精修等） |
|---|---|---|
| 例子 | 「本月营收多少」 | 「把预算改成 5000，其他不变」 |
| 走漏斗 | ✅ | ❌ 必须保多轮上下文 |
| 能省 token | ✅ 命中确定性层即 0 | ❌ 省不掉 |
| 正确性怎么保 | LLM 不碰数字 | **同样是 LLM 不碰数字** |

编辑场景省不掉 LLM 调用，但仍可让 LLM **不承担正确性**：④ 行动建议就是这么做的——
事实全部来自发现层，LLM 只排序和措辞，越界由 `GroundedNumberValidator` 拒整次生成。

## 6. 实施顺序（按依赖）

1. **G8 回归闸**（半小时，纯收益、无争议）
   回放 `ai_promoted_routes` 全部短语，断言仍产出答案而非反问。不做这个，后面全是裸奔。
2. **目录作用域覆盖**（治本）
   `dish_catalogue_scope` 目前只包住 `parse_restaurant_query`，部分抽取路径在作用域外
   跑、目录没加载 → fail-open → 退回黑名单。覆盖后「加权/环比/综合/同比毛利率」
   这一类**全部自动拦住**，黑名单可开始退役。
   同时实施 **G6 披露**。
3. **L1 结构解析**（闭集槽位 + 目录校验 + 歧义即拒）
4. **模板化晋升**（拿真实候选批量验证后晋升；前三步没做完不要开始）
5. **G5 折扣三态**（需先拍板以哪个口径为准）

## 7. 反向判据（写给未来的自己）

- 「相似度够高就直接答」——**不行**，见 §2 的三对问句。
- 「候选表 185 条推荐晋升，批量晋升省事」——**不行**，错的计划会被 0-LLM **永久回放**，
  比答错一次严重得多。2026-08-07 只晋升了亲验过的 9 条。
- 「D 太多不好看，把反问的问句也晋升掉」——**不行**，那是把反问固化成永久行为。
- 「黑名单再加个词就好了」——那是在作者已经指出不够用的路上再打补丁
  （代码原文：「黑名单只能拦住有人想到过的词，目录能拦住全部」）。
