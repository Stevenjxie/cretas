# BOM 工序优先调料配置重构设计

**日期：** 2026-07-14  
**状态：** 交互方案已确认，待书面规格审阅  
**分支：** `codex/process-seasoning-bom-redesign`  
**范围：** Web Admin BOM / 配方管理、版本化工序调料绑定、调料汇总；沿用既有锅序报工语义，不部署

## 1. 背景与目标

现有页面把普通 BOM 辅料和按工序调料拆成两个入口：

- “原辅料配方”里的辅料按成品单位维护，没有工序上下文；
- 独立“调料配方”Tab 按工序维护 `g/kg`、锅序和成本快照。

这造成同一业务存在两套入口、两种用量口径和潜在的双重计成本。重构后的核心心智模型是：

> SKU 的 workflow 包含多个工序；每道工序绑定零到多种调料。同一种调料可以绑定多个工序，每条绑定拥有独立的投入量和锅序规则。

目标：

1. 删除独立“调料配方”顶层 Tab，把调料配置收进“原辅料配方 > 辅料”。
2. 以工序为主要配置入口，用户先定位工序，再添加调料。
3. 提供按物料去重的“辅料汇总”视图，方便采购和成本核对。
4. 新配置只写版本化工序调料模型，避免与普通 BOM 辅料行重复计成本。
5. 保留已确认的锅序规则：第一锅 100%，第二锅及以后均按第一锅固定比例投入。

## 2. 已确认业务规则

### 2.1 关系与唯一性

- 主关系为 `BOM 配方版本 × 工序 × 调料`。
- 同一调料可以绑定多个工序。
- 同一配方版本、同一工序、同一调料只能存在一条有效绑定。
- 每条绑定独立保存：
  - `workProcessId`
  - `materialTypeId`
  - 每 1 kg 本工序半成品投入克数
  - 是否按锅序计算
  - 后续锅相对第一锅的固定百分比
  - 是否计入调料成本
  - 自动价格快照

### 2.2 用量与锅序

- 用量字段固定表达为“每 1 kg 本工序半成品投入量”，页面单位显示为 `g/kg`。
- 不把该值解释为“每份成品用量”，也不与普通 BOM 行的 `standardQuantity` 混用。
- 开启锅序后：
  - 第一锅固定为 100%，只读；
  - 第二锅及以后均使用同一个后续锅百分比；
  - 不做逐锅复利衰减。
- 示例：本工序投入 300 kg、3 锅、10 g/kg、后续锅 50%，每锅等重 100 kg，总调料量为 `100 × 10 × (100% + 50% + 50%) = 2000 g`。

### 2.3 价格和成本

- 调料必须从本厂有效的辅料/调料物料主数据中选择，不允许手填名称。
- 单价从移动平均价自动带入并保存为 BOM 版本快照，不显示“单价1 / 单价2”。
- 缺少有效价格时禁止激活或保存为可用于成本核算的绑定，并提供“去维护价格”的明确出口。
- 辅料汇总中的“理论成本贡献”只有在工序转换率、出成率和价格数据完整时才显示数值；数据不完整时显示“待计算”，不得静默显示 0。

## 3. 信息架构

### 3.1 顶层导航

`BOM / 配方管理` 仅保留：

- 原辅料配方
- 转换率

删除独立“调料配方”Tab。原有调料页面能力迁入“原辅料配方 > 辅料”。

### 3.2 原辅料分类

“原辅料需求明细表”继续保留：

- 原料
- 辅料
- 包材

其中“辅料”页提供两个视图：

- **工序编排：** 默认视图，用于新增、编辑、删除工序调料绑定。
- **辅料汇总：** 核对视图，按物料去重汇总跨工序使用情况。

原有通用“添加原辅料”弹窗不再允许通过 `AUXILIARY` 创建无工序的新调料行；原料和包材流程保持不变。

## 4. 工序编排视图

### 4.1 页面骨架

- workflow 工序按生产顺序纵向显示为折叠卡片。
- 卡片头展示：顺序号、工序名称、调料数量、配置状态和“添加调料”。
- 默认只展开当前操作工序；用户可以切换或手动展开其他工序。
- 无调料工序允许保持为空，不阻断 BOM 保存或激活。
- 右侧固定显示紧凑“辅料汇总”面板，按物料去重显示“用于 N 个工序”。

### 4.2 工序卡片内容

展开后显示该工序的调料绑定表：

| 字段 | 含义 |
|---|---|
| 调料 | 物料编码 + 名称 |
| 每 1 kg 本工序投入量 | `dosagePerKgG`，显示为 `g/kg` |
| 锅序 | 不按锅序 / 首锅 100% · 后续 N% |
| 自动单价 | BOM 版本价格快照 |
| 计入成本 | 明确状态，不使用模糊开关文案 |
| 操作 | 编辑、删除 |

同一调料若还用于其他工序，在行内显示轻量提示，例如“另用于 3. 炸水”；该提示只用于导航，不合并本工序的用量。

### 4.3 添加调料

点击某工序卡片中的“添加调料”后，表单上下文锁定为该工序：

1. 从物料主数据下拉选择调料；
2. 填写每 1 kg 本工序投入克数；
3. 选择是否按锅序；
4. 若开启锅序，填写后续锅百分比；
5. 查看自动价格和计算示例；
6. 保存到当前工序。

表单不再询问“投入工序”，因为工序已由入口确定。保存按钮使用“保存到本工序”，避免误解为修改整个物料。

### 4.4 状态与版本

- `ACTIVE` BOM 全部只读，页面提示“克隆为新版本后修改”。
- 只有 `DRAFT` BOM 允许新增、编辑和删除绑定。
- 切换产品或版本前若有未保存内容，必须确认离开。
- 保存后同时刷新工序计数、右侧物料汇总和成本摘要。

## 5. 辅料汇总视图

### 5.1 汇总原则

- 每个 `materialTypeId` 只显示一行。
- 不显示一个伪造的“汇总 g/kg”，因为不同工序的计算基数不同。
- 主表字段：辅料名称、物料分类、使用工序数、工序绑定概览、自动单价、理论成本贡献、配置状态、操作。
- “工序绑定概览”以标签展示，例如：
  - `2. 滚揉 5.0000 g/kg`
  - `3. 炸水 1.5000 g/kg`

### 5.2 展开明细

展开物料行后显示“工序投入明细”：

| 工序 | 每 1 kg 本工序投入 | 锅序适用规则 | 成本计入方式 | 操作 |
|---|---:|---|---|---|
| 2. 滚揉（保水） | 5.0000 g | 首锅 100% · 后续 60% | 计入成本 | 定位到工序 |
| 3. 炸水 | 1.5000 g | 不按锅序 | 计入成本 | 定位到工序 |

“定位到工序”会切回工序编排视图并展开目标工序。汇总页不直接新增调料，避免脱离工序上下文创建错误绑定。

### 5.3 搜索与筛选

- 搜索：辅料名称或编码。
- 筛选：全部、多工序使用、锅序调料、配置异常。
- 顶部摘要：`N 种辅料 · M 条工序绑定 · K 项异常`。
- 异常包括：历史无工序辅料、物料失效、价格缺失、工序失效和用量非法。

## 6. 数据与 API 设计

### 6.1 单一事实来源

- 新工序调料配置以 `bom_seasoning_items` 为明细事实来源。
- `bom_process_seasoning` 保存工序级锅序参数。
- `bom_items` / 普通 BOM 辅料行不再作为新工序调料配置的写入目标。
- 不允许一次 UI 操作同时向普通 BOM 辅料行和工序调料行写入同一物料。

### 6.2 数据约束

- 数据库或服务层保证 `(recipe_id, work_process_id, material_type_id)` 唯一。
- 保存时校验配方版本属于当前工厂且状态为 `DRAFT`。
- 保存时校验工序确实属于该 SKU 当前 workflow，并校验物料属于当前工厂且有效。
- `dosage_per_kg_g > 0`。
- 锅序关闭时后续锅比例必须为空；开启时比例必须在允许范围内。
- 后端从物料主数据覆盖名称和价格，拒绝客户端伪造。

### 6.3 读模型

页面需要一次取得：

- 当前 BOM 版本和可编辑状态；
- workflow 有序工序列表；
- 全部工序调料绑定；
- 锅序参数；
- 去重后的物料汇总；
- 配置异常和成本可计算状态。

可以由后端返回聚合 DTO，也可以由前端从完整绑定集合派生，但只有后端成本计算结果具有财务权威性。

### 6.4 写入语义

- 新增、修改、删除以单条“工序 × 调料绑定”为业务操作边界。
- 写接口需要幂等或带版本校验，重复提交不得产生重复绑定。
- 并发修改同一 BOM 时返回明确冲突，不允许最后写入静默覆盖其他工序的数据。
- 删除工序前继续使用既有引用守卫，存在调料绑定时返回 409 并引导先移除绑定。

## 7. 历史辅料兼容

历史普通 BOM 中可能已存在 `AUXILIARY` 行，但没有 `workProcessId`。处理原则：

- 不自动猜测工序，也不静默丢弃。
- 在辅料页顶部显示“存在 N 条历史辅料待绑定工序”。
- 用户逐条选择目标工序并确认用量口径后，后端在同一事务内创建工序调料绑定并停止旧行参与调料成本，避免双计。
- 在迁移完成前，汇总页将其标记为“待绑定工序”，且 BOM 不得以“配置完整”状态激活。
- 迁移操作必须可审计，并保留旧值供对照。

## 8. 错误与空状态

- **没有 workflow：** 显示“该 SKU 尚未配置工序”，提供“去工序配置”入口。
- **ACTIVE 版本：** 全部只读，提供“克隆为新版本”。
- **没有调料：** 工序卡片显示紧凑空状态和“添加调料”，不渲染大面积空表。
- **重复绑定：** 提示“该调料已在本工序配置”，并定位现有行。
- **价格缺失：** 显示物料名和缺失原因，提供维护价格入口，不按 0 元计算。
- **工序已失效：** 汇总页标记异常，禁止继续使用并提供处理指引。
- **请求失败：** 保留用户尚未提交的表单值，提供重试；不返回或展示假数据。

## 9. UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

- 生产/BOM 管理员：理解 SKU 工艺流程，需要快速把每种调料放到正确工序，但不应理解数据库字段或价格快照实现。
- 成本核对人员：主要关心一种辅料用了哪些工序、价格来源和成本贡献，不负责逐工序录入。
- 报工操作员：只填写现场知道的投入重量和锅数，不维护配方。

### 用户旅程

| 阶段 | 用户动作 | 系统回应 |
|---|---|---|
| 进入 | 选择 SKU 和 BOM 版本 | 展示版本状态、workflow 工序和配置完成度 |
| 定位 | 在工序编排中展开一道工序 | 只展示该工序的调料投入项 |
| 配置 | 选择调料、填写 g/kg、设置锅序 | 自动带入名称、单位、价格并实时解释计算口径 |
| 核对 | 切换辅料汇总 | 同一辅料只显示一次，可展开跨工序明细 |
| 修正 | 点击“定位到工序” | 返回并展开目标工序，不产生死路 |
| 生效 | 保存草稿并激活版本 | 后端校验完整性，报工按对应工序读取配置 |

### 摩擦点清单

- 同一调料跨多个工序，平铺物料表容易误以为只能绑定一个工序。
- `g/kg` 的分母是本工序半成品，而不是成品或整批原料。
- 汇总多道工序的 `g/kg` 没有统一数学意义。
- ACTIVE BOM 不可直接编辑，用户容易误认为按钮失效。
- 历史普通辅料没有工序，系统不能安全猜测。
- 单价缺失或工序失效会导致成本错误。

### 每个摩擦点的设计回应

- 以工序卡片为主入口，同一物料允许在多个卡片出现；右侧/汇总视图负责去重核对。
- 每个输入框固定文案“每 1 kg 本工序半成品投入量”，并提供计算示例。
- 汇总页展示各工序独立标签，不提供伪汇总用量。
- ACTIVE 页面显示明确克隆动作，不仅禁用按钮。
- 历史辅料进入待绑定队列，人工确认后原子迁移。
- 价格和引用异常以阻断式校验加明确下一步处理。

## 10. 验收标准

1. 顶层不再出现独立“调料配方”Tab；辅料页可切换“工序编排 / 辅料汇总”。
2. 同一调料可分别绑定滚揉和炸水，保存不同的 `g/kg` 与锅序规则；刷新后不丢失。
3. 同一工序重复添加同一调料被阻止，且不会产生重复数据库行。
4. 辅料汇总中该调料只显示一行，标记“用于 2 个工序”，展开后显示两条独立明细。
5. 汇总页不显示跨工序相加的伪 `g/kg`；成本条件不足时显示“待计算”而非 0。
6. 添加调料只能从主数据选择，名称、单位和价格自动带入；页面不存在“单价1 / 单价2”。
7. 开启锅序后第一锅固定 100%，后续锅只填一个固定比例；报工填写锅数后按既有公式计算。
8. ACTIVE BOM 只读，克隆为 DRAFT 后方可修改。
9. 历史无工序辅料可见且被标记为待绑定，不被静默遗漏或重复计成本。
10. 没有 workflow、价格缺失、物料失效、工序失效和并发冲突均有明确提示及下一步入口。
11. 后端针对唯一性、版本状态、锅序公式、历史迁移和并发冲突有测试；Web Admin 类型检查、构建和核心组件测试通过。
12. 使用 F006 隔离数据完成 headed 浏览器验收，覆盖工序配置、跨工序复用、汇总展开、版本只读与锅序预览。

## 11. 非目标

- 不重建 workflow 编辑器或运行时编译器。
- 不把工序调料迁移到 `ProcessMaterialRecipe`。
- 不删除历史 `product_recipes` 兼容路径。
- 不改变原料和包材的现有录入语义。
- 不在本设计阶段部署生产环境。
