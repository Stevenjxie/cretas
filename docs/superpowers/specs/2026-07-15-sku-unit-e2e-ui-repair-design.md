# SKU 单位链路 E2E 与 UI 修复设计

**状态：** 已确认并进入实施（用户已授权自主完成设计、实现与验收）
**基线：** `fb0f1d503ce0af4b38523cc329258f6ef2a30600`
**范围：** 只修复 SKU、Workflow、逐道录入、成品期初库存和销售订单中已复现的问题；不重算已完成历史单据。

## UX Flow Analysis

### 用户与核心任务

- 产品管理员维护 SKU 的基本单位、标准净重和多包装规格，并能在一个弹窗内清楚核对自动生成的规格。
- 工艺管理员从指定 SKU 进入 Workflow，看到正确产品和统一的报工单位；单位冲突时不能误发布。
- 操作员逐道报工时只填写业务事实：原料/半成品投料 kg、实际产出、留样和工时；不选择仓储批次，不重复填写出库量。
- 仓管录入成品期初库存或销售包装组合时，必须先选 SKU，再按该 SKU 的基本单位和包装规格录入。

### 当前阻塞与系统响应

1. 产品深链进入 Workflow 后选中了别的 SKU。系统必须以 URL 中的 `productTypeId` 为首选并在加载后保持选择。
2. 前端编辑器已能推导 kg，但后端按主数据 g 校验并把旧运行时端口 g 原样透出。系统必须把原料/半成品“报工单位”与主数据展示单位分开：报工统一 kg，成品继承 SKU 基本单位。
3. 逐道录入仍要求选原料批次并填写出库数量，操作员无法判断正式投料来自哪个批次。首道只录每种物料投料总量，正式提交时由生产库按转入顺序自动分摊。
4. 没有可用生产库或上游在制库存时，新增行和正式提交应禁用，并提示“当前只能保存草稿：生产库可投料量不足，请联系仓管补料”。
5. SKU 编辑、期初库存和销售订单字段过密或默认值误导。字段应在选择上下文后出现，关键动作固定可见，表格允许明确横向滚动，图标按钮具备可读名称和焦点状态。

### 防错规则

- 原料和半成品报工单位固定为 `kg`；成品单位继承 SKU 基本单位。单位只读，不允许操作员修改。
- Workflow 单位错误在节点上直接标记，并阻止发布；错误文案同时给出当前单位、应为单位和修复动作。
- 只兼容修复活动 Workflow 与未完成计划的投影；已完成、已撤销的业务记录保留原单位快照。
- 成品实际入库量为 `实际生产 - 留样`，成品重量为 `实际生产数量 × SKU 单位净重`；包装规格不进入报工。
- 期初库存数量在选 SKU 前保持空白，不预填 `0.01 kg`。
- 多包装销售/入库必须明确选择包装规格；无歧义时可自动带入。

## 技术方案

### 后端单位权威

- 建立单一报工单位策略：`RAW_MATERIAL`、`SEMI_FINISHED` -> `kg`；`FINISHED_GOOD` -> SKU 基本单位。
- Workflow 发布校验、运行时编译和报工配置投影共同使用该策略，不再用原料字典的 g 直接作为报工单位。
- 对活动 Workflow/未完成计划的旧 g 快照，在读取报工配置时做确定性的兼容投影；不修改已完成历史事实。
- 保留显式换算用于重量/数量计算，但不向操作员展示 `box × 200 = g` 等技术行。

### 前端交互

- Workflow 路由加载完成后按查询参数选中 SKU；AI 面板默认折叠，画布不被压缩。
- Process Sheet 优先使用 `materialInputTotals`，隐藏操作员不应维护的原料批次/出库数量；库存不足时仍可保存草稿。
- SKU 编辑使用不换行的标准换算标签与固定底部操作区。
- 成品期初库存改为空值初始化；销售订单包装明细设置最小宽度、横向滚动和关键列提示。
- 所有仅图标操作补充 `aria-label`，错误提示就地呈现。

## 验收清单

- 指定 SKU 深链进入 Workflow 后仍为该 SKU。
- 原料/半成品节点、端口、计划和逐道录入全部以 kg 展示；成品以 SKU 基本单位展示。
- Workflow 单位冲突会阻止发布，且不存在英文 box/case 换算行。
- 首道报工只填写物料投料总量，正式提交由后端自动分摊；库存不足仅可保存草稿并显示指定提示。
- 成品报工只填实际生产和留样，入库/剩余/重量只读自动计算。
- SKU 编辑、成品期初库存、销售订单在桌面视口无错误预填、遮挡或无法访问的关键动作。
- 后端目标测试、前端 Vitest、前后端构建以及 F006 隔离浏览器 E2E 通过。
