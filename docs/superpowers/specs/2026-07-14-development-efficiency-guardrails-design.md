# 开发效率护栏设计

**日期**：2026-07-14  
**状态**：已确认设计，待实现

## 目标

减少不改变交付质量的时间损耗：重复完整构建、宽泛排查、worktree 查找与清理、过期交接信息，以及手工拼接发布验收命令。

生产部署、`main` 出货闸、远端真值核验和最终风险验证继续保留；本设计只消除无效重复。

## 方案选择

采用“规则 + 两个只读工具 + 台账收敛”。

- 不自动删除 worktree 或远端文件。
- 不改变部署脚本，也不执行部署。
- 不写入任何凭证；远端地址通过既有公开部署配置或环境变量获取。

## 组件

### 1. 项目规则

`AGENTS.md` 新增四类执行约束：

1. 创建代码 worktree 前先检查现有 worktree、活动台账与 scope；只读和纯文档任务不新建 worktree。
2. 排查先从当前 handoff、明确模块和已知测试入口开始；无命中再扩大搜索，禁止默认全仓递归扫描或倾倒完整 CI 日志。
3. `origin/main` 与精简后的 `docs/dispatch/ACTIVE.md` 是当前状态真值；历史条目进入归档并从 ACTIVE 留下索引。
4. 同一 worktree 的 Maven 目标测试顺序执行；复用既有 E2E helper；浏览器/设备验证限制并发并在无真实进展时停止或切换路径。

### 2. Worktree 报告工具

新增 `scripts/maintenance/worktree-report.sh`：

- 输出 worktree 路径、分支/HEAD、脏状态与相对 `origin/main` 的合并状态。
- 对已合并且干净的分支标记为“可人工清理候选”。
- 默认只读；不提供删除选项。

### 3. 发布验收工具

新增 `scripts/deploy/verify-release.sh`：

- 显式选择 `backend`、`web-admin` 或 `all`，并接受环境与预期标记参数。
- 后端检查实际活跃槽位、对应服务状态、健康端点及可选 jar 标记。
- Web Admin 检查服务 HTTP 状态及可选 bundle 标记。
- 所有检查输出为单次可保存的证据报告；任一必需检查失败即非零退出。
- 仅执行 SSH/HTTP/read-only 文件检查，不重启、写入或清理远端内容。

### 4. 活动台账收敛

- 将历史状态移至带日期的归档文件。
- `docs/dispatch/ACTIVE.md` 仅保留：更新时间、当前真值入口、在飞任务、阻塞项、下一动作和归档索引。
- 不删除历史信息。

## 测试与验收

先为两个 shell 工具创建可在本地运行的测试：用临时 Git 仓库、PATH 注入的伪 `ssh`/`curl` 验证参数、成功、失败和只读行为。

实现后只执行：相关 shell 测试、`bash -n`、`git diff --check`。不运行完整 Maven 或前端构建；本次不触及产品代码。

## 非目标

- 不自动删除任何 worktree。
- 不改动生产部署、迁移、权限或业务逻辑。
- 不用 CI 全局强制门禁替代人工风险判断。
