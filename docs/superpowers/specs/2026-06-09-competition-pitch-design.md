## 二、核心叙事框架

**一句话定位**：白垩纪是中国中小食品工厂和餐饮的AI经营大脑——让没有数据部门的企业，用一句话完成数据分析师+ERP+生产监控三合一的工作。

**核心洞察（演讲中必须点出）**：

**洞察1（工厂）**: 所有"预设固定流程"的工具，根本不适合食品加工非标品行业。机器废、ERP不好用、工人不会录——底层是同一件事：软件的设计假设（标准化产品、固定工序）与食品加工现实（手工处理、批批不同、SKU常变）根本不匹配。AI的优势恰恰是不预设流程，用自然语言描述什么流程就执行什么，无需定制。

**洞察2（餐饮）**: 餐饮的数据分析问题不只是"贵"，更是"滞后"——调数据→图表→开会→问部门→重复，等分析完这个月已经过了。建议永远来不及。AI把决策延迟从几天压缩到30秒，让数据驱动在时间上变得可行。

### Slide 4c — 核心技术护城河 · 自我蒸馏数据飞轮（5:00–5:40）⭐ 技术差异化

> **新增（2026-06-10）**。配合已有 Slide 4b（成本随用随降 / 规则优先三层 resolver），4c 进一步讲透"为什么我们的 AI 可信、且越用越护城河"。对评委（投资人）讲清这是 Cretas 区别于金蝶/用友（无 AI、UI 复杂）和通用 LLM BI（会瞎编、贵）的**核心技术护城河**。

**标题**：自我蒸馏数据飞轮——不瞎编数字的可信 AI

**顶部对比**：通用 LLM BI（会瞎编数字 · 贵 · 重复场景重复烧钱）✕ vs 白垩纪（数字服务端重算 · 越用越便宜 · 数据自主）✓

**三大核心能力**：

1. **Claims-Pinning 结构性消灭数值幻觉**：服务端按真实业务数据**重算** LLM 输出的每个数字声明 + 实体归属校验，对不上即拒绝。AI 洞察**绝不瞎编数字**——这是食品/制造业 ERP 可信 AI 的关键（对比通用 LLM BI 的幻觉风险）。

2. **双层质量门 + 就绪度仪表**：G1 确定性重算 + G2 LLM-Judge（qwen3-max 评事实性 / 可操作 / 流畅），只有高质量数据被采用沉淀；census 仪表实时可见就绪度。

3. **Serve-from-Corpus 越用越便宜**：每次 AI 分析（图表洞察 / 经营问答 / 驾驶舱）经质量门沉淀进语料库；重复场景直接从语料库回答（**0 token**）→ 成本随使用量**下降**；语料质量 = 用户当下体验（无模型版自我蒸馏）。

**数据飞轮闭环**：用户用 AI → 双层质量门 → 高质量语料库 → 越用越便宜 → ⟳ 训练自有垂直模型（∞）

**两条护城河注脚**：
- **5 个 AI 子系统统一冷启动**：图表洞察 / 经营问答 / 驾驶舱叙事 / 数据物化 / 意图路由，全部沉淀进统一高质量语料（qwen3-max teacher）。
- **渐进自主路径**：系统已建到"训练只差一条命令"。按经济性门控触发后，可训自有垂直模型替代外部 LLM——**成本归零 + 数据自主 + 私有化部署**。

**效果数字**：全平台 ~28 个分析面 / 60+ 图表槽全部有 AI 洞察（确定性规则层 0-token + 按需 LLM）；数值幻觉结构性消灭；成本随用降；数据飞轮 = 护城河（越用越好 + 为自有模型攒语料）。

**对应 deck slide id**：`s4c`（位于 `s4b` 之后、`s5` 之前）。

### Slide 4d — 问答预案 · 训练自有模型 & 数据主权承诺（Q&A 备用）⭐ 数据合规

> **新增（2026-06-10）**。配合核心技术 slide `s4c`（自我蒸馏数据飞轮），`s4d` 是**问答预案 / Q&A 备用页**，回答评委 + B2B 客户最关心的一问：**"你们什么时候训练自己的模型？客户数据会被用于训练吗？"** Headline 放最显眼的是**数据合规（客户数据主权）**——这是 B2B / 食品制造业评委最在意的点。

**评委原问**：你们什么时候训练自己的模型？**客户数据会被用于训练吗？**

**🔴 数据合规（核心承诺，放最显眼 — 绿/红强调框）**：
1. 客户数据**默认不直接用于模型训练**。
2. 需**客户明确授权**才用于训练。
3. 授权后也走**脱敏**：数值分桶 + 实体（店名/菜名）伪名化 + **按业态桶训练（非按租户）** → 结构性防止跨租户记忆 / 数据泄露。
4. **合成语料**（系统自动生成、无任何真实客户数据）可无条件用于冷启动。

**其余 4 点（支撑卡）**：
- **何时训练**：数据就绪（某业态语料桶达 GREEN ~1000 条高质量；目前 restaurant 已 608/1000）+ 商业触发（规模过自托管经济门，或客户私有化/离线/数据自主需求）。系统已建到"训练只差一条命令"。
- **规模 · 方法**：LoRA/QLoRA 参数高效微调（非全量预训），~1–2k 高质量样本/业态桶，几个 epoch。
- **模型**：开源基座 Qwen2.5-7B/14B（强中文，匹配 qwen3-max 蒸馏 teacher 分布）+ LoRA 适配器。
- **GPU · 成本**：训练单张消费级 GPU（24GB 理想 / RTX3060 12GB QLoRA 4-bit 可训 7B），几 GPU-小时成本极低；自托管 serving 仅在月用量过 break-even(~5–10M token) 才划算。

**定位一句话（口述要点 — 收尾必说）**：
> **渐进自主**：现在用最强外部模型保证质量，数据合规沉淀语料，规模到了一条命令训出自有垂直模型——**客户数据主权始终在客户手里**。

**口述要点（数据合规优先级最高，先讲这一句再展开时点/成本）**：
- 先答合规：**"客户数据默认不进训练，要训也得客户授权 + 脱敏 + 按业态桶而非按租户 → 不可能跨租户泄露。冷启动只用合成语料。"**
- 再答时点：**"不是现在就训——现在用 qwen3-max 等最强外部模型保质量；等某业态语料攒到 ~1000 条高质量、或客户要私有化，一条命令就能训出垂直模型。"**
- 成本反问化解："自托管不是为了省小钱，是给需要数据自主/离线的客户兜底；消费级单卡 QLoRA 几 GPU-小时即可，门槛极低。"

**对应 deck slide id**：`s4d`（位于 `s4c` 之后、`s5` 之前）。

### Slide 4e — 进攻性卖点 · 正向数据飞轮 & 数据主权（5:40–6:00）⭐ 进攻框架

> **新增（2026-06-10）**。`s4c`（自我蒸馏数据飞轮 = 核心技术护城河）+ `s4d`（训练 Q&A / 数据合规防御承诺）已分别覆盖技术与防御视角；`s4e` 是把**数据合规从"防御性承诺"翻成"进攻性卖点"**的那一页——**正向数据飞轮 + 数据主权**作为赢得 B2B 客户的差异化武器。

**标题**：正向数据飞轮——你的数据训你的模型，主权在你

**核心论断**：合成数据让模型"会说话"，**真实授权数据才让模型"懂这家客户的生意"**（Fable 审计确认：微调买的是 style / 格式 / 语气，事实贴合度只有真实数据能给）→ **授权数据 = 训练价值的天花板**。

**正向数据飞轮（双赢商业故事，画成闭环图，slide 的 centerpiece）**：
客户授权数据 → 训出更懂的专属 AI → 客户体验更好 → 更愿意授权更多 → ⟳（飞轮越转越强）

**数据主权（差异化进攻点）**：
- **数据主权始终在客户**：可授权、可撤回；私有模型本地 / 私有化部署，数据不出客户域。
- **差异化**：通用 LLM BI 把你的数据喂给 OpenAI / 第三方；**白垩纪是"你的数据训你的模型，主权在你"**——对制造业 / 食品业（数据敏感）是强卖点。
- 两种模式：单租户**私有模型**（授权后原始数据直接用，效果最佳）/ 跨租户**共享模型**（授权 + 脱敏并行）。

**训练价值表**：

| 数据来源 | 价值 | 为什么 |
|---|---|---|
| 真实授权数据 | ⭐⭐⭐ 最高 | 匹配真实业务分布 / 问法 / 数据形状（脏数据 / 长尾 / 边界） |
| 合成语料 | ⭐⭐ 冷启动 | 覆盖均匀 / 隐私安全，但缺真实长尾，只够 bootstrap |
| fallback 日志 | ⭐ 补充 | 量大但质量参差（judge 实测 ~12% 过关） |

**一句话定位**：**"授权后真实数据不仅能直接训，而且是唯一能训出'懂这家客户生意'的高价值数据；数据合规从防御承诺变成'你的数据训你的模型、主权在你'的进攻性卖点。"**

**对应 deck slide id**：`s4e`（位于 `s4d` 之后、`s5` 之前）。

## 四、评委问答准备

**Q1: 和钉钉/金蝶/用友/美团数字化有什么区别？**  
A: 他们的产品假设客户有标准化的产品和流程，服务的是已经能数字化的企业。我们服务的是那些买了ERP但用不起来的非标品工厂，和那些有数据但没有分析能力的非连锁餐饮。AI原生而非模块化插件，这是结构性差异。

**Q2: 工厂和餐饮差别那么大，一套系统能真的服务两个行业吗？**  
A: 底层是同一套AI意图识别引擎（310个工具），上层按行业分化工具集。就像同一个操作系统可以跑不同应用，核心技术复用，行业层各自适配。POS渠道也同时覆盖工厂和餐饮，是渠道优势不是分散。

**Q3: 3万家渠道资源怎么转化？**  
A: POS系统合作方已有客户关系和信任基础，我们的产品接入他们现有系统，而不是让客户再装一个新软件。这是分销模式，不是直销，获客成本大幅降低。

**Q4: 数据安全和隐私怎么保证？**  
A: 支持私有化部署（食品溯源本身有合规要求，我们的数据安全标准高于行业均值）。食品溯源合规要求反而是护城河——客户数据必须留存，我们帮他们管理并利用这些数据。

**Q5: 视觉AI需要装摄像头，工厂愿意吗？**  
A: 已有六扇门客户验证可行性。摄像头只需普通IP摄像头，几百元成本，不改变工人任何行为，分析结果直接给管理层看。实测工厂接受度高。

## 五、PPT制作要点

**总页数建议**：10-12页（含封面/尾页）  
**风格**：深色背景（食品工业感）/ 大字号数据 / 双列对比布局（工厂vs餐饮）  

**每页核心原则**：
- 一页一个信息点，不塞多个概念
- 数字要大（90%无数据分析 / 310个工具 / 3万家渠道 / 30秒出报告）
- Demo页最重要，分配最大版面

**必备视觉素材**：
- 双列对比图（工厂痛点 vs 餐饮痛点）
- AI系统架构图（底层引擎 → 工厂引擎 / 餐饮引擎）
- 真实客户界面截图（六扇门报工界面 + 青花椒AI分析界面）
- 团队院校logo矩阵
- 视频：工厂报工演示（50s） + 餐饮AI问答演示（55s）
