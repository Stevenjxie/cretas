# SKU 单位链路 E2E 与 UI 修复实施计划

> 每项先补能复现线上失败的测试，再做最小实现；集中完成后统一构建和 E2E。

## 1. 后端报工单位契约

- 为原料/半成品固定 kg、成品继承 SKU 基本单位补充失败测试。
- 让 Workflow 发布校验、运行时编译与 Clerk Sheet 投影共用同一策略。
- 兼容活动 Workflow/未完成计划中的旧 g 快照，不改已完成历史记录。
- 验证正式投料总量的自动分摊、并发锁和库存不足草稿边界。

## 2. Workflow 和 SKU 页面

- 补充深链选择、单位阻断和默认折叠 AI 面板测试。
- 修复 URL 产品选择、单位错误可视化、画布布局。
- 修复 SKU 换算标签换行和弹窗操作区可见性。

## 3. 逐道录入

- 补充物料总量模式、kg 单位、库存不足禁用新增/正式提交、成品自动字段测试。
- 操作员界面不再要求选择原料批次或重复填写出库量。
- 放大行操作命中区，补充可访问名称和就地提示。

## 4. 仓储与销售 UI

- 期初库存数量和单位在选择 SKU 前为空。
- 包装明细支持清晰横向滚动和多规格选择，关键字段不被挤压。

## 5. 验证与发布

- 运行相关 Maven 测试、Vitest 与前后端构建。
- 使用隔离浏览器在 F006 重跑 SKU、Workflow、逐道录入、期初库存和销售订单 E2E。
- 代码审查后合并；发布前读取蓝绿 upstream，部署到非活动槽位并切换验证。
- 只读确认 LIUSHANMEN 未被写入，记录 F006 的线上截图和 API 证据。
