# 时间词语料 + 人工晋升 Implementation Plan（计划 2 / 共 2）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把「确定性规则没认出时间词、而 LLM 认出了」这件事**记下来**，并给人一条把它晋升进确定性规则的通道。

**Architecture:** 新表 `ai_time_phrase_corpus`（形状照抄既有的 `ai_promoted_routes`）。写入点是 `parse_restaurant_query`（async，手里有 `pool`），条件是产品**已经算好**的 `spec.window_from_llm_phrase`。一个 CLI 列出待处理的词并记下已处理；一个跑批在积压超阈值时告警，且把「语料至今 0 条」与「无积压」分开说。

**Tech Stack:** Python 3.11 · asyncpg · PostgreSQL（Flyway 风格迁移）· pytest · bash cron

## Global Constraints

- **设计卡**：`docs/superpowers/specs/2026-08-16-时间词语料与澄清按钮-design.md`（件 2 / 件 3 两节）
- **入库条件是 `spec.window_from_llm_phrase`** —— 产品已经算好，⛔ 不新增判别、⛔ 不重算一遍
- **写库 fail-open**：记语料失败 ⛔ 不许让一次问答失败，**但必须打 warning** —— 否则「语料一直是空的」会和「没有这类问句」长得一模一样
- **晋升是人手写分支**：`_resolve_sales_date_range` 是 237 行 / 38 个 `if` 的手写解析器，**没有可追加的词表**。CLI ⛔ 不能也⛔ 不许假装能机械 append；这句话要写进 `--help`
- **跑批三态 rc**（硬约束 4）：`rc=0` 正常 / `rc=1` 有积压 / `rc=2` **没量到**（表读不到）。第三态**必须主动构造一次**
- **「语料至今 0 条」单独一行**，⛔ 不与「无积压」同措辞
- **承重断言写在 `backend/python/tests/` 下**，⛔ 不只活在手工探针里
- **每条断言配变异对照**；阴性断言额外配阳性对照
- **⛔ 变异还原只用 `git checkout -- <file>`**，绝不用反向字符串 replace（本仓事故：它会命中同形状的别处）
- **⛔ 先提交再变异** —— `git checkout --` 会把未提交的改动一起抹掉（本仓一晚三次）
- **⛔ 不让 subagent 跑全量**（3 分钟，实测两次它会转后台然后丢掉整轮）。全量由控制端跑。当前基准 **8 failed / 6007 passed**，那 8 条在 `origin/main` 上就有

```bash
# 时间词语料积压告警。
#
# 🔴 三态(硬约束 4): rc=0 没问题 / rc=1 有积压 / rc=2 **这次没量到**。
#    ⛔ 两态会把「没量到」折叠进「没问题」—— 一个连不上库的跑批会安静地
#    天天绿, 而它一个样本都没看过。
set -uo pipefail
ALERTS=/www/wwwroot/cretas/logs/time-phrase-backlog-alerts.log
THRESHOLD=20

OUT=$(cd /www/wwwroot/cretas/code/backend/python \
      && source venv-current/bin/activate \
      && python -m smartbi.scripts.time_phrase_corpus_cli --counts 2>&1)
rc=$?

if [ "$rc" -ne 0 ]; then
    echo "XXX INSTRUMENT DEAD $(date '+%F %T') — 语料表读不到, 本次读数作废" >> "$ALERTS"
    echo "$OUT" >> "$ALERTS"
    exit 2
fi

total=$(echo "$OUT" | grep -oP 'total=\K[0-9]+')
unpromoted=$(echo "$OUT" | grep -oP 'unpromoted=\K[0-9]+')

# ⚠️ 解析不出数字也是「没量到」, ⛔ 不是 0
if [ -z "$total" ] || [ -z "$unpromoted" ]; then
    echo "XXX INSTRUMENT DEAD $(date '+%F %T') — 读数解析失败: $OUT" >> "$ALERTS"
    exit 2
fi

# 🔴 「至今 0 条」单独说 —— 它要么是词表饱和, 要么是**写入路径根本没跑**,
#    ⛔ 与「无积压」是两件事。
if [ "$total" -eq 0 ]; then
    echo "--- 时间词语料至今 0 条 $(date '+%F %T') — 要么已饱和, 要么写入路径没跑" >> "$ALERTS"
    exit 0
fi

if [ "$unpromoted" -gt "$THRESHOLD" ]; then
    echo "XXX BACKLOG $(date '+%F %T') — 未晋升 $unpromoted 条 (阈值 $THRESHOLD)" >> "$ALERTS"
    exit 1
fi
exit 0
```
