# 工序报工实时入库 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让一次工序报工在**同一事务**内完成「扣上道料 + 产出进半成品库 + 只关本道工序」，取消审批门，使下一道工序立刻可领料。

**Architecture:** 复用现有 `WipInventoryService.postApprovedOutput`（它已经是完整的过账事务：消耗源 WIP + 产出入 SFI + `wipPosted` 幂等标记），把它的**调用点从审批挪到提交**。批次完工判定从「按数量」改为「所有工序完成」。⛔ 不新建过账逻辑，不改 SFI 的锚粒度。

**Tech Stack:** Java 21 · Spring Boot 3.2.12 · JPA/Hibernate 6 · JUnit 5 + AssertJ + Mockito · Maven

## Global Constraints

- **SFI 锚不变**：`intermediateBatchNo = CLK-SEMI-{planId8}-{productTypeId8}`，per(计划, 产品类型)。追溯靠流水的 `report_id`，⛔ 不拆行。
- **成本判据**：SFI 是移动加权平均、路径依赖 ⇒ 只断言**模型一致 + 总成本守恒**，⛔ **不得断言 `unitCost` 逐位相同**。
- **「待小结投料」必须归零**：半成品盘点的 `PendingInterimFeedService` 补偿逻辑专为「延迟扣减窗口」而写；留一处未改就是双重扣减 → 假盘亏 + 假凭证（借6602/贷1405）。
- **闸的命名**：任何读 `src/main` 的新测试类必须以 `ContractTest` / `StartupGuardTest` 结尾，否则 CI 选择器不执行它（`GateSelectorCoverageContractTest` 会红）。
- **测试命令**：`cd backend/java/cretas-api && mvn -B -o test -Dtest='<类名>'`
- **每个 Task 结束必须 commit**，用 `./scripts/safe-commit.sh "msg" <files...>`。
- **变异纪律**：每条新断言都要**变异实测红过一次**，且**先证明变异落地**再读红绿。

```java
/**
 * 批次完工 = 该批次下【所有】工序任务都完成。
 *
 * <p>⛔ 不再按数量判 (actual >= planned)。planned_quantity 在 prod 是 NOT NULL,
 * 存货生产把「没有计划数量」存成 0 ⇒ 任何一次报工都满足 >=, 第一次报工就把整批关掉,
 * 而批次下面还挂着未完成的工序 → 后续报工一律 409。
 * (PR #2724 补的 planned>0 守卫是止血; 这里才是根治。)
 *
 * <p>SKIPPED 视为已完成 —— 跳过的工序不该把批次永远挂住。
 */
private boolean allTasksCompleted(String factoryId, Long batchId) {
    List<WorkProcessTask> tasks = workProcessTaskRepository
            .findByFactoryIdAndProductionBatchId(factoryId, batchId);
    if (tasks.isEmpty()) {
        return false;   // 没有工序 = 判不了, 不替用户收口
    }
    return tasks.stream().allMatch(t ->
            t.getStatus() == WorkProcessTaskStatus.COMPLETED
                    || t.getStatus() == WorkProcessTaskStatus.SKIPPED);
}
```

调用点替换原来的数量比较。
