## 一、诚实结论 (TL;DR)

**我的 E2E 证明了"系统管道"端到端能跑通 (订单→计划→批次→报工→完工→出货), 但它没有忠实复现 6.1-6.3 真实数据的工序结构、字段值、多仓订单、结存现实。**

- ❌ **E2E 演示用的是合成的"通用 10 道工序 + 编造数字", 不是真实的产品专属工序和真实重量。**
- ❌ **三个关键真实特征没有在系统里被体现**: (1) 每个产品工序结构不同, (2) 一个订单跨 6 个目的仓, (3) 结存/剩余 (跨天 carryover) 贯穿全流程。

数据覆盖度 (诚实): **系统能力 ~75%, 真实数据忠实复现 ~35%**。

### 2.2 生产工序 — 每个产品结构不同 (这是核心)

| 产品 | 实际工序链 (Excel sheet) | 副产物 | 最终单位 |
|---|---|---|---|
| **猪舌** | 修油 → 滚揉(保水) → 焯水 → 去舌苔 → 熟制(卤制) → 气调(分切装盒) | 肥油(修油)、舌苔碎肉(去舌苔) | 盒 |
| **猪蹄** | 前处理[领料-分切-化冻捞出-焯水油炸-修猪蹄] → 熟制 → 剔骨 → 气调 | 骨头(剔骨)、发黑废品 | 盒 |

每个工序 sheet 都有: 原料批次/上道批次/本道批次/日期/投入kg/产出kg/出成率/**剩余重量(结存)**/人工(分)/人工(时)/备注。

### 2.3 关键真实特征

1. **批次树状拆分/合并**: 1 个原料批次 → 多个滚揉/焯水/熟制/气调批次 (非 1:1 线性). 批次号链: 原料0517 → 滚揉0518 → 焯水0521 → 舌苔0522 → 熟制0523 → 气调.
2. **结存/剩余 (carryover) 贯穿全流程**: 每道工序、成品进出、原料进出库都有"剩余/该批结余"列。张权原话: "实际是有结存的, 分两天或分三天生产"。**这是张权明确的核心卡点 (G8)**。
3. **kg ↔ 盒 转换**: 生产以 kg 报工, 成品入库以盒计 (120g/盒)。气调 sheet: 成品重量70.68kg → 589盒。
4. **调料 BOM + 成本**: 猪舌有完整调料配方 (C18/花雕酒/花椒/盐/复合调味料... + 卤制八角/桂皮/...) + 单价 + 前制程成本/卤制成本/总成本 (0.366 元/盒)。包材成本 (气调盒0.23/膜0.085/气体0.21/标签0.0264 = 0.5514 元/盒)。
5. **人工按工序段分摊**: 人工 sheet 把每天的总工时按 修油/滚揉/焯水/舌苔/熟制/气调/装框 分摊到每盒 (元/盒)。报工原话: "8:00-9:40(14人) 9:40-11:30(12人)..."。
6. **成品总出成率 ~0.55** (气调 sheet 成品总出成率 0.55-0.60), 原料→成品整体出率约 55%。

### 2.4 报工格式 (群内图片, 张权微信报工)

实际报工 = **产品名 + 秤照(毛重) + 桶/皮重 + 净重计算(393.5-64=329.5Kg) + 时间戳 + 装盒照**, 一个工序分多条消息按时间发。语音转录确认逐道逻辑 (修油10→8, 滚揉8→12保水, 焯水12→5)。

## 四、6.3 剩余可能订单分析 (Steve 新增需求)

### 4.1 现象

6.3 订单 **猪蹄暴增到 7088 份** (6.1=505, 6.2=552, **6.3=7088, 14×**)。这种尖峰订单不可能当天现做, 必须**靠前几天的结存 (剩余成品库存) + 提前备货**填充。

### 4.2 数据里的"剩余"在哪

- **气调 sheet**: 每批 `入库数量/盒` + `留样/盒` + `剩余数量/盒` + `领用数量/盒` + `实际生产数量/盒`。剩余 = 当天没发完的成品。
- **成品进出 sheet**: 每个成品 `初期盒` + `该批结余` + 按日期列流水, 跨天结转。
- **原料进出库 sheet**: 原料 `初期` + `该批结余` (如冷冻猪舌结存50箱、猪蹄160箱)。

### 4.3 "剩余可能订单"应该怎么体现 (系统设计建议)

核心 = **订单需求 vs 可用结存库存 vs 生产缺口** 三方对账, 防呆地告诉操作员"这单还能不能接/要补产多少":

```
对某产品某仓某日订单:
  可用结存 (上日剩余成品 FG.available)
  - 已分配
  = 可立即满足
  订单需求 - 可立即满足 = 生产缺口 → 自动建/提示生产计划
```

落地形态 (3 选 1, 待 brainstorm 定):
1. **订单履约看板**: 每个 6.3 订单行显示 `需求7088 / 现有结存X / 缺口Y`, 缺口一键转生产计划 (符合防呆 Rule 1+5)。
2. **成品可用库存视图**: FG 按产品+仓显示 `在库/已留样/已分配/可用`, 跨天结转 (对应气调剩余列)。
3. **生产建议**: 基于"未来订单 - 当前结存"算每日应产量 (对应猪舌调料 sheet R60+ 已经在做的"应产/结存"测算)。

⚠️ 这是**新功能**, 不是 audit 范围内的现有能力。需走 brainstorm → spec → 实现。当前系统的 FG (finished_goods_batches) 有 status=AVAILABLE 但**没有"订单需求 vs 可用库存 vs 缺口"的对账逻辑**。

### 5.1 客户决策 (张权, 2026-06-03 微信) — 猪蹄工序建模 defer
