# 周五客户当面确认单 — 六扇门（2026-06-12 演示日）

> 4 项都是「需客户拍板才建/才关」的决策项，不猜着做。每项：现状一句话 + 要问什么 + 答案怎么落。

## 1. 编码：16 位分段是否严格执行

**现状**：已上线「小补」方案 = 数字前缀（001原料/002包材/003辅料）+ 前三位主编码 + BOM 关联主编码；16 位分段生成端点已有（`/material-segments/generate-code`，可现场演示预览）。
**客户原话**（转录行4192）："一共 16 位，前面 10 位是动不了的…选了类型原料以后他自动到 001，设计到牛腱以后到 001 的 001"；老板口径「无所谓」。
**要问**：编码是否必须严格 16 位贯穿全部物料/单据？还是现在的小补 + 16 位预览够用？
**落法**：严格 → 16 位分段体系排 P1（影响 A 流大小）；够用 → 维持现状，P1 项关闭。

## 2. 角色：PMC（生管）与 配料员 要不要独立账号

**现状**：系统角色枚举无独立 PMC/配料员；配料员功能当前可由 yield_operator（报工操作员）兼任（批B 审计 V0 残留项）。
**客户原话**（转录行3583 / catalog 行888-896）："生产全程是 PMC"；链路 = 中台消化订单 → 厂长排产建计划 → 下发生管（PMC）全程管理。
**要问**：① PMC 日常在系统里做什么（排产？改计划？只看？）—— 需要独立角色还是 production_manager 兼任？② 配料员要不要独立登录（只领料/配料权限）？
**落法**：要独立 → 扩角色枚举 + 权限矩阵（🔒 权限红线，终审后上）；兼任 → 记录结论，关闭 V0。

## 3. 付款：有没有「付钱给客户」的场景（G5）

**现状**：采购方向付款申请 → 双审 → 出纳付款全链已验通（V1）；销售方向付款（客户退款/返利/押金退还）无专用链路。
**要问**：实际业务里有没有要从系统发起「付给客户」的款？什么场景、大概频率？
**落法**：有 → 架构二选一（salesOrderId 专用字段+路由 vs 通用 entityType/entityId，回来拍板后建）；没有 → G5 关闭。

## 4. 财务对接：导表格式当面核对（SP11 scope）

**现状**：已拍「仅导金蝶表头格式凭证表，不接 API，财务流 H 整体 P2 偏后」；凭证导出已上线可演（含税三行价税分离已坐实）。
**要问**：① 财务用的金蝶具体版本（KIS / 云星空 / 精斗云）？当面对一遍导出表头，确认能直接导入；② 除凭证表外还要哪几张（科目余额表/序时账）？③ 确认近期不接 API。
**落法**：表头有出入 → 按版本调导出模板（小改）；要加表 → 排 P2。
