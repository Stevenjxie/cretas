# 六扇门食品工厂系统 — 排期 Roadmap

> **来源**: 2026-06-09 两份会议转录 → `requirements-catalog.md` → `需求与现状分析.md`(103 模块 gap)。
> **生成**: 2026-06-09 Opus organizer。工作量估算 S=0.5d/M=2d/L=5d/XL=10d, 仅计未完成(partial+missing)。

## 排期原则(organizer 判断)

1. **客户瓶颈优先**: 客户两次强调"工厂这边跑不通,所有商务大费都卡在这" + "半个月内 5 个品全上" → **P0 = 生产闭环(C) + 成本自动计算(B) + 一物一码补缺(A)**,这是上线必需。
2. **🔒 红线模块回 main 由 Opus 终审**: 凡涉及 成本核算口径/权限矩阵/库存事务/Flyway 迁移/业态隔离 的模块,执行者只做到 PR,Opus 终审+从 main 部署(见 organizer-protocol)。
3. **待客户拍板的先不动手**: 6 条矛盾 + 21 条待澄清(见 catalog 末)里,**半成品"三状态 vs 同单双产出"之争、是否要"建议销售价"、16 位编码是否真要、财务是否接金蝶/用友 API** 这几条直接决定 P0 模块怎么做 → 必须周五演示会先敲定。
4. **财务模块(H)/研发报价(G)/16位编码(A3) 偏后**: H 客户自己说"只做业务端,财务靠导表或接 API,不自建总账";G 多为新建;A3 客户口径摆动。→ 多归 P1/P2。
5. **端分工**: backend 101(几乎每模块都有) / web-admin 84(管理后台为主) / RN-app 29(操作员领料·报工·撤回·调拨接收)。RN 改动集中在 C/F 流。

## 阶段 0 · 客户澄清(周五演示会, 先于动手)

解下列**阻塞 P0 设计**的决策,否则会建错(见 requirements-catalog.md「矛盾/待澄清」全文):

- **C 半成品方案二选一**: 「生产单三状态(待生效/生效中/完成)+生产中存半成品」 vs 「同一单产出 成品+半成品 两产物,半成品挂库当原料」——客户当场反复,必须定。
- **E 是否要"建议销售价"**: 一方要"下单可改的建议价",一方要"根本不要,只留成本价+下单填价+毛利红线"。决定 SKU 是否存销售价字段。
- **A3 16 位分段编码是否真要**: 客户既说要 16 位主编码分段,又说"编码规则无所谓能搜到即可"。决定 A 流是大改还是小补。
- **H 财务对接方式**: 接金蝶/用友 API vs 仅导出其表头格式的凭证表。决定 H 流范围。
- **B 超支报警阈值口径**: "标准 18 实际 9 差 5 块报警"——按绝对值还是百分比?毛利红线按毛利率(成本×(1+目标毛利))。
