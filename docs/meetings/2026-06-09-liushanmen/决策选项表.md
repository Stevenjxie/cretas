## 决策 1 · 半成品方案：三状态生产单 vs 同单双产出

### 客户原话 (transcript.txt 行705-754)
> 行706-714 (先提三状态): "你新建生产任务单…然后分三个状态:**待生效 / 生效中 / 完成**,完成的时候才…转(成品),如果生产中的话那可以存半成品就走"
> 行720-731 (当场自我否决,改方案): "**哦不用了,我想起来了。我还是这个单子走** —— 半成品我折成成品数…挂成品单子在下面,你加一个半成品就行了。**直接在这个单子里面我产出两个成品:一个是成品,一个是半成品。那只挖(拨)的时候只会挖成品走,半成品是还挂在生产里面的**"
> 行747: "就拿前面一个单子去接下面一个单子"

### 选项
| | A · 三状态生产单 | B · 同单双产出 (客户最后落点) |
|---|---|---|
| 做法 | 生产单走 待生效→生效中→完成 状态机,完成才转成品;生产中可"存半成品退出" | 一张生产单**同时产出 成品 + 半成品两个产物**;成品出库,半成品挂半成品库当原料;下一单领该半成品续做 |
| 实现影响 | 新增状态机 + "中途存半成品"的挂起逻辑,较重 | **复用已建**: `SemiFinishedInventory`(WIP重量库) + `completeProduction` 建FG + `sourceWipNo`(二次加工领半成品)。只需加"一单多产物登记 + 半成品回挂" |
| 端 | backend + web + RN(报工) | backend + web + RN(报工产出登记) |
| 工作量 | L | **M**(地基已在) |

### ✅ 推荐 B（同单双产出）
客户**当场把 A 推翻选了 B**;且 B 跟我们已 ship 的半成品库/WIP 移动均价/sourceWipNo 完全对得上,改动小。A 的三状态机是客户的初始草稿、自己放弃了。

## 决策 2 · 要不要"建议销售价"

### 客户原话 (transcript-2b 行81-122)
> 行88-89 (一方,要建议价): "那个销售价…是所谓的**建议销售价**,不是固定那个值的,应该是下单后可以改的"
> 行92-102 (另一方/财务口径,否决): "**没有建议销售价,不需要建议销售价**…正常财务有一个成本价…然后我们销售创建销售订单,创建价格,**低于(底价)这个价格就会提示红色…预警**"
> 行107-111 (红线口径): "我这毛利率要达到10(%),有可能我的成本8块,那情况下**不允许低于(对应)10的销售价,以毛利率为主**"
> 行114-118: "销售把价谈高,毛利高,提成也就高…公司的红线这个底线就是这个毛利率"

### 选项
| | A · SKU 存"建议销售价" | B · 不存销售价 + 毛利红线预警 (主导口径) |
|---|---|---|
| 做法 | SKU 维护建议销售价,下单预填可改 | SKU **只存成本价**;下单时填价,低于 `成本×(1+目标毛利率)` → **红色预警(不卡死)**;毛利联动提成 |
| 实现影响 | SKU 多一字段;建议价每批次变易误导 | backend 算最低价 + web 下单实时预警 + 提成联动。SKU 更简洁 |
| 端 | web + backend | web + backend |
| 工作量 | S | M |

### ✅ 推荐 B（毛利红线，不要建议销售价）
否决方是老板/财务口径(占主导)、更简洁,且"毛利率红线预警"是反复强调的明确诉求。**前提**: 成本价必须先有(来自 B 流实际成本核算)。"建议价"每批次浮动、易误导。

## 决策 3 · 编码：是否大改成 16 位分段体系

### 客户原话 (transcript-2b 行3446-3464 + 行4192-4241)
> 行3446-3464 (一方,字母方案): "查找就是 **BC 开始**(包材)…如果 BC 开头自动是包材,后台字段关联一下"
> 行4192-4199 (16位结构构想): "一共 **16 位**,前面 10 位是动不了的…选了类型原料以后他自动(到)001 号,设计到牛腱以后到 001 的 001"
> 行4205-4208 (主编码关联): "**前面三位肯定是规定好的,就是主编码…BOM 关联只关联前三位的主编码**"
> 行4228-4241 (老板收敛): "**编码的规则到底怎么样都无所谓,到时候你们能看到能搜索到就可以了**…**001 我们就找原料,002 找包材,003 找辅料**"

### 选项
| | A · 大改 16 位分段编码 | B · 小补现有编码 (推荐) |
|---|---|---|
| 做法 | 建 16 位结构(类型/部位/品类级联自动拼前10位+后6位序号)+ 前三位主编码 + BOM 关联前三位 | 保持现有"类型前缀+3位序号"(A2 已 ship),**只对齐前缀语义(数字 001/002/003)+ 把 BOM 关联到编码主段**;不做 16 位分段 |
| 实现影响 | A3 全新 missing,改 BOM 关联逻辑 | 在已 ship 的编码生成上小补 |
| 工作量 | L | M |

### ✅ 推荐 B（小补，16位列 P1）
**老板自己说"编码规则无所谓,能搜到即可"** —— 16 位分段是 nice-to-have,不该阻塞 P0。前三位主编码 + BOM 关联可在现有编码上加。除非客户周五坚持要 16 位结构 → 那进 P1。**这条建议当面跟客户确认一句**("是要严格 16 位分段,还是能搜到归类就行?")。

## 决策 4 · 财务对接：接金蝶/用友 API vs 仅导凭证表

### 客户原话 (transcript-2b 行664-677)
> 行664-666: "财务软件很复杂,像**金蝶、用友**他们做十几年的东西,全部搬进来肯定不可能"
> 行667-671 (两种方式): "一个是看你们缺什么财务的东西他们实现不了的我们加;另外一个是**接他们的 API**…两个系统互通"
> 行676-677: "你只是**开发这个业务,以业务为主**"
> (别处 行710-859) 金蝶现状只用总账模块、手动录凭证;产品差异化=替客户省手动制表

### 选项
| | A · 接金蝶/用友 API | B · 仅导出金蝶表头格式凭证表 (推荐) |
|---|---|---|
| 做法 | 对接各家财务 API 双向互通 | 系统按金蝶表头格式**导出凭证/科目余额表**,客户导入;不接 API |
| 实现影响 | 依赖第三方 API + 花钱 + 维护,XL | 可配置表头 + 导出,M |
| 工作量 | XL | M |

### ✅ 推荐 B（导表）作起步，A 作后续可选
客户自己倾向最低成本(表头复用导表),且明确"不自建总账、以业务为主"。**整个财务流(H)偏后,不在 P0**。导表先解决"省手动制表"痛点,API 看后续需求再说。

## 决策 5 · 超支报警阈值口径（实现细节，告知即可）

### 客户原话 (transcript-2b 行219-268 + 行107-111)
> 行219-225: "出成率 **70%**,(能源水电人工)算到以后,**标准成本 18 块**"
> 行246-268: "(实际分摊后)最后变成 **9 块**…系统就会显示标准爆末 vs 它实际的成本,这里边**会超 5 块钱**"
> 行107-111 (另一个报警=毛利红线): "毛利率要达 10%…以毛利率为主"

> 注: 这里其实是**两个报警**: (a) 三价超支(标准成本 vs 实际成本偏差) (b) 销售毛利红线(售价 vs 成本×(1+目标毛利))。

### 选项 (仅指 a 三价超支)
| | A · 绝对值阈值(差>5块) | B · 百分比阈值 (推荐) |
|---|---|---|
| 做法 | 实际-标准 差额 > N 元 报警 | 实际/标准 偏离 > X% 报警(可配,默认如 10%) |
| 问题 | 5 块对 18 块产品和 100 块产品意义完全不同 | 跨价位可比 |

### ✅ 推荐 B（百分比，可配）
绝对值不跨产品可比;客户举的"5 块"作为该产品的**具体表现展示**即可。毛利红线(b)用**毛利率**(客户明确"以毛利率为主")。**这条偏实现细节,可在 B3 设计时定,不必客户专门拍,告知一声即可。**
