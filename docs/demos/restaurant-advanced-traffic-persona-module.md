# 餐饮高级客流画像模块记录

日期：2026-07-01

## 结论

餐饮 MVP 当前不把真实客流/人口画像作为前置依赖。真实数据通常需要客户授权和腾讯、百度、高德等供应商的商务开通，公开免费 API 只能覆盖 POI、天气、地理编码、路线、周边搜索等 proxy 信号，不能替代客流来源、停留时长、竞品重叠、人群消费力这类画像数据。

因此餐饮 demo 保留一个「高级客流画像分析」模块：

- 页面可见，明确标注「需额外开通」。
- demo 使用模拟聚合字段展示分析形态。
- 不接入真实个人轨迹，不提交任何供应商 key。
- 后期按客户、门店、商圈、项目范围开通真实数据。

## 可展示字段

腾讯位置大数据适合展示：

- 日均客流、小时客流指数
- 来源地 TopN
- 停留时长分布
- 竞品客群重叠
- 消费力指数
- 商圈/楼层客流变化

百度慧眼/百度地图适合展示：

- 区域热力和商圈趋势
- 常驻/游客拆分
- 年龄段、性别等聚合画像
- 来源城市/来源区域
- 工作日和周末客流差异

高德侧当前 MVP 更适合用作公开 proxy：

- 周边 POI 密度
- 竞品供给数
- 路况、天气、到达时间
- 交通可达性、停车压力 proxy

高德若要提供真实客流画像，也应按商务数据能力另行确认，不把普通地图开放 API 等同于客流画像。

## Demo 分析口径

以「海底捞火锅(人民广场店)」这类商圈店为例，高级模块不是只展示数据，而是回答这些经营问题：

- 商圈是否有足够外部机会，而不只看已成交 POS。
- 午市、晚市、周末分别应该如何排班、备货和设计套餐。
- 竞品是否在抢同一批客群，还是服务不同用餐场景。
- 高评分/高客单是否符合当前商圈消费力。
- 拥堵门店是否应该通过预约、候补和连锁近店分流减少流失。

## MVP 与后续边界

MVP 可用：

- 高德、腾讯、百度公开地图 API 的 POI、地理、天气和可达性数据。
- 内部 POS、会员、采购、BOM、评论采集数据。
- demo 模拟的客流画像字段。

后续付费模块可用：

- 商圈真实客流趋势。
- 来源地、人群结构、消费力等聚合画像。
- 竞品重叠、楼层热力、来源/去向分析。
- 与内部销售、排队、评价、备货、连锁分流联动的策略模型。

启用真实数据前必须确认：

- 客户授权范围。
- 数据供应商合同和计费方式。
- 只接收聚合统计，不处理个人级轨迹。
- 字段映射、更新频率、缓存策略和额度控制。
