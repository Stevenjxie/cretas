## 二、缺陷 / 逻辑漏洞（按严重度）

### 🔴 P0-1 包材库存按基本单位查不到 —— 有 10000 盒却报「可用 0」

**现象**：`成品盒` 在原料仓有 `MT-20260730-0555` 共 **10000**、`status=AVAILABLE`、无有效期，
但调拨时两种写法都拿不到：

| 传入 unit | 结果 |
|---|---|
| `box`（物料档案基本单位） | `409 原料源仓库存不足: 可用 0 box, 申请调拨 60 box` |
| `盒`（批次里实际存的字符串） | `422 调拨包装单位必须选择具体规格 TRANSFER_MATERIAL_PACKAGING_SPEC_REQUIRED` |

**根因**：`raw_material_types.unit = 'box'`，而 `material_batches.quantity_unit = '盒'`。
可用量按 `box` 精确匹配批次单位 → 匹配不到中文写法的批次。传中文又因
`transactionUnit != baseUnit` 落进"必须有包装规格"的分支。

**影响**：该物料**两条路都走不通**，等于库存不可用。同库里 `封膜`（档案 `slice`、批次 `slice`）
一次就成功 —— 差别只在单位写法是否一致。

**判据**：`material_batches.quantity_unit` 与 `raw_material_types.unit` 不一致的物料，
库存全部不可调拨。建议按这条扫全库。

### 🔴 P0-2 调拨去重只看「目标工厂 + 状态」，不看物料内容

**现象**：先建了一张只含冻猪蹄的调拨单（DRAFT），紧接着建**另一物料**的调拨单被拒：

```
409 5 分钟内已创建相同调拨 (调拨单 TRF-20260802-1103, 目标工厂 F006, 状态 DRAFT), 请勿重复提交
```

两张单**物料完全不同**，却被判为"相同调拨"。

**影响**：同一工厂 5 分钟内只能建一张调拨草稿；要备多种料只能挤进同一张单，
而同一张单里只要有一个物料触发校验（如 P0-1），**整张单失败**，无法分批推进。

### 🟠 P1 期初建账凭证号冲突，且提示指向调用方无法控制的字段

**现象**：`POST /material-batches/opening` 连续返回
`409 数据已存在，请勿重复提交`，`hintTarget: factory_id, voucher_number`。
换 `batchKey` 无效 —— 冲突在**凭证号**，而凭证号由服务端按工厂+日期生成，调用方给不了。

**影响**：同一工厂**当天只能期初建账一次**。而普通入库 `POST /material-batches` 已 `@Deprecated`
并直接抛"直接写库存已停用"，提示只能走「仓储来源任务 / 受控调整 / 期初建账」——
当期初被占用时，补货路径实际只剩下不那么直观的两条。

### 🟡 P7 包材在 BOM 里的三条隐性必填，报错分三次才凑齐

### 🔴 P0-4 同一采购订单的第二次收货永远确认不了 —— 应付按订单唯一

实走 `PO-20260707-0002`（已收 3.456kg / 待收 6.544kg，界面完整支持分批收货）：

1. 创建收货单草稿 → `RCV-20260803-5724` DRAFT ✓
2. 直接确认 → `409 确认收货前必须上传供应商供货单或收货凭证`（合理）
3. 上传凭证 → 再确认 → `409 数据已存在，请勿重复提交`，`hintTarget: factory_id, purchase_order_id`
4. **批次 0 条，货没入库**

**根因**：约束不在收货表，而在 **`ar_ap_transactions`**：

```sql
uk_aat_ap_invoice_per_po UNIQUE (factory_id, purchase_order_id)
  WHERE transaction_type='AP_INVOICE' AND deleted_at IS NULL AND purchase_order_id IS NOT NULL
```

确认收货会记应付，而**应付按采购订单唯一**。该 PO 已有一张 CONFIRMED 收货单
（`RCV-20260707-5533`，即"已收 3.456kg"），所以第二次收货一定撞唯一约束。

**影响**：**分批到货的采购订单，第二批永远入不了库**。而 UI 全程鼓励分批
（显示已收/待收、提供"少收关闭"），冲突只在最后一步暴露，且报错信息（"数据已存在，请勿重复提交"）
完全指不到真正原因（应付发票唯一），运维很难自查。

**建议**：应付发票应按**收货单**而非**采购订单**唯一，或第二次收货合并到既有 AP 发票。

### 🟠 P12 结单卡住：半成品喂出来的 WIP 批次 `material_type_id` 为空，撞 BOM 归属校验

走结单 `POST /production-plans/{id}/settle` 报：

```
409 所选原料批次不属于该生产计划 BOM   PRODUCTION_CONSUMPTION_NOT_IN_BOM
```

校验逻辑（`ProductionPlanServiceImpl:4224`）是
`eligibility.materialTypeIds().contains(batch.getMaterialTypeId())`。

而本计划的两个 WIP 批次：

| 批次 | material_type_id |
|---|---|
| `WIP-CLK-W-20260802-67662`（拆骨产出） | **空** |
| `WIP-CLK-W-20260802-52852`（卤制产出） | **空** |

原因是 `MaterializeContext.rawMaterialTypeId` 注释所述：WIP 产出的 material_type_id 必须指向
