# 第一部分 · GOAL SETTING PROMPT

## 北极星

▎**让一个餐饮老板打开它，能自己做出一个决定。**

不是「数据展示得很全」，不是「指标算得很准」。是**他看完之后知道明天该干什么**。

**取舍排序（冲突时按这个来，⛔ 不要平衡）**：

```
能不能决定  >  数字准不准  >  覆盖得全不全
```

这个排序的含义是具体的：一个「我算不出来，因为你缺 X，去做 Y 就能算」的回答，
**优于**一个精确但他看不懂怎么用的数字；而一个精确数字**优于**十个含糊的数字。

## 「做完了」的五条定义

老板（**单店** 与 **连锁**两种身份都要成立）打开之后：

1. **他想问的问题，答得上来。**
   ⛔ 不是「意图识别命中率 95%」——是**他真的那样问的时候**能拿到答案。
   连锁老板问的和单店老板问的**不是同一批问题**（他问的是「哪家店拖后腿」「要不要关店」「这家店的问题在哪家店也有吗」）。

2. **答完之后，还告诉他一件他没想到的事。**
   他问「昨天营业额多少」，除了数，还要有「⚠️ 有 3 道菜成本高于售价」这种他没问但该知道的。
   ⛔ 但**不许编**：说出来的每一条都要能点名到具体的菜/店/单据。

3. **他追问，接得住。**
   「为什么跌了？」→ 拆得出来。「那家店呢？」→ 知道「那家店」指谁。
   ⛔ 不许每一轮都当成全新问题重新开始。

4. **结果用表格给。**
   能列成表的就列表，⛔ 不要用一段话讲五个数。表格要有口径行（这个数是怎么来的）。

5. **答不了的时候，说清三件事**：**缺什么数据** · **怎么拿到** · **他自己要干什么**。
   ⛔ 不许含糊拒答（「暂不支持该查询」是失败）。
   ⚠️ 而且要诚实区分两种「答不了」：
   - **(a) 缺数据**：补了就能算 ⇒ 说「补 X，就能算 Y」
   - **(b) 方法下限**：数据齐了也只能是估的 ⇒ 说「这个数只能是估的，因为 <原因>」，
     并把「要变实需要改什么经营动作、代价是什么」说清楚**让他自己选**，⛔ 不是推着他做。

## 明确的反目标（做到了也不算分）

- ⛔ 覆盖率数字好看但没人能据此决定
- ⛔ 为了「能答」而编数、而降级、而给一个看不出可信度的答案
- ⛔ 加一个天天误报的提示 —— **它烧掉的是信任，而「敢说不准」这件事的全部本钱，就是每一句都站得住**
- ⛔ 为「只有种子数据支持的形状」建检测器 —— 那是在建幻觉

## 判据（怎么算验收通过）

**不是**跑分，是**逐条读**：

- 一批**真实老板问句**（单店 + 连锁各一批），逐条读回答，标三态：
  `能决定` / `看得懂但不足以决定` / `答不上或答错`
- 每一条「答不上」都要能归到一类：缺数据(a) / 方法下限(b) / **产品缺陷** —— 第三类才是要修的
- **归类本身要有证据**，⛔ 不许从代码推。判「某能力不存在」必须真跑一次
