# 一、GOAL SETTING PROMPT

> 复制这一段作为目标定义。它回答「什么算做完」，不回答「怎么做」。

## 目标（一句话）

**让工人在手机上报完一道工序之后，下一道工序立刻领得到料 —— 并且这件事在生产环境里被真的走过一遍证明过。**

## 背景（不要重新推导，这些是实测结论）

- 客户原话：「上工序不报工，下工序就没有库存，而且经常漏报工。」
- 2026-08-16 F006 受控走查实测把定性改了：**就算他一次不漏报，这条链现在也走不通**。
  - 一次产量报工把**整个批次**置 `COMPLETED`（`planned_quantity=0` 让 `actual >= planned` 恒真），后续工序 409。
  - 报工产出**不进半成品库存**；领用**即时扣**、产出**等审批** —— 不对称。
  - **小结完全不读 App 报工**（`InterimSettleServiceImpl` 里 `production_reports` 引用 0 次）。
- 设计与实施：`docs/superpowers/specs/2026-08-16-工序报工实时入库-design.md`、
  `docs/superpowers/plans/2026-08-16-工序报工实时入库.md`
- 已合并：#2721 #2722 #2724 #2725（#2727 待处理）

## GOAL ACHIEVED 的判据（全部满足才算）

### A. 端到端真的走通（最高优先，其余都建在它上面）

1. 改动**已部署到 prod**，且在**运行中的制品**里验到本次改动的标记
   （⛔「`DEPLOY_EXIT=0`」和「制品里 grep 到字符串」都**不是**判据 —— 找到标记 ≠ 它能跑）。
2. 在 **F006** 上按**真实产品路径**把这条链**真的走一遍**：
   工序任务 → 签到 → 报工（第②道）→ **立刻**查第③道可领量 → 报第③道 → 批次完工。
3. 每一步贴**原始响应**与**数据库读数**；每卡一次记一条。
4. 走完**冲销**（软删除 / 状态还原），事务内带硬断言，并有**阴性对照**（其他租户零变动）。

### B. 双端 E2E

5. **RN**：用 **Expo Web** 真跑报工屏，不是单测 mock。
6. **web-admin**：用 Playwright E2E（headed，按 `playwright-headed-mode` 规则）。
7. 两端都要覆盖：正常路径 + 至少一条**会被拦住**的路径（超领 / 无网络 / 下游已出厂）。

### C. UI 审计（Steve 明确要求）

8. **减少解释性文案，让操作变简单。**
   - 一屏一个主操作；副操作降级。
   - ⛔ 不要为了「防呆」堆一大段说明 —— 防呆是**事先拦住**（禁用按钮、预填、`max` 绑定），
     不是**事后解释**。
   - 错误文案两句话封顶：**发生了什么 + 下一步点哪**。
   - 工人语言：说**半成品名称**（「猪蹄碎肉 可领 4.5kg」），⛔ 不说「第②道产出的」、
     不出现 `CLK-SEMI-…` 这类内部编号。

### D. 对抗性审计（反复做，直到调不出毛病）

9. E2E 通过之后，**对自己的实现和交互做对抗性审计**，两个维度都要：
   - **逻辑毛病**：恒真断言、判据用了必然成立的条件、两份实现漂移、
     「产出端有了消费端收不到」、事务边界、并发、幂等。
   - **使用毛病**：低技术素养用户会不会卡住、会不会误解、会不会点错、
     离线/失败时会不会以为成功。
10. 每轮审计**必须产出发现**；连续两轮**调不出新毛病**才算收敛。
    ⛔ 「这轮没找到」不等于「没有」—— 换一个角度再来（换角色、换失败注入点、换数据形状）。

### E. 收口

11. 全部改动**已合并到 main 且已部署**，⛔ 不留只在本地/分支上的成果。
12. 台账与交接件更新；产品决策各留一张设计卡。

## 硬边界（触到就算没完成）

- 🔴 **没有在生产上真的走过一遍 ⇒ 不算完成**，无论测试多绿。
- 🔴 **每条新断言必须变异实测红过一次**，且**先证明变异落地**再读红绿。
- 🔴 **不许把推理当已验证** —— 这条今晚栽了四次（余额一样 / 锚粒度 / 成本口径 / 待小结投料），
  最后一次差点做出**假财务凭证**。写下「我想知道 X / 我实际在量 Y」并排读一遍。
- 🔴 **发现 spec 写错了就订正 spec**，⛔ 不要照着错的做（Task 5 就是这么停下来的）。

# 二、WORKING PROMPT

> 复制这一段作为工作方式。它回答「怎么做」。

## 你的权限

- ✅ 部署 prod、合并 PR、对 **F006** 真实写入与删除、冲销
- ✅ 自行做产品决策 —— **以长期为准**，不要为了这次好过而选短期方案
- ✅ 遇到设计分歧自己拍板，**但必须留一张设计卡**（`docs/decisions/YYYY-MM-DD-<主题>.md`），
  写清：判断是什么、依据的读数、被否掉的方案和理由
- ⛔ 只碰 **F006**，其他租户零写入（每次冲销都要有阴性对照证明这一点）

## 工作循环（不要停，一直转到收敛）

```
① 部署 → 在运行中的制品里验到标记 → 真跑一次那条路径
② 合并（CI push run 必须 success 才合）
③ E2E：RN(Expo Web) + web-admin(Playwright headed)，真实写入
④ 冲销（事务内硬断言 + 阴性对照）
⑤ 对抗性审计（逻辑 + 使用两个维度）
⑥ 有发现 → 回 ①；连续两轮无发现 → 收敛
```

⚠️ **顺序不能换**：先部署合并、再走 E2E、最后冲销。
⛔ 不要「本地测好了再上」—— 本地绿证明不了生产上能跑。

## 每一步的判据

| 步骤 | 判据 | ⛔ 不是判据 |
|---|---|---|
| 部署 | 进程启动时间晚于制品 mtime **且** 真跑一次那条路径拿到预期产出 | `DEPLOY_EXIT=0`、`RELEASE_FINAL_STATUS`、grep 到字符串 |
| 合并 | push run `completed/success`（⚠️ 本仓 CI **没有** `pull_request` 触发，看 push run） | PR 页面上那个绿 |
| E2E | 每步贴原始响应 + 数据库读数；卡住就记一条 | 「跑完了没报错」 |
| 冲销 | 逐项核对回基线 + 阴性对照断言其他租户为 0 | 「我删掉了」 |
| 审计 | 本轮**找到了什么** | 「看了一遍没问题」 |

## 不许做的事

- ⛔ **不在主工作目录干活**（它停在落后分支且被多 session 共享）。每件事开独立 worktree，
  永远 `off origin/main`；squash 合并后**必须重开分支**。
- ⛔ **不用 `git restore` / `git checkout` 抹掉未提交的修复** —— 变异前先 commit（今晚被抹过一次）。
- ⛔ **不为了让测试变绿改产品** —— 阳性对照红了先查夹具（今晚就是夹具不够，不是产品坏）。
- ⛔ **不为了「看起来在推进」留一个把套件搞崩的改动** —— 试三次更糟就回退并**登记坏法**。
- ⛔ **不用文本 grep 数结构**，用 AST（本仓在这上面栽过三次，每次的修法都是收窄正则，然后又长出来）。
- ⛔ **同一时刻只允许一个 prod 部署**。

## 卡住时怎么办

**自己决定，不要停。** 判断顺序：

1. 这个不确定性**挡不挡住别的工作**？不挡 → 先做别的，回头再说。
2. 挡住了 → 有没有**能查的读数**？有 → 去查（数据库、日志、真跑一次）。
3. 查不出来 → **选长期正确的那个方案**，写设计卡说明依据，继续。
4. 只有**「任何选择都可能造成不可逆损害」**时才停下问 —— 例如动别的租户的数据。

## 每轮必做的三件小事

1. **清孤儿进程再量**：跑全量/A_B 之前先清 node/java 残留
   （今晚留了 90 个 node 进程 4.2GB，导致 `ENOMEM` 假失败）。
2. **基线当场重跑**，⛔ 不引用交接件或记忆里的数。
3. **报数带口径**：两个数相同不代表是同一件事。

## 收敛的定义

连续**两轮**对抗性审计**调不出新的逻辑毛病和使用毛病**，且 GOAL ACHIEVED 的 12 条判据全绿。
那时写总结给 Steve：**改了什么 / 哪条断言在守它 / 变异红过没有 / 上线了没有 /
在运行的东西里验到没有 / E2E 走通没有 / 审计发现了什么**。
