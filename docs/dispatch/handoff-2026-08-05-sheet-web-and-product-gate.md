## 4. 🔴 我自己四次判据失误（下一个 session 请直接复用这些教训）

1. **CRLF 全文件重排** —— 用 python `io.open(...,'w')` 写 Java 文件，Windows 默认换行转换把 LF 变成 CRLF，commit 一度是 2300 增/2065 删（实质只有 268/33）。另一次相反：Edit 工具把 main 上**混合行尾**的 `list.vue`（749 CRLF + 748 LF）整体归一成 LF，diff 变 1510 行。
   → **改文件前先量行尾；用二进制写；提交前对比 `--ignore-all-space` 与原始 diff 是否一致**。
2. **假变异** —— 给领料守卫做变异，测试红了，但读报错发现红的原因是「批次不存在 400」，那是**我测试自己没铺库存造成的产物**，证明不了守卫拦住了什么。补上库存重做，才拿到真 oracle：`Expected BusinessException to be thrown, but nothing was thrown`。
   → **变异变红还不够，要读红的原因**。
3. **源码 grep 断言对「合并」是沉默的** —— 产品页两把权限闸写在 SFC 的 computed 里，用 grep 断言。把两把闸合并成一把后 **8 条断言全绿**（合并后两个模块名仍都在文件里）。把判据抽成纯函数并注入 `canWrite`，同一变异才真的变红。
   → **抽函数不一定是为了复用，可能只是为了可断言**。
4. **`grep -l | head -1` 抓到旧产物** —— 核对部署时，Web 目录保留 24h 内的历史 chunk，`head -1` 抓到今早那份，于是得出「#2293 没上去」的错误结论，差点去查发布链。
   → **目录里有历史产物时，必须按本次部署的 mtime 筛，或从 `index.html` 反查真正被引用的入口**。

另有一次被测试当场纠正：写权限用例时拿 `operator` 当「只读角色」反例，测试判红 —— operator 其实 `production` 可写，拿它做例子会让断言恒真。换成仓管才是真反例。
