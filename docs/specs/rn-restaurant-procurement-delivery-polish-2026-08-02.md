# 餐饮 RN 采购确认送货体验打磨

## 范围

- 调整餐饮采购经理路径中的“采购确认送货”页面，并补齐餐饮管理员管理栈中的同页路由。
- 不修改被工厂管理员、工厂仓管复用的 `SupplierDeliveryCreateScreen`、`SupplierDeliveryDetailScreen` 与仓管导航。
- 不修改后端接口、生产数据、角色权限或价格权限规则。

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

餐饮门店采购负责人 — 中低技术熟练度 — 在手机上把已审批报货转成供应商送货草稿，并交给后续验收人员处理。

### 用户旅程

| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|---|---|---|---|
| 1 | 已审批报货卡片，显示报货单号、食材项数和预计到货日 | 选择一张报货单 | 明细自动带入，不展示档口或食材内部 ID |
| 2 | 供应商名称输入框与匹配结果 | 输入名称并选择供应商；未匹配时保留真实名称 | 页面明确显示已匹配状态，不要求用户填写供应商 ID |
| 3 | 每行食材名称、候选食材、数量和单位 | 搜索并点选食材，填写数量 | 点选后锁定正确主数据；重新改搜索词时旧选择立即清除 |
| 4 | 报价照片、语音联系记录 | 按需上传或录音 | 上传状态明确，上传未结束时说明暂不能提交 |
| 5 | 页面底部唯一主操作与提交前提示 | 点击“生成送货单草稿” | 只在供应商、食材、数量完整时可提交；错误保留全部输入并给出下一步 |

### 摩擦点清单

| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|---|---|---|
| F1 | 页面要求或展示供应商 ID、档口 ID，普通用户无法理解 | 高 | 防呆 Rule 2、自由文本改约束选择 |
| F0 | 餐饮超级管理员从采购订单点击送货确认入口后，目标路由未注册，页面不可达 | 高 | 防呆 Rule 5、真实可达性 |
| F2 | 修改食材搜索词后仍可能携带上一次选择的 `rawMaterialTypeId` | 高 | 防呆 Rule 1、错误预防 |
| F3 | 报货行缺名称时以食材内部 ID 兜底显示 | 中 | 防呆 Rule 2、上下文业务化 |
| F4 | 提交按钮只在请求中禁用，表单缺项要到提交后才知道 | 中 | 防呆 Rule 1、提交前边界 |
| F5 | 食材候选点击区域偏小，选中状态不清楚 | 中 | 44pt 点击目标、状态反馈 |

### 每个摩擦点的设计回应

- F0 → 只在 `isRestaurantMode` 条件分支注册餐饮采购确认送货路由；工厂管理员仍不注册该餐饮页面。
- F1 → 供应商改为名称搜索与候选卡片；允许未匹配名称按名称保存，但不显示或要求填写 ID。报货卡片只显示业务单号、食材项数和到货日。
- F2 → 任何食材搜索文字变化都同步清空旧主数据 ID，必须重新点选候选才能提交。
- F3 → 优先使用报货行名称，其次使用已加载食材主数据名称，最终显示“未命名食材”，绝不把内部 ID 当名称。
- F4 → 页面持续显示一条具体的提交阻塞原因；主按钮仅在供应商、至少一条有效食材明细及附件上传状态都满足时启用。
- F5 → 候选项使用有按压反馈的 44pt 以上卡片，并显示明确的已选择提示。

## 验收标准

- 餐饮页面源代码不再渲染“供应商 ID”或 `requesterDeptId`。
- 餐饮超级管理员可从“管理 → 采购订单 → 送货确认”进入页面；该路由仅在餐饮模式注册。
- 报货行缺名称时不显示 `materialTypeId`。
- 修改食材搜索词会清空已选主数据标识；只有重新选择候选后才能提交。
- 提交按钮前置禁用并显示具体阻塞原因，上传中也不可提交。
- 目标 Jest、TypeScript 基线检查、`git diff --check` 通过。
- Expo Web 使用餐饮账号完成只读页面验收；除登录外不发送业务写请求，实际业务写入为 0。
