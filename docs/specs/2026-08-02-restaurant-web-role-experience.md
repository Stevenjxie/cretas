# 餐饮 Web 四角色体验打磨契约

日期：2026-08-02
状态：第一批已实现，待发布
范围：餐饮老板、店长、采购、厨师长；运营、市场、人事、财务；餐饮 AI 与数据分析。

## 1. 体验目标

用户登录后 10 秒内应能回答三件事：我今天负责什么、哪条数据最值得先看、下一步去哪里完成。高级感来自信息层级、真实数据、明确状态和更短路径，不来自渐变、装饰性大卡片或虚构图表。

设计方向采用两套相容表情：日常业务页为 host-native operational，强调紧凑、明确和可执行；数据与 AI 为 analytical editorial，强调结论、口径、上下文与证据。两者只使用现有 Element Plus、全局 CSS token、图表主题和权限 store。

## 2. 角色与部门职责

| 角色 | 可做 | 不可做 | 主要交接 | 默认关注 |
|---|---|---|---|---|
| 餐饮老板 | 四部门读写、经营决策、查看价格 | 不替代系统审批与操作确认 | 店长、采购、财务 | 全局营收、毛利、门店差异、异常 |
| 餐饮店长 | 运营/市场/人事执行，财务只读 | 不修改财务口径 | 老板、采购、厨师长 | 今日营运、目标、客流、排班 |
| 餐饮采购 | 运营执行、采购链路、财务只读 | 不进入营销/人事，不做财务审核 | 厨师长、店长、财务 | 报货、到货、价格异常、对账 |
| 厨师长 | 报货、领料、验收入库、后厨运营 | 不看采购价格，不进入营销/财务 | 采购、店长 | 领料、损耗、盘点、配方 |

部门页不是四套孤岛：老板可跨部门决策，店长负责运营协同，采购和厨师长只看到职责内入口。每个页面必须说明职责、可执行动作和交接对象，不能只显示标题。

## 3. 菜单与导航

- 顶级“餐饮运营”保留四部门驾驶舱与日常业务路径；部门项继续由 module 权限单一门控。
- “数据与分析”保留所有餐饮角色都能使用的经营驾驶舱和 AI 问答；经营分析、收入报表、AI 经营体检及数据管理按餐饮角色单独裁剪。
- 菜单裁剪必须只在 `factoryType=RESTAURANT` 时生效，不得影响工厂角色。
- 菜单隐藏与路由直达必须使用同一餐饮角色约束，避免“看不见但可手输 URL”。

## 4. AI Product Contract

### 4.1 目的与边界

AI 是餐饮经营的解释、诊断和决策助手，必须调用大模型；确定性工具负责取数、计算与权限裁剪，大模型负责理解问题、澄清上下文、综合解释和给出建议。AI 不以模型猜测替代真实指标，不在咨询模式执行写操作。

### 4.2 输入、输出与角色化

- 输入：自然语言问题、当前租户、会话上下文、明确的角色权限；入口可携带部门推荐问题。
- 输出：先结论，再证据/口径，再建议与继续追问；不具备的维度明确写“无法计算/尚未接入”。
- 老板/店长优先经营决策；采购优先报货、供应商、成本异常；厨师长优先领料、损耗、盘点和菜品。
- 页面不得把采购或厨师长统一称为“老板”。

### 4.3 状态模型

`idle → composing → routing/reading → answering → answered`；异常进入 `clarification`、`honest-empty`、`permission-blocked`、`timeout/retry` 或 `error`。操作意图在咨询模式进入 `read-blocked`，在操作模式必须经历 `preview → confirm → execute → receipt`。

### 4.4 信任与控制

- 持续显示当前租户数据范围、会话上下文和读写模式。
- 真实数值由业务工具提供；大模型生成解释和建议，两者在文案上可区分。
- 清空对话和新话题语义不同；新话题清上下文但保留可见记录。
- 金额字段遵循价格权限；无权限显示“—”并解释，不显示 0 或空列。
- 错误不走伪造 fallback；提供重试或下一步。

## 5. 部门驾驶舱模块

顺序固定为：职责与数据上下文 → 关键指标带 → 趋势与一句话结论 → 明细/诚实空态 → AI 诊断 → 功能入口与交接。无数据时收起大面积空画布，保留原因、口径和可执行下一步。

KPI 使用 tabular numbers；第一指标是视觉主值，其余指标同级紧凑排列。趋势图必须有标题、单位、实际覆盖期和由数据确定性计算的一句话结论；不得推断天气、活动等数据未提供的原因。

## 6. 视觉系统

- 颜色：全局 `--color-primary`、Element Plus semantic colors、现有部门 accent 仅作细线/状态点，不整页染色。
- 字体：系统无衬线；数字 `font-variant-numeric: tabular-nums`。不引入展示字体。
- 密度：桌面主内容 20–24px 间距，KPI 内部 12–16px；减少嵌套卡片和大面积空白。
- 形态：8–12px 圆角，1px 边框，阴影只用于层级浮起；无渐变、无装饰光球、无 `transition: all`。
- 响应式：1536、1024、768 三档；窄屏操作优先于完整列宽，按钮保留可见文本/aria-label。
- 动效：只对颜色、阴影和 transform 做 150–200ms；尊重 `prefers-reduced-motion`。

## 7. 验收清单

- 四角色首页标题、主动作、价格展示和部门入口与权限矩阵一致。
- 四角色餐饮菜单/数据菜单无空组、无越权项；直达路由同样拦截。
- 部门页有职责、口径、实际数据/诚实空态、AI 与交接；无空白大图表。
- AI 快捷问题、标题、placeholder 按角色变化；咨询/操作、上下文、真实数据与大模型职责清楚。
- 目标 Vitest、类型检查和生产构建通过；无 `transition: all`、无横向溢出、键盘焦点可见。
- 生产只读验收只登录和导航，不发送 AI、不触发业务写；`actualBusinessWrites=0`。
