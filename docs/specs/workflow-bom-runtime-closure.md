# Workflow + BOM 运行时闭环

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

仓管员 — 熟悉实物与批次，但不应理解 DAG、Workflow revision 或 BOM Family — 在手机或管理端按生产报工事实确认成品入库。

### 用户旅程

| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|---|---|---|---|
| 1 | 待入库计划、单号和每个终端 SKU 的批次/报产量/单位 | 打开待确认单 | 不出现空白页，不把 kg、盒等混成一个总数 |
| 2 | 每条终端产出的明确上限 | 核对或填写逐行实收 | 默认等于报产量，不能超过对应行上限 |
| 3 | 唯一主按钮“确认入库” | 提交一次 | 同一幂等键只过账一次，每条产出生成自己的成品批次 |
| 4 | 成功结果或可执行错误 | 返回列表或修正原输入 | 成功后消失；失败时保留已填值并提示如何解决 |

### 摩擦点清单

| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|---|---|---|
| F1 | 多产出被压成一个数量，混合单位相加 | HIGH | Rule 1 / 信息密度 |
| F2 | 显示 raw owner 名称而非实际终端 SKU/批次 | HIGH | Rule 2 |
| F3 | 后端要求 output lines，但页面只发 scalar | HIGH | Rule 1 / Rule 5 |
| F4 | 重试生成重复入库 | HIGH | Rule 4 |
| F5 | 失败后清空已核对数据 | MED | 错误恢复 |

### 每个摩擦点的设计回应

- F1 → 单位相同才显示兼容总数；混合单位只显示逐行卡片和逐行输入。
- F2 → 每行固定显示 SKU、批次、报产上限和单位，确认按钮前可目视复核。
- F3 → RN、Web 和 Mobile API 统一提交 `outputLines`；旧单产出继续兼容 scalar。
- F4 → 打开确认页时生成并复用稳定幂等键，提交中禁用主按钮。
- F5 → 网络或业务失败保留表单值，显示后端原始原因与下一动作，允许直接重试。

### 交互门禁

- 当前每条实收量必须大于 0 且与对应报产量一致；有差异时先退回生产修正报工，避免在仓库端猜测分摊。
- Workflow 结单必须完整覆盖计划固定的终端 SKU 集合，缺一条、多一条或单位不符均禁止入库。
- 原料领用按 pinned revision 的物料节点 + 输入端口校验；中间品 SKU 不冒充终端归属，共享原料保持 BOM Family 归属。
- 混合单位时 `actualFinishedQuantity`、计划 `actualQuantity`、仓库总实收与总单位均保持空值，逐行台账是唯一数量真值。
- 旧 Workflow 计划若缺失可证明的 revision/BOM authority，禁止猜测回填或降级成 Legacy：未开始/进行中计划在核对无扣料后重建；已结单或待入库计划先人工核对扣料、成本、结单和成品库存，禁止直接重建造成双扣。
