# 包装标签拍照质检冷启动规格

## 目标与边界

首版支持质检员在 RN 手机端录入 SKU、批次号、生产日期并拍摄多张包装照片。服务器使用现有视觉模型路由进行高召回初筛，定位“疑似缺白标”“疑似缺彩标”区域；Web 端由人工逐张审核、纠错或补画漏检框。人工审核结果是最终真值，同时沉淀为后续 YOLO 训练数据。

首版不识别标签文字是否正确，不自动放行批次，不在服务器训练 YOLO，不把 AI 未报异常等同于人工合格。图片不清晰、遮挡严重或模型失败时必须进入人工审核，不得静默判定正常。

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

- 现场质检员：手持手机、戴手套、操作时间短；需要大点击区、少输入、失败后可继续。
- 质量主管/审核员：在 Web 上集中查看一批照片；需要始终看到 SKU、批次、日期、拍摄人和 AI 来源，并能快速纠正误报与补漏。
- 模型维护人员：需要从已审核数据中导出原图、归一化框、最终标签及模型版本，且能追溯 AI 原始判断。

### 用户旅程

| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|---|---|---|---|
| 1. 创建拍检 | SKU、批次号、生产日期三项核心上下文 | 选择 SKU，输入批次，确认日期 | 未填或格式错误时就地说明，不能进入拍照 |
| 2. 拍照 | 构图提示、照片计数、缩略图 | 连续拍 1–6 张，删除或重拍 | 每张照片能看清盒体边缘与标签区域 |
| 3. 上传 | 明确的逐张进度与唯一主操作 | 点击“提交拍检” | 重复点击不产生重复任务；失败保留全部数据并可重试 |
| 4. AI 初筛 | “AI 正在初筛，最终以人工审核为准” | 返回任务列表或继续工作 | 服务器异步处理，失败也进入人工审核 |
| 5. Web 审核 | 队列、上下文卡、原图、AI 疑似框 | 将候选改为缺白标/缺彩标/正常误报/无法判断，或补画漏检框 | 每个候选都有人工结论；漏检可被补录 |
| 6. 完成审核 | 审核摘要与风险提示 | 点击“完成审核” | 任务锁定为已审核，记录审核人、时间和最终真值 |
| 7. 训练导出 | 已审核任务筛选和导出说明 | 导出训练清单 | 只导出人工确认的标注，保留来源和版本 |

### 摩擦点清单

| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|---|---|---|
| F1 | SKU、批次、日期输错会让照片无法追溯 | 高 | 防呆 R1/R2/R3 |
| F2 | 堆叠、反光、遮挡导致模型和人工都难判断 | 高 | 防呆 R1/R5；RN 拍照规范 |
| F3 | 网络失败或重复点击造成照片丢失/重复任务 | 高 | 防呆 R4/R5；RN 网络错误 |
| F4 | 用户把 AI 未发现异常误认为已经放行 | 高 | 明确人工门禁 |
| F5 | 只允许改 AI 框会漏掉模型没有发现的问题 | 高 | 冷启动纠错闭环 |
| F6 | 直接自由文本标注容易产生不可训练的脏标签 | 中 | 防呆 R3 |
| F7 | 审核时看不到 SKU/批次上下文，可能审错任务 | 高 | 防呆 R2 |

### 每个摩擦点的设计回应

- F1 → SKU 使用受控选择；批次和日期提交前验证；拍照页、上传页、审核页持续显示同一上下文。
- F2 → 相机页固定显示“每盒露出标签边、减少堆叠、避开反光”的三条提示；模糊或不可判定统一输出“无法判断”。
- F3 → 客户端生成幂等键；先创建草稿任务再逐张上传；上传失败保留表单和照片，提供显式重试。
- F4 → 所有未人工完成的状态都显示“待人工审核”；AI 的正常结果同样进入待审队列。
- F5 → Web 图片支持拖拽补画矩形，并要求选择缺白标、缺彩标或无法判断。
- F6 → 人工结论只允许 `MISSING_WHITE_LABEL`、`MISSING_COLOR_LABEL`、`NO_DEFECT`、`UNJUDGEABLE` 四类；备注为可选补充，不参与训练标签。
- F7 → 审核页顶部固定显示 SKU、批次、生产日期、拍摄人、照片序号和模型/提示词版本。

### Web 人工审核防呆补充（2026-07-26）

| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|---|---|---|
| F8 | 低高度办公屏幕中“本图结论”落在独立滚动区下方，审核员不知道还要滚动 | 高 | 防呆 R1/R5；当前步骤信息不得隐藏 |
| F9 | “整图正常”会批量拒绝当前图全部 AI 疑点，误点后直接影响训练真值 | 高 | 防呆 R1/R4；危险批量动作必须预告影响 |
| F10 | 被拒绝的 AI 框立即消失，缺少可见撤销路径 | 高 | 错误恢复；用户动作必须可逆 |
| F11 | 审核抽屉关闭会销毁未提交草稿，用户没有防丢提示 | 高 | 防呆 R5；错误后保留已填数据 |
| F12 | 未完成本图时普通“下一张”仍可点击，用户可能误以为已经完成 | 中 | 单屏唯一主操作；当前步骤完成后再前进 |

- F8 → 右侧只让“当前疑点”区域内部滚动；“本图结论”固定在右侧底部并始终位于整单导航上方。
- F9 → 当本图仍有 AI 候选时，点击“整图正常”必须明确显示将拒绝的候选数量并二次确认。
- F10 → 右侧持续显示“已拒绝 AI 疑点”摘要，允许在整单提交前逐个撤销并重新判断。
- F11 → 维护本地 dirty 状态；关闭审核工作台前弹出“继续审核 / 放弃草稿”，没有改动时直接关闭。
- F12 → 本图未完成时主导航改为“请先完成本图”，按钮禁用；用户仍可从左侧照片队列显式查看其他照片，最终提交继续要求所有照片完成。

## 信息架构与状态

### RN

`质检首页 → 包装标签拍检 → 基本信息 → 多图拍摄 → 上传进度 → 已提交`

- 每屏只有一个主操作。
- 创建页展示 SKU、批次号、生产日期。
- 拍照页允许 1–6 张，缩略图可删除，提交前再次确认上下文。
- 结果页只表达“已进入审核”，不表达“合格”。

### Web

`质量管理 → 标签拍检审核 → 待审列表 → 图片审核 → 完成审核`

- 默认优先显示 AI 疑似异常和分析失败任务。
- 审核页面左侧为照片与归一化框，右侧为候选结论。
- AI 候选可改为误报；人工可新增候选框；所有结论完成后才允许提交。

### 状态机

`DRAFT → UPLOADING → QUEUED → ANALYZING → NEEDS_REVIEW → REVIEWED`

任何单图分析失败仍进入 `NEEDS_REVIEW`；任务级不可恢复错误使用 `ANALYSIS_FAILED`，并提供重新分析。提交、重试和审核接口均须幂等。

## 数据契约

### 任务

- 工厂、SKU ID/编码/名称快照、批次号、生产日期。
- 创建人、幂等键、状态、照片数、AI 异常数、最终异常数。
- 审核人、审核时间、创建/更新时间。

### 照片

- 任务 ID、附件 ID、顺序、宽高。
- 分析状态、模型、提示词版本、结构化 AI 候选及错误信息。

### 标注

- 照片 ID、来源（`AI`/`HUMAN`）、归一化框 `xMin/yMin/xMax/yMax`。
- AI 标签/置信度/证据与人工标签/备注并存，禁止人工结论覆盖 AI 原始数据。
- 训练导出只使用已审核后的最终标签；`NO_DEFECT` 作为负样本记录，不生成缺陷框。

## 视觉初筛策略

- 不使用 OCR；只判断白标和彩标是否存在。
- 对原图做固定重叠切片，保证堆叠边缘有足够像素；每个切片调用现有 `SLOT.VL` 路由。
- 提示词强调“宁可多报、不可漏报”，并要求只返回结构化 JSON。
- 模型无法可靠给出像素级框时，使用切片在原图中的归一化矩形作为候选区域；人工负责最终确认和补框。
- JSON 解析失败、超时或模型拒答一律生成 `UNJUDGEABLE` 候选，不得当成正常。

## API 摘要

- RN：创建任务、登记照片、提交分析、查询任务详情/列表、重试。
- Web：分页查询审核队列、读取含临时图片地址的详情、提交全量人工审核。
- 训练：按审核时间范围导出只读 JSON 清单，包含图片引用、最终框、最终标签、SKU/批次和来源。

## 验收标准

- 冷启动示例的已知异常能够进入候选区域；正常图即使误报，也可在两次点击内改为“正常（AI 误报）”。
- AI 未报异常时，人工仍能补画框并提交缺白标/缺彩标。
- 分析失败不会丢照片，不会自动判正常。
- 多次点击提交不会创建重复任务；跨工厂不可读取或审核。
- 审核后的 AI 原始结果与人工真值可同时查询，训练导出只返回人工真值。
- RN 和 Web 都能在主路径持续看见 SKU、批次和生产日期。
