## 目标

基于当前 React Native 质检员页面和 Web 管理端的真实操作流程，制作一份可在手机和桌面浏览器阅读的截图操作指南。指南从管理员按手机号建立工厂白名单邀请、预设角色权限、员工本人验证邀请并设置密码开始，覆盖手机号登录、首页待审核入口、录入批次、拍照、提交 AI 初筛、逐图人工审核，以及 Web 已审核数据的备份、软归档、恢复和技术管理员训练确认。不得自动训练或发布模型。

## UX Flow Analysis

### 用户画像

- 主要用户：工厂 QC 质检员和承担复核工作的质检员，手机操作，技术熟练度低到中等。
- 现场环境：生产现场，可能戴手套、光线复杂、网络不稳定、操作时间短。
- 核心目标：让每个 SKU、批次和生产日期的照片都得到逐张人工结论，并把确认、拒绝和补框结果沉淀为训练真值。
- 安全边界：AI 只负责初筛；AI 未发现异常不等于自动合格，人工未完成逐图确认时不得提交最终审核。

### 用户旅程

| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|---|---|---|---|
| 0 | Web 人事“账号邀请” | 管理员填写手机号、姓名并选择“质量检验员” | 建立只属于当前工厂的白名单邀请 |
| 0.1 | App “注册用户” | 员工验证同一手机号，核对工厂和受邀角色 | 邀请身份不可由员工修改 |
| 0.2 | App 设置密码 | 员工本人输入并确认密码 | 账号以手机号登录；管理员不接触明文密码 |
| 1 | App 启动页和登录表单 | 使用白名单手机号和本人密码登录 | 进入“质检工作台” |
| 2 | 质检首页首屏 | 有待审任务时点击“待我审核”；需要拍检时点“发起标签拍检” | 不向下寻找即可进入对应任务 |
| 3 | 新建拍检表单 | 选择 SKU，填写批次号和生产日期 | 三项追溯信息准确绑定 |
| 4 | 取景/照片缩略图 | 拍摄或选择 1–6 张清晰照片 | 每盒标签边缘尽量可见 |
| 5 | “提交拍检” | 再次核对信息后提交 | 任务进入上传、排队和 AI 初筛 |
| 6 | “待我审核”列表 | 点击状态为“待人工审核”的任务 | 打开逐张人工审核 |
| 7 | 照片上的橙色 AI 框 | 逐个“确认”或“拒绝疑点” | 每个 AI 疑点都得到人工结论 |
| 8 | 照片空白处 | 轻点漏检位置新增框，选择缺白/缺彩/不清 | 人工漏检补框被记录 |
| 9 | 已选中的人工框 | 拖动移动、右下角缩放；必要时删除 | 框尽量贴近问题盒和缺标位置 |
| 10 | 整张照片和“给出本图结论” | 再检查全图，确认本图标注无误或整图正常 | 当前照片计入已完成 |
| 11 | 顶部照片缩略图与底部按钮 | 点“下一张未审核”，重复逐图检查 | 所有照片都达到已完成 |
| 12 | “提交人工审核” | 最后核对后提交 | 服务端保存人工真值，任务进入已完成 |
| 13 | Web“已审核整理” | 下载 JSON 备份或执行软归档 | 数据不物理删除，归档记录可恢复 |
| 14 | 技术管理员训练确认 | 复核人工真值后批准或拒绝 | 只有批准数据可进入训练导出；不会自动训练或部署 |

### 每个摩擦点的设计回应

- F1 → 用连续两张截图拆开“启动页登录”和“表单登录”，不公开账号密码。
- F2 → SKU、批次、日期在创建页和审核页顶部持续展示；提交前按三项逐一复核。
- F3 → 单张建议 8–15 盒，每盒露出标签所在边缘，避开顶灯反光；看不清就补拍。
- F4 → 任务页固定写明“AI 先找疑点，人工逐图给最终结论”；0 个疑点仍需给出本图结论。
- F5 → 在旧流程“等待人工审核”后明确新增“待我审核”入口和任务卡截图。
- F6 → 照片上方固定展示“轻点空白处补框 · 拖动框移动 · 右下角缩放 · 双指放大照片”；指南逐条解释手势。
- F7 → 新增框时显示类型菜单；选择问题类型后菜单收起为小标签，再点小标签可重新编辑。
- F8 → AI 框全部确认/拒绝、人工框全部选类型后，才出现“给出本图结论”。
- F9 → “上一张”和当前主按钮固定在底部；未完成时显示“请先完成本图”，完成后变为“下一张未审核”或“提交人工审核”。
- F10 → 上传失败优先点击“重试提交”；审核保存失败保留当前草稿，检查网络后重试，不重新建立批次。
- F11 → 管理员仅填写白名单手机号、姓名和角色；员工验证同一手机号后核对工厂/角色并自行设置密码。
- F12 → 已审核数据默认训练状态为“待技术确认”；归档不删除，训练导出只选择已批准记录。

## 当前操作流程真值

1. 管理员从 Web 人事模块的“账号邀请”填写手机号、姓名和“质量检验员”角色；邀请即当前工厂白名单，员工不能自行更换工厂或提权。
2. 员工从 App 登录页点击“注册用户”，验证相同手机号，核对受邀工厂/角色，再由本人设置密码；以后账号填写手机号，密码填写本人所设密码。
3. 管理员不会发放、查看或在指南中保存明文密码；忘记密码必须走“忘记密码”，不得重复创建同手机号账号。
4. 质检员登录后进入角色专属底部导航：首页、质检、记录、分析、我的；导航为安全区预留空间，窄屏不裁字。
5. 首页首屏优先显示“待我审核”，可一键进入待审队列；“发起标签拍检”进入 `QILabelQcCreate`。
6. 必填信息为 SKU、批次号、生产日期；照片至少 1 张，最多 6 张。
7. Web 运行时按钮文案为“选择照片”，原生手机运行时为“拍照”。
8. 任务状态可能为：草稿、上传中、排队中、AI 初筛中、待人工审核、已完成或 AI 失败需人工检查。
9. “待我审核”任务卡展示 SKU、批次、日期、照片数和 AI 疑点数。
10. 审核页每个橙色 AI 框必须“确认”或“拒绝疑点”；AI 失败或“不清”仍由人工判断。
11. 轻点照片可新增绿色人工框；问题类型为“缺白、缺彩、不清”，人工框可移动、缩放和删除。
12. 双指缩放照片，放大后拖动画面；拖动标注框本体只移动框，右下角控制点只缩放框。
13. 当前照片所有框均已判断后，必须再点击“确认本图标注无误”或“整图正常 · 没有其他问题”。
14. 多张照片使用“下一张未审核”继续；全部照片完成后，底部主按钮变为“提交人工审核”。
15. 只有点击“提交人工审核”才把人工结果写回服务器；此前移动框、补框和选择类型都是当前页面草稿。
16. 人工审核写回时把训练状态重置为 `PENDING`；Web 可下载单任务 JSON 备份、软归档和恢复。
17. 只有拥有 `system:read_write` 的技术管理员可以批准/拒绝训练数据和导出已批准训练集；批准不等于模型已训练或已部署。

## 验收

- 本地 HTML 在 `390 × 844` 与 `1440 × 1000` 视口无水平溢出。
- HTML 中所有截图存在、图片具备替代文本、截图灯箱可打开关闭、步骤导航锚点可用。
- 文案与当前 RN 按钮、手势、照片数量限制和状态语义一致。
- 人工审核流程无死路：待我审核 → AI 框 → 人工补框 → 本图结论 → 下一张 → 提交人工审核。
- 开户流程无死路：管理员创建白名单邀请 → 员工验证手机号 → 核对工厂/角色 → 本人设密 → 手机号密码登录。
- 权限边界明确：普通 QC 可审核、备份和归档；技术管理员才可确认/拒绝训练数据并导出已批准训练集。
- 归档是可恢复的软归档，备份可下载；任何操作均不自动训练或部署模型。
- 不公开凭证；本次验收生产业务写入为 0。
- 用户后续授权生产发布：Java 已切换至绿槽 `10020`，Web Admin 与 QCSOP 已完成原子发布，RN 已发布 runtime `1.0.3` 的 production Android OTA `1785095974077`；服务、公开页面、manifest、CDN bundle 与功能标记均已只读验证。
