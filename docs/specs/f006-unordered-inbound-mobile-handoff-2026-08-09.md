# F006 无订单入库跨角色接力

## 目标

客供料、赠予等没有采购/销售订单的来料先由运营创建预告。仓管在现有 RN 仓储“入库”入口收货；如果只到一部分，预告继续保留，管理员可处理同一预告的下一次入库并最终结束。库存批次与客户归属由后端现有流程保存，本次不新增后台业务模块。

## UX Flow Analysis

- **Who**：主要操作者是仓管，低频接替者是工厂管理员；两者操作同一个后端待办，不创建角色私有副本。
- **Where**：入口仍在“仓储 → 入库”，原“采购收货”调整为“待收货任务”，同时展示采购与无订单入库。
- **Start**：运营已创建 OPEN 或 PARTIALLY_RECEIVED 的无订单入库预告。
- **Core path**：打开待办 → 核对客户/入库原因 → 搜索选择原料 → 搜索选择仓库 → 填实收数量 → 选择保留待办或结束预告 → 查看完整确认摘要 → 提交。
- **Guardrails**：不允许手填原料 ID、仓库 ID 或单位；单位来自原料主数据且只读；数量最小 0.01、最多两位小数；提交中禁用并复用同一幂等键；结束预告前明确二次确认。
- **Error recovery**：列表的采购源与无订单源独立报错，不把局部失败伪装为空列表；提交失败保留用户输入；部分入库后返回列表并刷新，待办继续可见。
- **Success**：部分入库提示“已入库，预告继续保留”；最终入库提示“已入库并结束预告”。返回后重新拉取服务端任务，不能依靠本地假状态。
- **Physical context**：按钮最小 44pt，主要信息用名称和业务编号，不展示内部 ID；列表使用虚拟化渲染，适合仓库移动设备。

## 业务边界

- 无订单入库不新增采购单、销售订单或生产前质检。
- `completeNotice=false` 创建批次但预告保持待办；`completeNotice=true` 创建本次批次并关闭预告。
- 仓管与管理员使用同一收货 API 和同一待办真值，因此天然支持跨角色接力。
- 管理员继续使用现有 Web 仓储入口；仓管使用 RN，不取消其 Web 移动端角色限制。
- 本次不改后端权限、数据模型、迁移、Security/Auth。

## 验收

1. 仓管看到指定 OPEN 预告并以 0.01 的有效数量部分入库。
2. 回读批次和预告：批次归属 F006/指定客户，预告为 PARTIALLY_RECEIVED，待办仍存在。
3. 管理员打开同一预告，以新的幂等键补录 0.02 并选择结束。
4. 回读批次和预告：第二个批次写入，预告结束且不再出现在待收货任务中。
5. 记录每次实际 mutation 的 URL、ID、HTTP 结果；F006 以外业务写入为 0。
