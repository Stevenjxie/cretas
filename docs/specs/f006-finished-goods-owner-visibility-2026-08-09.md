# F006 成品库存归属可见性

## UX Flow Analysis

### User Persona

- 仓管、运营和销售在成品库存列表中判断某批货能否用于当前客户发货。
- 用户不应理解 `CUSTOMER_OWNED`、UUID 或内部数据关系，只需看到业务名称。

### User Journey

1. 进入成品库存列表，直接看到每批货是“公司库存”还是“客户专属”。
2. 客户专属批次在同一单元格显示客户名称和客户编码。
3. 打开批次详情，在数量信息之前再次确认库存归属和归属客户。
4. 批次售罄后仍保留归属展示，用于历史追溯与发货复核。

### Friction Points

| ID | 问题 | 严重度 | 防呆依据 |
|---|---|---|---|
| F1 | 当前列表/详情没有归属信息，仓管可能把客户专属库存当作公司库存 | HIGH | Rule 2：关键操作上下文必须带身份信息 |
| F2 | 客户资料加载失败时若默认显示公司库存，会造成跨客户误发 | HIGH | fail-closed：未知不能伪装为安全状态 |
| F3 | 直接显示 UUID/英文枚举，现场用户无法核对 | MEDIUM | L5：内部 ID 不作为用户主信息 |

### Design Decisions

- 列表增加一个“库存归属”组合列：语义标签 + 客户名称/编码，不再增加多个分散字段。
- 详情在产品之后、数量之前展示“库存归属”和“归属客户”。
- `ownerCustomerId` 存在时一律按客户专属处理，即使枚举数据异常也不能误标公司库存。
- 客户专属但缺少客户 ID 时显示“未记录归属客户”；只读解析失败时显示“客户资料加载失败，请刷新”，不回退到公司库存。
- 客户查询仅用于只读展示，静默处理单条查询错误并在单元格内给出明确状态，避免多个阻塞 toast。

## Scope

- Web Admin 成品库存列表、详情、只读类型、归属展示 helper 与目标测试。
- 不修改后端数据模型、权限、库存扣减、预留、销售订单或生产流程。
- F006 验收使用既有已售罄客户专属批次，只读请求，业务写入为 0。
