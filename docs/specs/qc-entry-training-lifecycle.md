## 目标

1. 质检员登录 RN 后，在首页首屏直接看到“待我审核”及数量，一次点击进入任务队列。
2. 首页仅保留当前工作最需要的状态与操作，底部导航在窄屏、全面屏安全区和 Expo Web 手机视口中完整可见。
3. 人工审核完成只形成“已审核真值”，不会自动进入训练集。
4. Web 管理端提供独立的软归档、恢复、备份导出和技术管理员训练确认；所有动作记录操作者和时间。
5. QCSOP 用真实 Web Admin 与 Expo Web 截图说明完整开户、登录、拍检、标注和训练数据整理流程。

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

| 用户 | 使用环境 | 主要目标 | 认知边界 |
|---|---|---|---|
| 质检员 | 工厂现场，手机单手操作，可能戴手套 | 快速找到待审核照片、确认或补画问题框、提交 | 不需要理解模型、训练集、归档版本等技术词 |
| 工厂管理员 | Web 管理端 | 按手机号开通本厂人员，配置职责范围 | 不应接触其他工厂，不替员工设置或查看最终密码 |
| 技术管理员 | Web 管理端 | 整理已人工审核数据，备份并确认是否进入训练集 | 不参与现场拍检；任何训练确认必须显式、可审计 |

### 用户旅程

| 阶段 | 用户动作 | 系统即时反馈 | 下一步 |
|---|---|---|---|
| 1. 管理员开户 | 输入手机号、姓名，选择工厂角色，加入白名单 | 显示“待员工注册”，账号明确等于手机号 | 把注册网址/手机端入口交给员工 |
| 2. 员工注册设密 | 输入同一手机号，通过邀请校验，本人设置密码 | 展示工厂与受邀角色，不允许自行改角色 | 返回登录 |
| 3. 手机登录 | 使用手机号和本人密码登录 | 进入质检首页，首屏显示待我审核数量 | 打开待审核或发起拍检 |
| 4. 找任务 | 点击首页“待我审核” | 直接进入待人工审核筛选，不要求先找快捷操作 | 打开 SKU/批次任务 |
| 5. 人工审核 | 逐图确认/拒绝 AI 框或点击照片补框 | 每张图明确显示完成进度与下一张按钮 | 提交整单人工审核 |
| 6. 数据整理 | Web 查看已审核任务，选择归档或导出备份 | 归档不删除；备份包含照片、标注和批次元数据 | 技术管理员复核 |
| 7. 训练确认 | 技术管理员明确批准或拒绝进入训练集 | 显示批准人、时间和备注；只有批准数据可导出训练集 | 本地训练流程另行执行 |

| 编号 | 严重度 | 当前摩擦 | 设计响应 |

| F3 | HIGH | 底栏固定高度 60px，未把设备底部安全区计入容器高度 | 使用安全区动态高度、完整标签、最小 44pt 点击区域和窄屏字号 |
| F4 | HIGH | Web 文案把“人工审核完成”直接等同“进入训练数据” | 状态拆为“待训练确认 / 已批准 / 已拒绝”，只有技术管理员能确认 |

### 设计响应

- 首页信息顺序固定为：身份与通知 → 待我审核 → 发起拍检/记录 → 今日精简摘要。
- “待我审核”卡显示数量；有任务时显示下一条 SKU/批次，无任务时显示“当前无待审核”及“发起拍检”。
- 质检底栏保留“首页、质检、记录、分析、我的”，但使用动态安全区高度和完整可见标签；业务是否显示仍遵循工厂功能开关。
- 人工审核提交按钮只写“完成审核”，不再宣称自动进入训练集。
- 训练确认使用 `system:read_write` 权限；普通 `quality:read_write` 只能审核、查看、归档和备份，不能批准训练。
- 归档是可恢复的业务状态，不使用物理删除；恢复后仍保留审核、归档和训练决策审计字段。

## 数据生命周期

```text
NEEDS_REVIEW / ANALYSIS_FAILED
        ↓ 质检员完成逐图审核
REVIEWED + TRAINING_PENDING
        ├─ 工厂质检管理：备份导出（不改变训练状态）
        ├─ 工厂质检管理：归档 / 恢复（不删除）
        └─ 技术管理员：批准 / 拒绝训练
              ├─ TRAINING_APPROVED → 可进入训练导出
              └─ TRAINING_REJECTED → 不进入训练导出，可保留归档
```

训练批准不启动训练作业；本地下载、训练、评估和模型发布属于独立流程。

## 开户与登录指引内容

QCSOP 必须逐项说明并配真实截图：

1. 管理员登录 Web 后，从“人事 / 入职白名单”进入账号邀请。
2. 输入员工真实手机号和姓名；手机号是员工后续唯一登录账号。
3. 选择职责角色，例如“质量检验员”；角色决定权限，员工注册时不能自行更改。
4. 保存后确认状态为“待注册/有效邀请”；白名单只对当前工厂有效。
5. 员工在 RN 注册页输入同一手机号；系统展示受邀工厂和角色后，由员工本人设置密码。
6. 密码按页面规则设置并二次确认；管理员不读取、不代存员工明文密码。
7. 员工在登录页以手机号 + 本人密码登录；同一手机号可在多台授权手机同时在线。
8. 故障处理：
   - 提示“未找到有效邀请”：核对手机号、工厂和白名单状态。
   - 角色不对：由管理员修改邀请，员工不能自提权。
   - 密码错误：重试或走忘记密码；不要新建重复账号。
   - 已换手机：直接用手机号和原密码登录，不需要先踢掉旧设备。

- QCSOP：真实 Expo Web 和 Web Admin 截图，开户与人工标注流程连续，不使用 HTML 假手机原型。
- 后端：真实 JPA Context、租户隔离、状态门禁、幂等/并发、权限测试通过。
