# 无订单入库申请并入仓储收货

## 决策与边界

- 不新增“运营协同”一级模块；唯一入口为“仓储管理 → 原料 / 物料入库与批次”。
- 页面位置与写权限分离：运营创建/取消来源申请，仓管根据待收任务登记现场事实，创建申请本身不增加库存。
- 原因固定为“客户来料 / 赠予 / 其他”。客户来料必须选择客户，实际收货生成客户所有库存；赠予和其他可不选择客户，实际收货生成公司库存。
- 不增加来料质检；生产成品照片质检保持原流程。
- 旧 `/operations/customer-material-arrivals` 地址保留兼容重定向，避免收藏和历史链接成为死路，但菜单不再展示独立运营模块。

## 权限矩阵

| 角色 | 查看仓储收货页 | 创建/取消无订单入库申请 | 确认实际收货入库 |
|---|---:|---:|---:|
| 运营协调员 | 是 | 是 | 否 |
| 仓管 | 是 | 否 | 是 |
| 工厂超级管理员 | 是 | 是 | 是 |

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

- 运营协调员 — 熟悉客户和到货协调，但不掌握现场物料、数量和仓库事实 — 在统一仓储收货页发起来源申请。
- 仓管 — 技术素养较低、现场操作节奏快 — 只处理明确的待收任务并核对实际入库信息。

### 用户旅程

| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|------|---------|---------|---------|
| 1 | 仓储页顶部“发起无订单入库” | 运营点击主按钮 | 打开不包含物料、数量、仓库和质检字段的申请表 |
| 2 | 原因、预计到达和来源说明 | 运营选择原因；客户来料时选择客户 | 生成“待到货”申请，不增加库存 |
| 3 | 同页待收货任务和来源徽标 | 仓管查看客户来料/赠予/其他来源 | 明确知道为什么收货、库存归谁 |
| 4 | 收货确认弹窗显示申请号、来源、客户/公司所有权 | 仓管选择实际物料、数量、仓库并确认 | 幂等生成对应所有权的库存批次 |
| 5 | 完成或保留待办 | 仓管选择是否还有后续到货 | 状态变为已完成或部分收货 |

### 摩擦点清单

| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|-----------|---------|---------|
| F1 | 独立运营一级模块增加寻找入口和跨模块跳转成本 | HIGH | 内联 UX 信息密度 |
| F2 | “在仓储页”容易被误解为运营可以直接写库存 | HIGH | fool-proof Rule 2 |
| F3 | 客户来料与赠予的库存所有权相反，选错会污染领料边界 | HIGH | fool-proof Rule 1 / Rule 2 |
| F4 | 旧运营链接被移除后会形成 dead-end | MED | fool-proof Rule 5 |
| F5 | 重复点击收货可能重复增加库存 | HIGH | fool-proof Rule 4 |

### 每个摩擦点的设计回应

- F1 → 在现有仓储页顶部提供唯一主入口，不再显示独立运营菜单。
- F2 → 创建按钮只由 `operations:write` 控制；收货按钮只由 `warehouse:write` 控制，申请表明确提示“不会直接增加库存”。
- F3 → 原因使用固定单选；客户来料联动客户必填并预览“客户所有”，赠予/其他预览“公司所有”，仓管确认前再次展示所有权。
- F4 → 旧地址重定向到仓储页并自动定位无订单入库区域。
- F5 → 继续使用来源申请 ID + 幂等键，重放只返回既有批次，不产生第二次库存写入。

## 验收标准

- 菜单没有“运营协同”一级组；仓储页可找到“发起无订单入库”。
- 运营账号只有创建/取消按钮，仓管只有实际收货按钮，管理员同时具备。
- 客户来料、赠予、其他三种原因的表单联动和后端所有权门禁一致。
- 创建申请前后库存数量不变；实际收货后才增加对应所有权库存。
- 旧 URL 可达新入口；错误保留表单内容并提供下一步。
