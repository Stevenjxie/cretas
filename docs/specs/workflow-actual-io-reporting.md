# Workflow 实际投入/产出报工语义

任务：`BUG-WORKFLOW-ACTUAL-IO-SEMANTICS-20260727`

## 业务真值

1. Workflow 管工序拓扑以及“可能投入、可能产出”的稳定接口，不管理本次生产选择。
2. BOM 管主料、替代料、辅料、包材、用量与成本。报工候选必须来自批次固定 BOM。
3. 工序 Cell 不配置投入关系、产出关系、主产出、联产品、副产品或静态成本分摊比例。
4. 正式报工按当次实际情况提交：
   - 至少一条数量大于零的实际投入；
   - 至少一条数量大于零的实际产出；
   - 可以只报一个可用产出，也可以同次报多个可用产出；
   - 未发生的投入或产出不提交，不伪造零数量业务行。
5. 主料和替代料关系从 pinned BOM 自动派生：
   - 每个 BOM 主项及其允许替代料形成系统候选，不要求用户配置关系；
   - 正式报工至少选择并投入一种 BOM 允许的原料；
   - 候选集合等于 Workflow 当前工序接口、pinned BOM 授权集合和当前仓可用批次的交集。
6. 本次成本分配：
   - 只报一个产出时，本道共享投入成本 100% 归该产出；
   - 同次多个产出且单位可统一时，按统一后的实际数量自动计算；
   - 单位量纲不可统一时，仅在本次报工表单要求输入各实际产出的分摊比例，合计 100%；
   - Workflow 和 BOM 页面都不要求用户预设本次比例。
7. 已发布 Workflow revision、历史计划、报工和成本快照不可改写。新语义通过新草稿/新 revision 生效；历史 runtime snapshot 保持原解释。

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

车间报工人员——低技术素养、按当天实际生产数量快速录入，不理解端口组、主产出、联产品、量纲或 Workflow revision 等工程术语。

### 用户旅程

| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|------|---------|---------|---------|
| 1 | 当前批次、本道工序和 BOM 允许的物料 | 选择实际使用的主料或替代料并填数量 | 只显示合法且有库存的候选 |
| 2 | 本工序所有可能产出 SKU | 给当天实际产出的一个或多个 SKU 填数量 | 未生产项保持空白，不阻止提交 |
| 3 | 自动成本状态 | 检查系统自动换算结果 | 单产出直接归集，多产出自动按实际数量分配 |
| 4 | 仅当量纲不可统一时显示本次分摊 | 填写本次多个实际产出的百分比 | 合计 100% 后可正式报工 |
| 5 | 明确的报工摘要 | 点击“正式报工” | 保存实际投入、产出、批次和本次成本快照 |

### 摩擦点清单

| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|-----------|---------|---------|
| F1 | Workflow Cell 暴露投入/产出关系、角色和比例 | HIGH | 信息密度、只暴露当前步骤 |
| F2 | 报工候选可能超出 BOM 授权替代料 | HIGH | fool-proof Rule 1 |
| F3 | 未生产的产出被强制填写 | HIGH | fool-proof Rule 1 |
| F4 | 自动换算失败后清空已填数量 | HIGH | 错误恢复 |
| F5 | 技术错误没有下一步 | MED | fool-proof Rule 5 |

### 每个摩擦点的设计回应

- F1 → Workflow Cell 仅展示投入与产出 SKU 列表，辅文案为“正式报工时按实际选择并填写数量”。
- F2 → 后端权威计算 pinned BOM 主料/替代料与可用库存批次交集，前端不能扩展候选。
- F3 → 空白或零数量产出不进入请求；至少一个正数产出即可。
- F4 → 无法自动统一量纲时保留投入/产出数量，只展开本次成本分摊输入。
- F5 → 错误说明发生了什么以及如何修复；缺 BOM 直接引导配置 BOM，单位不兼容引导补本次比例。

  已被 BOM 固定或非当前草稿的异常修订继续阻断，绝不静默改写历史。
