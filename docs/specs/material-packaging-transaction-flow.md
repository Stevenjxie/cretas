# 原料多包装交易与基本单位库存契约

## 目标

原料类型维护一个库存基本单位，并维护一条或多条“采购包装单位 → 库存基本单位”的直接换算。采购、收货入库、跨仓调拨可以用包装单位录入；库存批次、库存余额、生产领料和 BOM 可用量只使用基本单位。

例如原料基本单位为 `kg`，配置 `1 箱 = 10 kg`、`1 袋 = 2.5 kg`：

- 采购可以选择箱或袋，并同时看到折合基本量。
- 收货默认继承采购规格；实际包装不同时，可从该原料有效包装规格中改选。
- 调拨可以按箱或袋录入，但库存实际扣减和调入落账均为 kg。
- 生产只能看到和消耗 kg，不再看到箱、袋等交易包装单位。

## 核心数据契约

1. `RawMaterialType.unit` 是唯一库存基本单位。
2. `MaterialPackagingSpec` 是包装换算的唯一主数据来源；每条规格直接换算到基本单位。
3. 采购、收货和调拨保存所选包装身份、包装数量、包装单位、换算系数和折合基本量快照，历史单据不受主数据后续修改影响。
4. `MaterialBatch.receiptQuantity`、`quantityUnit`、库存扣减、移动平均价和生产事件统一使用基本量与基本单位。
5. 采购和收货的超收边界按折合基本量比较，禁止不同单位裸数相加。
6. 多包装规格必须显式选择；只有一个有效规格时自动选中并清楚展示。
7. 抄码原料不使用固定包装换算，收货继续按实际称重的基本单位落账。

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

采购员与仓管员 — 熟悉实际包装名称但不应手算单位换算 — 在电脑采购、手机或 Web 收货、跨仓搬运时快速确认数量。

### 用户旅程

| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|------|---------|---------|---------|
| 1 | 原料名称、基本单位、所有有效包装规格 | 采购员选择包装规格并填包装数量 | 即时显示“8 箱 = 80 kg”，采购单保存包装和基本量快照 |
  | 2 | 采购单号、原料、采购包装、待收上限 | 仓管核对或改选实际到货包装，填写数量 | 即时显示本次基本量和剩余可收边界 |
  | 3 | 计划量、已确认收货、草稿待确认、待收差额 | 仓管确认本次收货 | 仅按已确认累计量判断；每个采购行累计已收大于等于计划时，订单标为 `COMPLETED` 且任务自动退出待办 |
  | 4 | 少收关闭入口与计划/已收/少收差额 | 确认供应商不再补发后选择标准原因并提交 | 保留已确认库存，采购单标为 `CLOSED`，剩余数量不再生成待入库任务 |
  | 5 | 原料批次、可用基本量、可选包装规格 | 仓管选择调拨包装并填数量 | 即时显示将扣减的基本量，不能超过当前基本量库存 |
  | 6 | 调拨确认摘要 | 调出/调入仓确认 | 两端库存均按基本单位扣减和增加 |
  | 7 | 生产领料与 BOM 可用量 | 生产人员查看或领料 | 只出现基本单位，不需要理解采购包装 |

### 摩擦点清单

| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|-----------|---------|---------|
| F1 | 多规格时不知道当前选的是箱还是袋 | HIGH | fool-proof Rule 2 / 批次选择规则 |
| F2 | 用户需要自己计算包装数量对应多少 kg | HIGH | fool-proof Rule 1 / 数字联动 |
| F3 | 收货单位与采购单位不同后直接比较裸数量 | HIGH | fool-proof Rule 1 |
| F4 | 包装单位写入库存后污染生产领料 | HIGH | 当前业务契约 |
| F5 | 主数据规格变更导致历史单据重新解释 | HIGH | 写操作可追溯性 |
| F6 | 仓管重复选择采购已经锁定的规格 | MED | 信息密度 / 单规格自动选择 |
  | F7 | 抄码料被固定箱重误换算 | HIGH | 现有抄码业务规则 |
  | F8 | 活动收货草稿占满剩余量后，界面误显示“待收 0”并被当成已完成 | HIGH | 状态可见性 / 防误解 |
  | F9 | 少收关闭误触后，剩余计划被永久终止 | HIGH | fool-proof Rule 3 / 危险操作确认 |
  | F10 | 关闭时仍有未确认草稿，导致草稿与终态并存 | HIGH | 并发与状态一致性 |

### 每个摩擦点的设计回应

- F1 → 选择项始终展示“规格名 · 1箱=10kg”，多规格未选择时禁止提交。
- F2 → 数量输入下方实时显示折合基本量，不要求用户心算。
- F3 → 后端统一折合成基本量后做上限检查，并在界面预先显示最大可收包装量和基本量。
- F4 → 库存批次、调拨库存和生产事件只写基本量；包装只保存在交易快照字段。
- F5 → 采购、收货、调拨分别保存当时的规格 ID、单位和系数快照。
- F6 → 采购规格自动带入收货；只有实际包装不同时才需要改选，单规格自动选中。
  - F7 → 抄码料隐藏固定包装规格，强制按实际称重的基本单位录入。
  - F8 → “已确认收货”只显示已落库累计量；“草稿待确认”独立展示；“待收数量”始终等于计划减已确认，不用草稿量伪装完成。
  - F9 → 少收关闭为次级危险操作；确认框同时显示采购单、供应商、计划、已确认与少收差额，并强制选择标准原因；“其他原因”必须填写说明。
  - F10 → 后端在采购单悲观锁内检查活动草稿；存在 `DRAFT`/`PENDING_QC` 时拒绝关闭并指向继续收货，重复关闭幂等且不覆盖首次审计。

## 验收

- 多规格原料在采购、收货和调拨均可选择具体包装，并显示折合基本量。
- 入库及调拨完成后，新建原料批次的数量单位等于 `RawMaterialType.unit`。
- 生产领料、库存可用量及相关事件只读取基本量。
- 历史采购、收货、调拨仍能显示原包装快照。
- 旧客户端未传包装规格时：单一可证明规格可自动解析；多规格必须失败并提示选择，绝不猜测。
  - 目标测试覆盖旧 `g/box/case`、中文基本单位、多包装规格和抄码料。
  - 确认收货后，每个采购行累计已收等于或大于计划量时自动变为 `COMPLETED`；超收仍受既有上限控制。
  - 少收关闭仅允许 `FINANCE_APPROVED`/`PARTIAL_RECEIVED` 且无活动收货草稿的采购单；记录原因、说明、操作人和时间，已确认库存零回滚。
