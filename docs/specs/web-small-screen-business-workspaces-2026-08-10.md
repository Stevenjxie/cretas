# Web Admin 小屏业务工作区优化

## 目标与范围

本轮建立两层能力：

1. 全局为 Element Plus `Dialog` / `Drawer` 提供安全的小屏基线，保证正文可滚动、标题与底部操作始终可达。
2. 将高信息密度、长流程的“手动新建调拨单”迁移到独立路由 `/transfer/new`，作为后续业务长表单迁移的参考实现。

采购、供应商、SKU、Workflow、销售与生产页面当前存在其他 scope 锁，本轮不直接改动这些页面；它们先自动获得全局安全基线，待各自 scope 释放后再按审计清单逐页迁移。

## 全仓审计基线

对 `web-admin/src/**/*.vue` 的静态盘点共识别到 371 个 Dialog/Drawer 使用面，分布于 217 个文件、26 个业务模块。按固定宽度、表格/上传/多步骤、长表单、嵌套滚动和底部动作风险综合分级：高风险 82、中风险 92、低风险 197。

全局处置分为三档：

- 低风险确认/轻表单：保留弹窗，由本轮全局 viewport 基线直接兜底。
- 中风险编辑/选择器：保留 Overlay，但按模块逐步使用内容滚动、固定动作区与窄屏字段重排。
- 高风险批量导入、明细表、长流程：优先迁移为独立业务工作区；本轮以调拨新建完成首个生产实现。

当前在飞任务已锁定采购、供应商、SKU、Workflow、销售和生产的多个页面。为避免覆盖其他 Owner 改动，本轮不直接修改这些文件；这不是遗漏，而是将它们纳入迁移队列并先统一获得全局小屏安全基线。

## UX Flow Analysis

### 用户与环境

- 主要用户：仓管、仓储主管和兼任后台操作的业务人员。
- 使用环境：1366×768 办公电脑、1024px 窄窗口，偶尔使用 768px 宽窗口；键鼠为主。
- 技术熟练度：中低，用户更依赖业务名称、库存提示与明确的下一步，而不是内部 ID 或复杂表格操作。

### 核心旅程

`调拨单列表 → 手动新建调拨单 → 填写调拨信息 → 添加物料并核对库存 → 创建草稿 → 进入详情 → 提交 OA 审批`

### 主要摩擦点

| 编号 | 严重度 | 现状 | 设计响应 |
|---|---|---|---|
| F1 | 高 | 960px 长弹窗在 1366×768 下正文和页脚互相挤压，底部按钮可能离开视口 | 改为独立路由页；全局弹窗改为纵向 flex，正文滚动、页脚固定可达 |
| F2 | 高 | 物料表格列多，窄窗口横向裁切，用户容易忽略库存和单位 | 独立页提供明确的横向滚动容器、列标题与库存上限提示 |
| F3 | 高 | 长弹窗向下滚动后丢失“正在创建什么、下一步是什么”的上下文 | 页面头部、步骤条、右侧流程说明和底部操作区保持稳定层级 |
| F4 | 中 | 关闭弹窗和误触遮罩会丢失已填内容 | 独立路由不响应遮罩关闭；离开按钮提供明确语义，提交期间禁止重复操作 |
| F5 | 高 | 库存不足、重复物料、包装换算若只在最后报错，会造成返工 | 保留并强化 `max`、可用库存、基本量预览、重复选项禁用和提交前 fail-closed 校验 |

### 信息架构

- 页面标题区：返回列表、用途说明、当前状态“新建草稿”。
- 进度区：`调拨信息 → 调拨物料 → 创建草稿`，用于说明流程而非虚构已完成状态。
- 主工作区：基础信息卡 + 物料明细卡。
- 辅助区：创建后流程与关键规则说明。
- 底部操作区：取消、创建草稿；小屏下保持可见并允许换行。

### 防错与恢复

- 调出/调入仓库必须选择；同厂仓库调拨时两者不得相同。
- 物料选择来自所选调出仓库真实库存，重复物料在候选中直接禁用。
- 数量不得超过库存折算后的包装上限；基本量在输入旁即时展示。
- 创建失败保留当前表单，不返回列表；成功后进入新单详情页继续流程。
- 全局弹窗基线不改变业务逻辑，只修复 viewport、滚动与操作可达性。

## 验收矩阵

| 视口 | 全局 Dialog/Drawer | 调拨新建页 |
|---|---|---|
| 1366×768 | 不超过视口；正文滚动；页脚可达 | 页面无整体横向溢出；物料区可局部横向滚动 |
| 1024×768 | 同上，按钮可换行 | 主辅栏合并为单列，字段仍清晰 |
| 768×768 | 最大化利用宽度，保留安全边距 | 表单双列变单列，底部操作可见，表格局部滚动 |

## 非目标

- 不修改后端 API、数据库、权限或生产业务数据。
- 不在本轮逐个迁移所有 82 个高风险页面；已有 scope 锁页面只获得全局安全基线。
- 不执行生产部署。
