# 工厂 RN 角色能力与 PC 边界

## 目标

RN 服务现场与移动协同，PC 服务复杂规划、批次编排、结算和主数据治理。角色权限以真实业务动作划分，不以页面是否可见代替能力定义。

| 角色 | RN 允许 | RN 不允许 / 转 PC |
| --- | --- | --- |
| 生产经理 | 查看生产计划、批次、工序进度和异常 | 创建/编辑生产计划、结单、成品入库、复杂排产 |
| 车间主管 | 查看车间任务、现场协调和授权范围内确认 | 改计划主数据、替仓储入库 |
| 操作员 | 按任务报工、查看自己的工序和结果 | 建计划、结单、入库、改其他人的记录 |
| 销售 | 客户、订单和交付状态的标准移动操作 | 复杂定价、批量治理、仓储和财务动作 |
| 采购 | 采购单、到货协同和异常的标准移动操作 | 仓储收货确认、质检判定、付款执行 |
| 运营协调员 | 跨模块只读；创建、查看和在未收货前取消客供料到货通知 | 入库、库存调整、生产执行、质检判定、销售商务条款、财务和系统配置 |
| 仓管 | 按待办执行收货、入库、出库、盘点等现场闭环 | 采购下单、生产结单、跨角色审批 |
| 老板/工厂管理员 | 全局查看、仅处理系统中真实存在且分配给自己的审批/异常 | 代替一线录入生产、仓储、采购、销售事实 |

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

- 生产经理 — 中等技术熟练度 — 在车间走动中快速掌握计划和工序进度，复杂计划工作回 PC。
- 运营协调员 — 中等技术熟练度 — 信息面广但写权限窄，只完成跨部门协同所需的少量动作。
- 仓管与操作员 — 低技术熟练度 — 高频、单手、弱网现场操作，必须明确当前任务与下一步。
- 全部 RN 用户 — 技术熟练度不一 — 启动时需要直接知道能否继续使用、为什么必须更新以及唯一下一步。

### 用户旅程

| 步骤 | 用户看到 | 用户操作 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 启动检查页 | 等待最低版本检查 | 支持版本进入登录/业务；弱网检查失败时保留既有离线可用性 |
| 2 | 低于最低版本时的全屏阻断页，显示当前版本、最低版本和更新说明 | 点击“立即更新” | 打开服务器返回的官方安装包地址，不能绕过进入业务 |
| 3 | 下载或安装失败后的明确提示 | 点击“重新检查”或再次更新 | 保持阻断，不丢失原因和版本信息，不出现“稍后”入口 |
| 4 | 支持版本登录后的角色首页或待办 | 进入列表和详情 | 直接进入与角色匹配的路径，不经过通用高权限首页 |
| 5 | 带客户、产品/物料、单号或批次、当前状态的卡片 | 执行角色允许的真实动作 | 成功后显示结果、当前状态和下一责任人；失败时保留输入 |

### 摩擦点清单

| # | 摩擦点描述 | 严重程度 | 来源规则 |
| --- | --- | --- | --- |
| F1 | 未知角色落入通用导航会同时造成找不到工作和越权入口 | HIGH | fool-proof Rule 1 |
| F2 | 把 PC 完整表单搬到手机，字段过多且不适合现场 | HIGH | 内联 UX 规则：信息密度 |
| F3 | 使用系统并不存在的“开始生产”概念会误导状态流转 | HIGH | fool-proof Rule 2 |
| F4 | 把整个模块写权限授予运营，会让有限协调动作扩大成业务事实修改 | HIGH | fool-proof Rule 1 |
| F5 | 仓储表单填写完仍不清楚是否已产生库存事实 | HIGH | fool-proof Rule 2 |
| F6 | 弱网或重复点击可能导致重复提交 | HIGH | fool-proof Rule 4 |
| F7 | 空状态和权限错误若只有技术错误码，用户无法知道下一步找谁 | MED | fool-proof Rule 5 / 内联 UX 规则：错误恢复 |
| F8 | 最低版本提示只是 Toast 或允许“稍后”，用户仍能进入不兼容业务 | HIGH | fool-proof Rule 1 |
| F9 | 把普通 OTA 与最低版本阻断混为一体，会导致每次小更新都打断现场工作 | HIGH | 内联 UX 规则：信息密度与错误恢复 |

### 每个摩擦点的设计回应

- F1 → 每个业务角色显式映射独立导航；未知或未配置角色进入锁定页，不自动开放业务入口。
- F2 → 移动端只保留高频现场字段，复杂创建、批量处理和治理返回 PC。
- F3 → 按真实动作命名：录入工序、报工、结单、入库分别呈现，不设置虚构的“开始生产”。
- F4 → 运营只进入独立的运营协调页面，不借用通用模块写权限。
- F5 → 提交前展示影响范围，成功后明确库存事实和下一责任角色。
- F6 → 提交中禁用按钮，后端业务键幂等；失败保留输入并允许安全重试。
- F7 → 权限不足、无任务和空列表均给出可执行的下一步与责任角色。
- F8 → 最低版本检查在业务导航挂载前完成；确认过旧后只渲染全屏阻断页，没有关闭、返回或“稍后”。
- F9 → 普通同 runtime OTA 保留“稍后”；只有服务器最低版本阈值触发不可绕过的安装包更新。

### Interaction Constraints

- 同一屏幕只突出一个主动作；危险取消使用二次确认。
- 触控目标不小于 44pt；关键数量使用至少 24px 字号。
- 长列表使用 `FlatList`，避免一次渲染全部记录。
- 表单错误定位到字段，网络失败不清空已输入数据。
- 页面遵循安全区和系统字体缩放，不依赖颜色单独表达状态。
- 最低版本阻断页仅有一个主操作“立即更新”，次操作“重新检查”用于安装后验证；更新失败显示“发生了什么 + 怎么解决”。

## 验收范围

- `operations_coordinator` 有明确 RN 导航，只能执行已批准的客供料到货通知动作。
- `production_manager` RN 只能查看生产信息，无创建计划、完成生产、结单或入库入口。
- 操作员既有任务报工路径保持可用。
- 销售、采购和仓储继续使用各自专用导航，不回退通用高权限页面。
- 老板/工厂管理员不因本次改动新增代操作入口。
- 普通 OTA 仍允许稍后；低于最低支持版本时 AppNavigator 不挂载，不能登录或进入任何业务页面。
- 最低版本接口异常时不得误判为过旧；已明确判定过旧后，下载失败或回到前台仍保持阻断并可重试。
- Android 正式包升级到 `1.0.4` / versionCode `15`；旧 `1.0.3` runtime 先发布一次兼容 OTA，使接受该 OTA 的旧包具备最低版本阻断能力。
- 所有验证使用测试数据或静态/自动化检查，生产业务写入为 0。
