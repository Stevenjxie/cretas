# 质检首页待办与通知角标一致性

## 目标

质检员将单条或全部通知标为已读后，通知列表和首页铃铛角标必须与服务器未读数保持一致；AI 初筛完成后，首页“待我审核”必须自动出现对应任务；网络失败时不得伪装成功。

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

工厂质检员 — 以手机现场操作为主，关注“现在还有几条需要处理”，不应理解缓存、页面生命周期或手动刷新。

### 用户旅程

| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|------|---------|---------|---------|
| 1 | 首页铃铛显示未读数量 | 点击铃铛 | 进入当前账号的通知列表 |
| 2 | 未读通知有醒目标识 | 点击单条通知 | 服务器确认已读后，该条未读标识消失 |
| 3 | 通知页仍有多条未读 | 点击“全部已读”并确认 | 服务器确认后，本页所有未读标识和数量清零 |
| 4 | 返回质检首页 | 无额外操作 | 首页自动重新拉取，角标立即减少或消失，不要求下拉刷新 |
| 5 | 网络或接口失败 | 点击已读操作 | 未读标识保持不变，并提示检查网络后重试 |
| 6 | AI 初筛在用户停留首页期间完成 | 无额外操作 | 首页在 10 秒内自动更新“待我审核”数量和下一条任务 |

### 摩擦点清单

| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|-----------|---------|---------|
| F1 | 当前页面只改本地 `read`，服务器未读数不变，返回首页后角标仍显示 | HIGH | fool-proof Rule 1 |
| F2 | 首页仅首次挂载拉取，通知页返回时不会刷新角标 | HIGH | 内联 UX 规则：即时反馈 |
| F3 | 通知查询未带当前用户 ID，角标可能混入同工厂其他人员消息 | HIGH | fool-proof Rule 2 |
| F4 | 接口失败仍本地清零会制造“已经处理”的错觉 | HIGH | 错误恢复 |
| F5 | 重复点击已读可能重复发送请求 | MED | fool-proof Rule 4 |
| F6 | 首页只在首次进入时读取待审核任务，AI 异步完成后数量一直停留为 0 | HIGH | 内联 UX 规则：状态自动推进 |

### 每个摩擦点的设计回应

- F1 → 单条和全部已读都先调用服务器 API，成功后才更新本地列表。
- F2 → 首页使用导航聚焦事件重新拉取未读数，返回时自动同步。
- F3 → 通知列表、未读数量和全部已读均携带当前登录用户 ID。
- F4 → 请求失败保留原未读状态，显示“未能标记已读，请检查网络后重试”。
- F5 → 请求进行中锁定对应操作，避免重复提交。
- F6 → 首页聚焦时立即读取待审核队列，并每 10 秒静默刷新一次；离开页面后停止刷新，避免无效请求。

## 验收标准

- 单条已读成功：API 调用一次，本地未读数减一。
- 单条已读失败：本地状态不变，出现可理解的重试提示。
- 全部已读成功：使用当前用户 ID 调用 API，本地未读数归零。
- 全部已读失败：本地状态不变。
- 从通知页返回首页：自动重新请求当前用户未读数。
- 页面首次加载和下拉刷新：通知列表均限定当前用户。
- 首页停留期间 AI 初筛完成：10 秒内自动显示待审核数量；切回首页时立即刷新。
