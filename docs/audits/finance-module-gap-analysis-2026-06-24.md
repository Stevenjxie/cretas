# 财务模块审计 + 专业财务软件差距分析

**日期**: 2026-06-24
**方法**: 2 个只读盘点 agent (后端能力矩阵 + 前端页清单) 实证扫描, 非凭记忆
**对标**: 金蝶 K3/云星空, 用友 U8/NCC, SAP FI

---

## 总体结论

**当前定位 = "经营财务层 + 凭证喂数器", 不是"专业账务系统 (system of record)"。**

在这个定位上已相当成熟 (16 个可用前端页 + 全套凭证/三大报表/AR-AP/辅助核算/金蝶导出, 无 stub)。
若要当**法定账务的系统 of record** (替代金蝶/用友记账), 则在"总账(GL)深度 + 法定合规"上有硬缺口。

**一句话**: 操作型财务做得好, 专业总账(GL)账务深度欠火候。

**完成度粗估**: 操作型财务 ~85% · 专业总账(GL)账务 ~55% · 制造业成本/资产会计 ~30%

## ✅ 已具备 (够打)

- **凭证**: 手工 + 7 类业务单 (SO/PO/RETURN/INTERNAL_TRANSFER/WASTAGE/PAYROLL/DEPRECATION) 自动生成 · 过账/作废 · 借贷平衡校验 · 凭证模板 (`VoucherTemplate`) + 科目映射 (`VoucherSubjectMapping`)
- **科目体系**: 标准 CoA (中国 GAAP, V20260701_02 seed) + 工厂自定义 + **7 类辅助核算** (客户/供应商/部门/员工/项目/存货/外包)
- **三大报表**: 资产负债表/利润表/现金流量表 (BalanceSheet/IncomeStatement/CashFlowService); 2026-06-24 修了 balanceCheck (未分配利润合成行) + 现金流活动分类 + 营业成本科目大类
- **AR/AP**: `ArApTransaction` 挂账/收付款 · 6 档账龄 · 对账单
- **期间结账**: `AccountingPeriod` OPEN→PENDING_CLOSE→CLOSED + 20 天调整窗口
- **账簿/导出**: 总账/明细账/序时账/科目余额表/试算平衡表 · **金蝶/用友格式导出** (`VoucherExportService`)
- **经营财务** (专业软件反而弱的差异化): 开票审批流 · 收款 · SKU 毛利 · 毛利红线 · 进销存台账 · 成本归因 · SmartBI 分析

## ⚠️ 与专业财务软件的差距

### Tier 1 — 卡住"当账务系统用"的硬缺口 (合规/基础)

| 缺口 | 现状 | 为什么关键 |
|---|---|---|
| **结转损益自动凭证** | `MonthCloseServiceImpl` 月结只锁期 + 快照报表, **不过"借收入/贷本年利润"凭证** | 最关键。本年利润/未分配利润从不入账, 跨年结转无从谈起 (做 balanceCheck 时是用"合成未分配利润行"绕过的, 不是真账) |
| **红字冲销 / 反过账** | 只有 void (作废), 无 reversal / unpost | 会计法不允许删/废已过账凭证, 必须红冲。审计硬要求 |
| **期初余额录入** | 无 OpeningBalance 入口 | 真实公司年中上线必须录期初, 否则报表从 0 起全错 |
| **凭证连续性校验** | 无断号检测/编号强制 | 会计法 + 审计要求凭证号连续 |
| **所有者权益变动表** | 无 (四大报表缺一) | 正式财报/审计标配 |

### Tier 2 — 制造业重要缺口

| 缺口 | 现状 |
|---|---|
| **固定资产模块** | 基本没有 (仅能手工生成折旧凭证, 无卡片/折旧计提表/减值/处置/盘点) |
| **存货核算 → GL 成本结转** | 出入库不自动过账到 GL; 加权平均未实现 (仅 FIFO 工具); 无月末成本结转 |
| **成本核算** | 无标准成本/作业成本/分步法/品种法 (M67 出成率成本是分析, 不是入账的成本核算) |
| **税务模块** | 仅利润表识别"所得税"; 无增值税进销项管理/认证/纳税申报/发票池 |
| **AR/AP 正式核销** | 收款隐式冲减余额, 无"收款核销到具体发票"、无坏账核销 |

### Tier 3 — 规模化/高级

银行对账 & 资金管理 · 全面预算管理 · 多币种/外币 · 多组织/合并报表 (抵消) · 配置化凭证审核工作流

## 📌 战略建议

**关键事实**: 系统已有金蝶/用友导出 (`VoucherExportService`, target=KINGDEE/KINGDEE_YXSKY)。这暗示一条更省力、也更贴合 SME 客户实际的路线。

**不要去全量复刻金蝶。** 多数像六膳门这样的 SME, 记账(法定账务)是会计在金蝶/用友里做的; ERP 的价值是**把业务流自动转成凭证 + 喂给会计软件**。所以:

1. **优先 (投入小、价值大)**: 补 Tier 1 里**让导出的凭证可信**的几项 ——
   - ① **结转损益自动凭证** (否则导出的账不平/不完整)
   - ② **红字冲销** (否则会计在金蝶里还要手动红冲)
   - ③ **期初余额**
   这三项直接提升"凭证喂数器"质量, 是当前架构的自然延伸。
2. **中期 (若客户要 ERP 内出正式财报)**: 所有者权益变动表 + 凭证连续性 + 固定资产模块。
3. **谨慎评估再投**: 成本核算、税务申报、银行对账、多组织合并 —— 这些是"做成专业财务软件"的深水区, ROI 取决于是否真有客户要 ERP 当唯一账务系统。多数 SME 不需要, 别过度投入。

**推荐起点**: 先做 **结转损益自动凭证** —— 它直接让刚修好的三大报表"真账化" (替换掉资产负债表里的合成未分配利润行)。
