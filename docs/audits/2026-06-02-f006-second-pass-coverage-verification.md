## 一、总评

**整体真实覆盖 ~70%。** 客户最核心、最难的一条链——逐道双量 (投入+产出) → 自动算出成率 → 跨天累加 → 半成品 WIP 账 → 部分领用扣减 → 容忍数据不守恒——**已实打实落地并 live 验证** (998→382.08 累计 0.3828 金标准)。工序两步配置、分仓库存查询、开工前库存校验、超收 30% 上限、收货幂等也真做了。

**但不是"A1-G10 基本覆盖"(此前结论过于乐观)。报工体系还断在两处性质严重的地方:**

1. **成本算不出来 (最致命)** — 张权微信语音亲口"这个唯一卡点是什么呢?就是人工怎么去计算"。逐道报工采集了人数、工时,但 `YieldReportRequest`/`StepYieldDTO`/`BatchYieldDTO` **全部无任何成本字段** (二次 grep 确认空),从没把"人数×工时×工价"推算成钱。客户最关心的卡点是空白。
2. **累加式分时段报工在旧路径被去重逻辑封死** — `WorkReportingServiceImpl.java:70-79`: 同工人+批次+类型+日期 → 抛 409"您今天已对该批次提交过报工"。客户要每小时一报后台累加。**(注: 此为旧 ScanReportScreen 路径; 我新建的逐道路径 `YieldReportServiceImpl.submitReport` 无此去重、按 task 分组天然支持累加。但操作工进"报工"Tab 首页默认是旧路径,仍可达。)**

## 三、漏的 / 做错的清单 (本次核对重点)

### P0 — 误实现 / 完全未做

**1. [误实现] 累加式分时段报工在旧路径被去重封死 (REQ-17)**
- 原话: "能不能设置上那种累加式的…一个小时为一个节点你一个小时报一下…后台审批…最后计算肯定又加一起" (M1)
- 现状: `WorkReportingServiceImpl:70-79` 第 2 次提交直接 409 拒绝。逐道路径无此问题但操作工 Tab 首页默认进旧路径。
- 建议: 去掉旧路径全天去重 (或只防 5min double-click),或把操作工默认导到逐道路径。**P0,最高优先级。**

**2. [未做] 报工"花了多少元"逐道实际成本 (R-A6 / G5)**
- 原话: "我领了修完油的 8kg,投入到滚揉,一共花了多少元"
- 现状: 逐道 yield DTO 无 costAmount/unitCost (grep 空),采人数工时但不落地成钱。
- 建议: 报工后增逐道人工成本推算 (人数×工时×工价),存 DTO + 批次详情展示。是 #3 的前置依赖。

**3. [未做] 人工成本算法 — 张权亲口"唯一卡点" (R-A12 / G8 卡点1)**
- 原话: "这个唯一卡点是什么呢?就是人工怎么去计算"
- 现状: 人数工时采了,跨工序段归集到订单/批次的人工成本算法从未做通。`EmployeeProcessSegmentController` 记签到签退但不算钱; 多人同工序 totalWorkers 靠手填。
- 建议: 连同 #2 一起做。**口径需先问张权 (材料/人工/能耗各算哪些)。**

### P1 — 核心场景做了一半

**4. 多区间工时不累计 (REQ-14)** — 可多次签到签退生成多条记录,但无 SUM 聚合视图,同员工同工序多区间 workMinutes 不求和。(注: 工时机制分散 BatchWorkSession / ProcessCheckinRecord / EmployeeProcessSegment 三套并存,F006 实际激活哪套取决配置,需确认。)
**5. 多笔 WIP 无选择器 (R-A2/R-A16/G2)** — 上道跨天多笔产出时 `resolveSourceWipNo` 返 null,RN 屏无列表选择器。后端 `listWip()` 已存在但前端未接 → 提交 sourceWipNo=null → WIP 余额不扣 → 半成品账失准。
**6. "今日工序"下拉无日期过滤 (REQ-13)** — `getAvailableProcesses()` 拉所有活跃计划工序,含多天,低文化操作工分不清今天哪个。
**7. 分订单下钻视图缺失 (REQ-21)** — 只有厂级 /by-process + 单批 /yield + /wip,无"按销售订单聚合其下所有批次投入产出"。客户明说"以订单模式呈现、分订单分产品分工序"。
**8. 收货分次时序明细不准 (R-B3)** — `receives/list.vue` 用前端页内聚合 `cumulativeForRow()` 跨页数字不准; 后端 `/cumulative-received` 已实现但前端未调; "第1次X第2次Y"按时序分列未做。

### P2 — 权宜方案/口径/防呆细节

**9. 报工"报表导入"权宜方案没做 (REQ-19)** — 客户 M2 明确接受先用 Excel 报表报量,系统连入口都没有。低成本应补。
**10. 投料达成率用错口径 (REQ-27)** — `overallAchievementRate` 用成本偏差,客户要数量偏差 (实际用量/预计用量); 数量偏差 variancePercent 在 items 有但未汇总+未展示。
**11. 逐道报工路径无独立审批 (REQ-18)** — 旧路径有 DRAFT→SUBMITTED→APPROVED; 逐道 submitReport 提交即计入出成率,无审批挂起。两路径不一致,与"每次都要审批"矛盾。
**12. 工序表单两个标签都叫"产出单位"** — `work-processes/index.vue:264` (绑 unit 主单位) 与 :287 (绑 outputUnit) 同名,操作员困惑。第一个应改"计量单位/主单位"。
**13. 生产计划工序下拉留 allow-create** — `plans/list.vue:1036` 可手写任意工序名,绕开"只能选已配工序",下游出成率无法关联。应去掉。
**14. 采购入库链路三处防呆缺口** — (a) `receives/list.vue` 新建入库 + RN 扫码入库无事前 :max 边界预显 (违 Rule 1,客户原话"告诉他你要收多少就行"正是此); (b) 收货重复创建无 existingId 提示 (Rule 4); (c) catch 块吞 actionHint,409 仅全局 toast 无导航 (Rule 5)。
**15. 线边仓"当天清零"实为人工多步 (D3)** — 只建 DRAFT 草稿调拨单,仍需 submit→approve→ship,无 EOD 强制清零。
**16. WIP 半成品余料退回死胡同 (D4)** — `ReverseTransferService` 只处理原料/成品,不处理 WIP; 退回仅文字提示无入口 (违 Rule 5)。`Status.RETURNED` 定义但未实现。

## 六、结论

**没有完全覆盖。出成率这条最硬的核心链真做通了 (可交付演示),但"报工→成本→效率"闭环断在成本这一环,且累加式报工在旧路径是坏的。**

必修优先级:
- **P0**: #1 修旧路径去重 / #2+#3 补逐道成本+人工成本算法 (口径先问张权)
- **P1**: #4 工时累计 / #5 多笔 WIP 选择器 / #6 今日工序过滤 / #7 分订单视图 / #8 收货分次明细
- **P2**: #9 报表导入 / #10 达成率口径 / #11 逐道审批 / #12-14 防呆三缺口 / #15-16 线边仓清零+WIP 退回

**一句话**: 出成率引擎能用能演示,但张权下次验收最关心的"人工怎么算"目前是空白,#1/#2/#3 应列本轮必修。
