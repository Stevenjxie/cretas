## ③ 4 个 deploy 决策

### Option A: 立刻发微信 brief 给客户

❌ **强烈反对**. 客户走 brief 5 步 → 100% 看到错路由/timeout/暂无. Demo crash 概率 100%. 业务后果: 单一客户演示失败 → 整个 Sprint 11 "MealClaw" 项目可能被砍 / 客户不会再给 demo 机会.

**Risk**: Sprint 8-11 ~4 周工作量 (mainline + 6 sister chat) 信用受损; 修复后再约时间 +2-4 周.

### Option B: 先修 Composite Tool + Round 7 routing 再发

⚠️ **不够 — Composite Tool 不是 root cause**. 此审计揭露 **真 root cause 是 NL routing 把 phrase 错 route 到 DAILY_CUSTOMER_FOLLOWUP**, 而不是 Composite Tool 内部数据缺。即使 P0-3 餐饮 chat 修了 Composite 数据接通, **客户的 UI 仍然 看不到** — phrase 根本到不了 Composite。

修复要 hit 三层:
1. **Routing (P0-1B)**: BI chat 修 IntentKnowledgeBase phrase shortcut, 让 "上月损溢异常" / "损益分析" / "上月成本" / "哪个菜亏钱" 都路由到 RESTAURANT_ECONOMICS_ANALYSIS 而不是 DAILY_CUSTOMER_FOLLOWUP (~6h)
2. **Composite content (P0-3 Option A)**: 餐饮 chat 修 sub-Tool 真接通 financial_metrics / shrinkage_rows / financial_data context (~12-24h)
3. **UI error UX (P0-2)**: 把 `Skill 执行失败` 路由到 red el-alert banner sticky (~5min - 1h)

合计: **18-30h** + 部署 + UI re-test 12 cases。最快 2 工作日。

### Option C: 改 brief 走 SmartBI Path B + 不走 chat

✅ **推荐 (短期)**. SmartBI 模块已 demo-ready (per 餐饮 retro §4D), 客户走 SmartBI 上传 POS Excel → 看 chart + AI 分析。**不依赖 Workdesk chat 的 NL routing**。
- 改 brief 5 步 → 1 步 SmartBI 上传 + 看分析
- Pre-condition: RES_3101_009 (或其他 demo restaurant factory) SmartBI 已 seed 数据 — 此 audit 未验证, 餐饮 chat 应快速 SQL 验证 (10 min)
- Effort: brief rewrite 1-2h, 客户演示流程缩短从 5 步 → 1-2 步

**风险**: SmartBI 模块本身的 UX 未在此 audit 内 (需独立 verify), 但 Sprint 8 据说已 verified shipped。

### Option D: Steve 陪同演示 + 现场 "AI 跑出错了, 现场切到 SmartBI 演"

⚠️ **降级方案**. Steve 在场可以 cover gap, 但客户失去对 AI 的 trust ("你 AI 我看着没用, 还得 Steve 现场救场"). 不推荐除非客户已 booked + 不能改时间.
