> 来源: `六扇门工厂数据、/6.1-6.3/` (6.1-6.3 真实生产数据 + 群内图片传统报工照片 + 负责人结构化报表)

> 日期: 2026-06-02

## 一、传统报工现状 (微信群 + Excel)

六扇门目前报工 = **微信群发文字+照片** + **负责人手工汇总进 Excel 报表**。两层:

### 1.1 工人层 — 微信群逐道报工 (照片+文字)
工人(聂云/魏丽江/魏振江/小珍敏阳/萧春祈/代满怀期徐)每道工序在群里发:
- **文字**: `日期 + 产品 + 工序 + 投入量(下锅X公斤,N锅) + 产出量(熟制后Y公斤) + 工时时段(8.30-21.30) [+人数] [+副产物]`
  - 例: `20260601 猪蹄熟制下锅1121公斤 熟制后1032公斤 8.30-21.30` (出成率92%)
  - 例: `处理叮咚猪舌头 2026/06/01 08:00~11:30 (6人) 肥油:100kg 猪舌头处理后的重量845公斤`
- **照片**: 产品在电子秤上 + 秤读数特写 + 托盘皮重(`托盘24.5`/`托盘39`) + 成品盒数(`掌中宝308盒`/`猪舌头第Z车 236盒`)
- **皮重扣减 + 多托合并算式**: `猪舌头浆揉腌制: 621-24.5=596.5Kg`、`299.5+269.5-57.5-54=457.5Kg` (毛重减托盘减杂)

### 1.2 负责人层 — 日末成品汇总 (永珍骏阳 每日发群)
末道装盒入库后,负责人按**产品分类**汇总:
```
叮咚卤门腔(猪舌) 分切、装盒  批次20260602
入库513盒、留样3盒、剩余201盒
7:00-8:00 (9人)
8:00-15:50 (14人包括打包卤牛腱肉)
15:50-17:00 (11人)
17:00-18:20 (14人)
18:20-23:00 (5人加洗抛片机、洗工器具、卫生)
```
- 每产品: 工序(分切/抛片/装盒/剔骨) + 批次 + **入库盒数 + 留样盒数 + 剩余盒数** + **料头(损耗 kg)** + **副产物(骨头289kg / 肥油100kg)**
- **工时 = 多时段 × 各段人数** (非单一人数!); 段备注说明跨产品/清洁工作

### 1.3 负责人层 — 结构化出成率报表 (猪舌.xlsx 等)
负责人把群报工誊进 Excel 正式报表 (每产品一表, 多 sheet 按工序):
- **熟制 sheet**: 生产日期 | 原料批号 | 投入量(998) | 产出量(935.5=主833.5+副产物102) | 出成率(0.937) | 人工工分(2660=人·分钟) | 人工工时(44.33h) | 备注
- **滚揉 sheet**: 原料批次 | 产品批号 | 投入(833.5) | 产出(1126.5) | 出成率(1.35 保水) | 焯水使用数量 | 剩余数量 | 人工工分 | 人工工时 | 备注(多托减皮算式)
- 出成率 = 产出/投入; 人工工时(h) = 人工工分/60

### 1.4 订单层 — 叮咚销售订单导出
`订单商品明细导出6.X送货.xlsx` = 叮咚给六扇门的采购单(六扇门视角=销售订单):
采购单ID | 类型(0601-好食T+2) | 收货仓(昆山叶城路) | 要求到货 | 预约入场(09:00~10:00) | 商品条码 | 计划采购数量 | 实际数量。

## 二、与 Cretas 现状对照 (P0+P1 后)

| 传统报工要素 | Cretas 现状 | 差距 |
|---|---|---|
| 逐道投入/产出/出成率 | ✓ Phase A + Top-5 | 有 |
| 保水 >100% | ✓ | 有 |
| 半成品 WIP / 焯水使用 / 剩余 | ✓ G6/G7/G8 | 有 |
| kg/份(盒)换算 | ✓ Top-5 P0-2 | 有 |
| 逐道成本(人工+材料) | ✓ 本次 P0+P1 单元A | 有 |
| 跨天累加报工 | ✓ Phase A + 单元B | 有 |
| 分订单出成率 | ✓ 单元F | 有 |
| **图片证据(每道拍秤照+盒数照)** | ✗ 报工无附件 | **缺 — 用户本次重点** |
| **多时段×人数工时** | 单一 workerCount+workMinutes | **缺 — 传统是 7:00-8:00(10人) 多段, 单元C有segment未接成本** |
| **副产物/损耗(料头/肥油/骨头)** | output 单值 | **缺** |
| **留样(留样3盒)** | ✗ | **缺** |
| **称重计算器(毛-皮, 多托合并算式)** | 单一数字手填 | **缺 — 防呆(仓管文化低)** |
| 末道日汇总(负责人按产品分类) | by-process + 单元F分订单 | 部分(无留样/料头/副产物列) |

## 三、适配方案 (在 Cretas 基础上, 5 个增量)

### 适配1 — 逐道报工图片证据上传 (核心, 用户重点)
- 报工(YieldReport)支持附 1-N 张照片(产品+秤读数+盒数), 存 OSS(阿里云已有), URL 列表存 ProductionReport.evidenceImages(jsonb)。
- RN 报工屏: 拍照/选图上传(Expo ImagePicker); web-admin 批次详情逐道展示缩略图+点开大图。
- 价值: 溯源证据链 + 防作假 + 客户演示力(对账时看照片) + fool-proof(照片比数字可信)。

### 适配2 — 多时段×人数工时 (修 M2 + 贴传统格式)
- 报工支持录多个 (时段开始, 时段结束, 人数, 备注) 段; 人工成本 = Σ(人数 × 时长h × 工序工价)。
- 比单一 workerCount×workMinutes 准(传统就是 7:00-8:00 10人 / 8:00-14:30 12人)。
- 复用单元C的 EmployeeProcessSegment 思路, 但接进逐道成本算法(单元A)。
- 同时修 final review 的 M2(totalWorkers SUM 膨胀 → 改 person-hours 口径)。

### 适配3 — 副产物/损耗录入
- 报工加 副产物明细(料头/肥油/骨头 名称+kg) + 损耗。
- 出成率校验: 投入 ≈ 主产出 + 副产物 + 损耗 + 剩余WIP (容忍非守恒 per G9, 偏差>阈值软告警)。
- 末道汇总报表加副产物/料头列(对齐负责人 Excel)。

### 适配4 — 留样
- 末道装盒报工加 留样盒数; 入库量 = 总产出 - 留样 - 剩余。

### 适配5 — 称重计算器(净重防呆)
- 报工数量输入支持"算式模式": 输入 `294.5+245.5-57.5-54` 自动算净重 457.5, 显示毛重/皮重/净重拆解。
- 防呆: 仓管文化低, 照传统群里的算式习惯, 减少手算错误。

## 四、不在适配范围 (已有或后续)
- 微信群对接(自动抓群消息): 不做, 改为 APP 内结构化报工替代群报工。
- 叮咚订单自动导入: 订单明细导出可走现有 Excel 导入(SmartBI), 单独评估。
- 负责人 Excel 报表完全复刻: by-process + 单元F分订单 + 适配3/4 列已覆盖核心, 不 1:1 复刻 Excel。

## 附：三种成品入库路径对比 (T127 补充)

| 路径 | 走报工? | API | 来源 | 适用场景 |
|---|---|---|---|---|
| **期初建账** (`opening`) | ❌ 直接入库 | `POST .../finished-goods/opening` | 历史结存 | 5/31 冷启动导入 Excel 存量 |
| **存货/备货生产** | ✅ 完整计划→转批次→RN逐道报工→完工自动 FG-AUTO | `POST .../production-plans` + 转批次 + 报工 | `sourceType: SAFETY_STOCK` | 为备库而产，不绑销售订单；备货看板缺口快捷入口 |
| **订单驱动生产** | ✅ 同报工链 | `POST .../production-plans` (财审后 shortfall 自动建) | `sourceType: CUSTOMER_ORDER` | 销售订单财审通过后库存缺口自动建计划 |

> **关键**: 存货生产与订单驱动生产走完全相同的报工→ FG 链 (`onBatchCompleted` → `createFinishedGoodsFromBatch`)，区别仅在于无 `sourceOrderId`。完工后均自动生成 `FG-AUTO-*` 成品批次并入库。
