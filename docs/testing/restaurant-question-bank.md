## 3. 多轮（T3+）—— 上下文继承链

**测上下文的主力**。每条链在同一会话里连续问，中途不要新开会话。

### 链 A：指代 + 指标切换（菜品不变）
```
1. 米饭的销量是多少      → 反问时间
2. 本月                  → 反问门店
3. 全部门店              → 出米饭销量
4. 那成本呢              ← 指代，菜品仍是米饭
5. 那毛利呢              ← 继续切指标
6. 是否合理              ← 追问评价
7. 怎么优化              ← 追问行动
```

### 链 B：实体切换（中途换菜）
```
1. 本月全部门店米饭卖得怎么样
2. 那娃娃菜呢            ← 换菜，时间/门店继承
3. 那毛利呢              ← 换指标，菜是娃娃菜
4. 换成上个月呢          ← 换时间，菜不变
```

### 链 C：门店切换
```
1. 本月全部门店营收多少
2. 青花椒紫荆广场店呢     ← 缩到单店
3. 那毛利率呢
4. 跟上个月比呢
```

### 链 D：从概览钻到明细
```
1. 这个月生意怎么样
2. 哪家店最好
3. 那家店哪个菜卖得最好
4. 这个菜赚钱吗
```

### 链 E：话题跳转（测**不该**继承）
```
1. 本月全部门店米饭销量
2. 我有几家店            ← 完全换话题，不应带米饭
3. 今天天气怎么样        ← 域外，不应带任何上下文
```

### 链 F：反问后答非所问
```
1. 哪个菜卖得好          → 反问时间
2. 青花椒紫荆广场店       ← 答的是门店不是时间
3. 本月                  ← 补上时间
```

## 4. 同一问题的不同问法（口语层）

以「本月营收」为例，真人会这么说：

- **老板口气（短、糙）**：这月挣了多少 / 这个月流水多少 / 本月做了多少钱 / 这月营业额 / 钱收了多少
- **店长口气（业务词）**：本月营收情况 / 本月营业额汇总 / 这个月的销售额是多少
- **书面 / 文员**：请提供本月全部门店的营收数据 / 本月经营概览
- **带情绪、带判断**：这月是不是不行啊 / 这个月怎么这么差 / 本月生意好不好
- **祈使句**：给我看下本月营收 / 拉一下这个月的数 / 查本月营业额

其他高频同义替换：

| 意图 | 说法变体 |
|---|---|
| 哪个菜卖得好 | 哪个菜最好卖 / 哪道菜卖得最好 / 什么菜卖得最多 / 卖得最好的菜是啥 / 爆款是哪个 / 主推哪个菜 / 哪个菜点得最多 / 销量第一的菜 |
| 亏损 | 哪家店亏钱了 / 哪家店在亏 / 有没有店亏本 / 哪个店不挣钱 / 哪家店赔钱 |
| 补货 | 哪些食材快没了 / 什么料不够了 / 该进货了吗 / 库存不够的有哪些 / 缺什么货 |

## 5. 错别字 / 输入噪声

### 形近字
本月**莹**收多少（营→莹）/ 哪个菜卖得**耗**（好→耗）/ 毛利**卒**（率→卒）/ **末**利率（毛→末）/ 客**担**价

### 音近、同音
本月**赢**收多少 / **好**利率最高的菜 / **番**台率 / **抱**损 / **盼**点 / **蛙蛙**菜 / **米范**

### 拼音混入（打字没选词）
本月yingshou多少 / 哪个cai卖得好 / 本月maolilv

### 漏字、多字
本月营多少（漏"收"）/ 哪个菜卖得好好 / 本月全部门店店营收 / 这个月生意怎样

### 语音转文字典型错误（手机端高频）
本月**盈利**多少（实际想问营收）/ 哪个菜**卖的**好 / 本月**赢**收怎**摸**样

### 标点、空格
本月营收多少呢？？？ / 本月 营收 多少 / 本月营收多少啊啊 / 半角逗号混用

### 繁简混用
本月營收多少 / 哪個菜賣得好 / 毛利率最高的菜是哪個

### 菜名、店名写错（考模糊匹配与反问）
招牌**清**花椒味 / 青花椒**紫金**广场店 / 鲜行者打**铺**桥日月光店 / **鹅**边脆笋 / 摇滚小**苏**肉

## 6. 边界与陷阱

| 类型 | 问法 | 期望 |
|---|---|---|
| 不存在的菜 | 本月全部门店佛跳墙卖了多少 | 明确说没找到，不编数、不退化成排行 |
| 非菜品项 | 本月打包盒卖了多少 / 需要餐具有多少 | 排行里应被剔除 |
| 闭店门店 | （闭店）青花椒宝山万达店本月营收 | 正确处理而非报错 |
| 超长复合句 | 先告诉我昨天全部门店的营收，再告诉我哪家店业绩最好，另外米饭卖得好不好 | 各部分都要答到 |
| 写操作 | 下架卤炸牛肉串 / 把最近7天销量最低的5道菜下架 | 进确认流程，**不能**直接执行 |
| 域外 | 今天天气怎么样 / 股票怎么样 / 帮我订个机票 | 明确说不在范围，不编 |
| 无时间的因果问 | 卤炸牛肉串销量为什么低 | 先摆判断前提，不臆断涨跌 |


### 计划缓存的历史漂移守卫
计划缓存键是 `(租户, 归一化句子, plan_version)`，**不含 session**。守卫保证「LLM 从历史里补出来的时间窗」不会被缓存后泄漏给别人。

```
会话1：  1. 上个月营收多少
        2. 营收多少        ← 有历史，planner 可能填「上个月」
会话2：  3. 营收多少        ← 全新会话，必须【反问时间】而不是直接给上个月
```
第 3 步若直接返回上个月的数据 = 守卫失效。

### 入口一致性
同一句「本月全部门店哪个菜卖得好」，三个入口应给出**同一个答案**：
- 手机端 `https://admin.cretaceousfuture.com/mobile-ai/rest/`
- web-admin 餐饮分析页的 AI 抽屉
- SSE 流式接口 `/api/mobile/{factoryId}/ai-intents/execute/stream`

## 8. 与回归电池的关系

自动化回归电池在 `backend/python/smartbi/scripts/restaurant_ai_eval.py`（当前 65 例，每天 04:40 cron 跑一次）。

本问题库**不是**电池本身，而是它的素材池：人工走查用这里的问法，发现真实缺陷后，把该问法固化成电池用例，防止复发。

当前电池覆盖较薄的两块，是本库优先该补进去的：
1. **多轮链**（电池只有 dish / dish_named_store / store_rank 三条）→ 本文 §3 的 A~F 六条链
2. **错别字与输入噪声**（电池目前一条都没有）→ 本文 §5

补用例时注意电池的既有约定：断言用**结构性 marker**（含 / 不含某字串），不锁具体数字（demo 数据每日滚动，数字天天变）。日期敏感的行为要像 `_THIS_WEEK_EMPTY_PERIOD_CASE` 那样按日期切换断言，别写死。
