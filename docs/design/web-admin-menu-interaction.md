# Web Admin 菜单交互规范

## 目标

Web Admin 的菜单用于高频业务操作，不做依赖运气的 hover 飞出层。默认交互必须稳定、可预测、可键盘访问。

## 分层规则

- 一级菜单：业务域，例如生产管理、仓储管理、财务管理。
- 二级菜单：工作区，例如生产过程、生产配置、生产分析。
- 三级菜单：页面内 tab 或当前工作区内的分组操作，不默认继续铺在左侧栏。

生产管理的目标结构：

```text
生产管理
  - 生产过程
  - 生产配置
  - 生产分析
```

生产过程页面内部再放：

```text
计划排产 / 批次执行 / 报工审批 / 异常撤回 / 领退料协同
```

## 交互规则

- 展开态侧边栏：点击一级菜单展开二级菜单，展开后保持固定；鼠标移开不自动收起。
- 收起态侧边栏：hover 图标时显示浮层菜单；浮层应用 menu aim 延迟和安全通道，避免鼠标斜向移动时误关闭。
- 移动端：只使用点击展开，不使用 hover。
- 当前路由所在父级必须保持展开和高亮。

## Menu Aim 行为

菜单使用 `web-admin/src/components/layout/menuAim.ts` 作为统一模块。

- `showTimeout`: 子菜单出现前的轻量延迟，避免擦过菜单时误展开。
- `hideTimeout`: 子菜单关闭延迟，给用户移动鼠标留缓冲。
- `collapsedHideTimeout`: 收起侧边栏浮层使用更长关闭延迟。
- safe triangle: 当鼠标从父项斜向子菜单移动时，当前子菜单应保持打开。
- popper bridge: 浮层左侧有不可见安全通道，覆盖父项与浮层之间的小空隙。

## 实现约定

- 左侧菜单节点统一通过 `SidebarMenuNode.vue` 渲染，支持递归 children。
- 不在业务页面重复实现级联菜单逻辑；需要菜单意图行为时复用 `menuAim.ts`。
- 如果某个模块确实需要三级左侧菜单，必须先确认它不是页面内 tab 更合适。
